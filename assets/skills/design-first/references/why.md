# Why
Look for accepted ADRs, original design records and relevant Git history. Distinguish an explicitly recorded reason from a plausible interpretation.
If history supports only what changed, say the motivation is unknown. Do not infer author intent from the current code alone.
Explain present tradeoffs as your analysis, with the assumptions that could change the recommendation.
Keep stated constraints separate from your recommendations. Quote the relevant requirement when excluding an alternative: "no separate database service" does not exclude an embedded database. Do not present your technology preference as a user prohibition.
