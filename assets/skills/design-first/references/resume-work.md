# M1 resume without a database
An explicit change ID or document path takes precedence. Use the same location rule as creation: an explicitly supplied change location, then the project's documented change root (including an OpenSpec convention), then docs/changes as the fallback. Read project instructions to find that root. Without an explicit path, list metadata only in those selected roots within the current project, bounded to 20 candidates total; request a narrower filter or selection when ambiguous. If no matching change is found, report the searched location and ask for its ID or path instead of starting a duplicate. Do not traverse all workspaces or guess by recency.
Read the selected metadata, design, tasks, progress and relevant glossary/ADRs. Confirm the actual repository/worktree and inspect relevant source and Git state. Metadata is a hint, never authority.
Keep current source, historical source and historical test records separate: record the exact path and which version each observation describes. After reading historical copies, reread the relevant lines from the current working file before reporting an implementation gap or design drift. Quote the current condition exactly; do not combine conditions from two versions into reconstructed code. If the current line cannot be confirmed, mark the claim unknown rather than prescribing a fix for it.
Classify findings as consistent, progress_lag, implementation_lag, minor_deviation, material_design_drift, requirement_changed or unknown, with evidence.
Missing/corrupt metadata means reconstruct context from existing files and disclose uncertainty; preserve originals and avoid duplicate changes. Branch/HEAD/dirty flags alone cannot establish identical test inputs.
Return a summary of verified work, implemented_unverified work, remaining work, deviations, unknown inputs and the next action. Update factual progress.
Only expand a deviation when its current-source evidence supports it. A stale test result makes verification stale; it does not by itself mean the implementation is missing or broken. Keep the handoff concise and save it before repeating its contents in chat.
Unfinished investigation/design resumes that stage. Before implementing in a new session, present the current design and differences and obtain explicit current-session authorization. Historical approval text is insufficient.
A blocked task retains its original stage and exit condition; removing a blocker does not automatically resume execution. Completed work opens its outcome rather than starting another task.
M1 uses no ChangeStore, ArtifactStore, leases or trusted approval restoration.
