# Playground 执行模型：宿主自备 JDK、裸子进程、默认关闭

> 2026-10-27 更新：用户决定以 Python 替换 Java。运行环境、草稿保留与依赖契约以 [当前架构文档](../architecture-playground.md) 为准；以下保留原决策背景。裸子进程、非沙箱与服务端开关边界仍适用。

对话消息、小记与右栏文件预览里的代码块需要能直接运行 Java 片段。我们决定：**不打包任何 JVM 运行时**（Docker 镜像与 Electron 安装包都不含 JDK），改为探测宿主已安装的 `javac`/`java`，探测不到就把功能显示为不可用；每次运行起一个普通子进程（独立临时目录、墙钟超时、输出上限、进程树查杀），并且**明确不是沙箱**——执行的是宿主机器上的任意 Java 代码；总开关**默认关闭**，存在服务端全局配置里由路由处理器强制校验，并可用 `PI_WEB_PLAYGROUND=off` 在部署层锁定为不可修改。

## Considered Options

-   **把 jlink 最小运行时打进 Docker / 桌面安装包**：三平台矩阵各约 40–50MB，加上许可证与版本漂移，对一个默认关闭的辅助功能不划算——被否。
-   **平台级隔离（macOS seatbelt / Linux bubblewrap / Windows job object）或每次运行起容器**：跨平台复杂度高，桌面版也没有 docker；在「默认关闭 + 只绑 loopback + 单用户本地工具」的前提下收益不足——被否，留作以后真要跑不可信代码时的方向。
-   **JVM 内限制（`SecurityManager`）**：新 JDK 已废弃/移除，实际不可用。
-   **浏览器端 WASM JVM（CheerpJ 之类）**：等于另起一套运行时，与「用你自己的工具链」定位冲突。
-   **把开关做成每客户端界面偏好**：任何能打开页面的人都能自己把它打开，等于没关——被否；安全开关必须由服务端强制。

## Consequences

-   没装 JDK 的用户会看到功能不可用，这是明确接受的代价；探测失败只表现为功能不可用，绝不影响服务启动。
-   「不是沙箱」必须写进 UI 文案与文档，避免有人拿它跑不可信代码。
-   以后若要打包 JDK 或补沙箱，是替换执行层的大改——所以这条值得记下来，而不是让它变成「顺手改一下」。
