# OMP 模型配置

主聊天、独立 Wiki、SSH 与 Playground 的模型配置使用同一数据目录下的 OMP 原生配置与凭据库。主聊天／Wiki 模型表单写入 `<dataDir>/omp/agent/models.yml`，内置供应商 API 密钥与 OAuth 使用 OMP 凭据接口。使用原版 SDK；具体入口和未完成事项见 [OMP 接入契约](architecture-omp.md)。

## 配置来源

应用入口不再自动读取 Claude Code、Codex、OpenCode 或旧 Pi 的模型配置，不生成 `sync-*` 别名或 `model-sources.json`。旧 `sync_model_sources` 请求返回错误且不改变配置。模型管理页只显示当前 OMP 自定义配置和原生供应商目录，不提供已退休的「恢复同步」。遗留来源解析器的独立测试不代表应用仍加载它。

凭据不自动从旧 Pi 迁入。用户通过现有模型管理、密钥表单和原生 OAuth 入口配置；API 密钥及自定义请求头不下发浏览器。空白的已有自定义密钥编辑框保留原值。内置供应商的清除操作只移除其 API-key 行，保留其他供应商、OAuth、环境变量和 models.yml 认证。

## 输出额度

已按批准的迁移方案取消宿主统一的 128000 输出覆盖。未填写最大输出时，交给 OMP 当前模型目录决定；编辑器保持空白，不将有效默认值冒充用户设置。明确填写的额度保留；清空会删除覆盖，后续请求恢复原生默认。

OMP 18.20.0 对专项中的未知自定义模型给出 16384 默认输出，测试检查实际出站 `max_tokens`。这个数值只描述该夹具，不应作为所有模型的应用常量；原生模型目录或发现器可能采用不同值。

## 写入和生效

各 worker 对 models.yml 使用跨进程锁，覆盖读取、合并、原生校验和失败回滚。保存保留未知顶层字段、非聊天模型和请求头；无效配置恢复原文件。具体合并行为另见 `tests/unit/model-config-merge.test.ts` 与 `omp-model-catalog-test.mjs`。

保存后的空闲 worker 通过配置指纹和原生凭据代数刷新目录，重新绑定同一 provider/model 身份，不自动换到其他模型。正在运行的会话拒绝由自身发起的配置写入；其他空闲窗口可以修改共享配置，但运行中的多轮工具任务继续使用原连接、额度和凭据。任务结算或下一次明确发送前同步新配置，不自动重发任务。

配置共享不合并聊天历史。模型选择、会话 ID、文件、主聊天／Wiki 归属保持独立；服务重启后恢复原历史及已保存的模型配置。删除或失去凭据的模型不继续发送，用户需明确选择可用模型。

模型管理页说明共享范围和更新时机；最大输出输入框支持空白默认值及明确覆盖。模型目录读取、编辑和保存不调用推理模型。

## 验证边界

- `model-sources-protocol-test.mjs` 保留在完整冒烟清单，使用真实宿主 WebSocket、主聊天／Wiki OMP worker 和本地 Anthropic 流。检查实际工具回传期间的密钥／网关隔离、新轮配置、历史隔离、明确及清空额度、无效配置回滚、重启和秘密值不外泄。外部 OpenCode 配置仅作禁止导入的夹具，并验证原文件不变。
- `--browser` 检查真实模型表单的保存、重新打开、清空额度、凭据不回填和窄屏布局；不要求旧配置来源面板存在。
- `omp-model-config-test.mjs` 覆盖独立 worker 的并发写入、内置密钥库、原生默认和服务商删除；`clear-provider-key-test.mjs` 覆盖宿主凭据清除与重启；`stale-model-selection-test.mjs` 覆盖不可用模型警告、禁止发送和草稿保留。

本地模拟接口不消耗真实模型额度，也不能证明 Windows DeepSeek 原任务已修复。实际供应商 OAuth、网关差异、Windows 原任务及打包验收仍按整体迁移要求分别进行。
