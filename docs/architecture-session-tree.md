# 原生会话树

## OMP 迁移状态（2026-11-15）

聊天历史来自公开 `SessionManager.getBranch()` 的当前分支，而非供下一次模型调用使用的 `session.messages`。OMP 可从活动上下文移除失败或仅思考的额度截断回复，原生持久分支仍保留时，界面必须继续展示其错误／截断状态。普通消息和 custom_message 使用原生 transcript 转换，压缩与分支摘要使用原生消息构造器；条目 ID 直接随原生条目返回，不再按模型上下文正文反查。此投影不修改原生历史或模型上下文，原生回收时从分支移除的条目也不复活。

普通聊天删除历史会拒绝当前会话、活终端、后台任务／队列／恢复和其他客户端持有的文件；已退出终端仅有回放，不阻止删除。Wiki 的明确删除当前会话操作允许先创建空白后继，普通 `delete_session` 不自动切走当前聊天。操作持有导航权及服务级文件删除保留权：关闭 worker 完成前不删除，其他窗口的保存选择和显式打开都不能在此期间创建同文件 worker。持有者检测包含初始化中的文件路径，不依赖尚未返回的 sessionId。

删除通过独立 Bun 元数据操作调用公开 `FileSessionStorage.deleteSessionWithArtifacts`，一并处理 transcript、原生日志附件及 Windows 重写 `.bak`，不会重启停止的 Agent 或发起模型调用。原生删除成功后仅清理本次已确认的恢复标记，避免旧客户端重连时把用户明确删除的失败历史显示成待恢复会话；删除期间新增的失败标记保留。清理失败显示未完整完成，不把部分删除当作成功。该服务内保留权不是对任意外部进程的文件事务锁。回归见 `omp-history-ownership-test.mjs`、`delete-session-terminal-test.mjs`、`switch-session-background-test.mjs` 和 Wiki 助手回归。

原生 `custom_message` 也参与条目 ID 映射，不再只匹配 `message`。用户发起的 `skill-prompt` 在聊天与树中投影为用户问题，原生记录保持不变；“仅用户”筛选和编辑重问包含这些技能调用。原文取保存的调用草稿，保留行内 `/skill:` 位置，不将展开后的技能正文当作编辑内容。队列消息的瞬态标签不参与持久化条目匹配；自动技能和其他扩展消息保持原有类别。回归见 `omp-skill-history-test.mjs`，其编辑草稿与原生 `navigate_tree` 返回值对照，覆盖冻结附件及重启恢复。

主入口已使用 OMP RPC。树写操作与编辑重问先取得当前对话的独占操作权，整个异步过程使用捕获的会话；期间切换对话、新建、切工作区、重复树写入及普通发送被拒绝。只读回复保留请求所属 conversationId。Stop 使等待中的后续步骤失效，不允许旧操作重开进程或发送。原地编辑调用 OMP navigate_tree，原分支保留在原文件。详情只返回白名单消息内容或摘要，不直接下发原生条目的任意元数据。

原生 navigate_tree/compact 会占用 RPC 串行队列。产品 Stop 先通过 worker 独立控制路径清队列并取消原生摘要、压缩和重试，再走原生 abort 并关闭进程；分支摘要期间保持产品任务忙碌和停止按钮。`tests/omp-tree-test.mjs` 使用真实 OMP 与本地接口验证原地编辑、原分支保留、并发操作拒绝、Stop 在 5 秒内完成及无自动重发。

OMP 编辑重问现先从当前原生会话解析附件引用，再完整构建本次输入，最后导航／派生和发送。内联文本、选中行与编辑器快照恢复原始全文，引用保留路径语义；不使用界面截断预览，不重读已修改或删除的文件。伪造引用与无效编辑器快照在导航前拒绝。原生历史投影提供 questionText 与有界附件卡片，刷新后仍可恢复编辑草稿。回归为 `tests/omp-tree-test.mjs` 与 `tests/omp-attachments-browser-test.mjs`。

协议 v73 增加独立摘要取消。服务端生成操作 ID，绑定导航请求、所属对话及 worker 代数；快照中的 branchSummary 让重连页面恢复当前操作。tree_cancel_summary 只接受匹配的操作，过期、跨对话和已结束请求返回 stale，不改变下一个摘要。重复取消不会启动第二个取消循环。

取消调用原生公开 abort_branch_summary，不关闭 worker、不清空其他对话队列，也不重发导航或模型请求。原生导航可能尚未建立 abort controller，因此已请求取消时，在同一操作仍未结束期间串行重复幂等取消（每次响应后间隔 100ms）。导航结束时停止循环，并在释放导航操作权之前等待最后一条取消响应，避免它落到后继操作。取消准入返回 requested，只有原生 navigate_tree 返回 aborted/cancelled 才决定最终结果；成功导航不能被伪装为已取消。原生扩展若不响应取消信号，仍可使用现有整个任务 Stop。

界面显示摘要进度和独立「取消摘要」，正在取消时禁用重复点击；刷新后由快照恢复，操作完成后清除。不生成另一个执行计划或模型提示词。正常对话可在取消后沿用同一 worker 继续，后台任务不受影响。真实回归覆盖实际请求取消、取消早于原生初始化、重复／旧 ID／跨对话请求、后台任务隔离、原位置保留、无重发和整个 Stop；浏览器覆盖树面板发起、重连、键盘及中英文窄屏。

树列表的排序、五种过滤和搜索已改为读取锁定 OMP 版本的公开 `TreeSelectorComponent.getTreeList().pickerView()`。Bun 侧用公开 `searchInput.setValue()` 赋查询，再切换过滤使其重算，不将查询传入终端键盘处理器；选择、取消和标签回调均为空，不对会话执行动作。Node 侧只投影原生可见条目、结构深度、活动路径和清理后的预览，详情与写操作仍通过完整条目索引校验。原生默认显示工具结果，隐藏非当前 leaf 且正常结束的无正文 assistant；错误／中止条目保留，当前分支优先。搜索遵循原生模糊词及内容范围，而非搜索整段模型历史。先过滤再截断 5000 个可见条目，组件用后释放。

`tests/omp-tree-projection-test.mjs` 先在旧实现复现默认过滤丢失工具结果，再覆盖五种过滤与真实选择器对照、分离／模糊词、200 字搜索范围、书签清除、技能与 advisor、独立根、空 leaf 和一万条历史。它使用原生内存会话，不调用模型；实际 worker 接线另由树、技能历史和浏览器回归验证。树快照摘要、聊天消息兄弟切换和历史列表分叉计数的后续接入见下方协议 v74；列表专项本身不代表完整迁移验收。

OMP 原生持久化通知现已接入（协议 v62）。两个原生进程争用历史时，SDK 的转存通知同步更新当前保存路径并展示原／新文件；保存失败则撤回所属会话队列、取消摘要／压缩／重试并停止其 worker，保留当前消息展示和失败状态，禁止普通发送或树写操作隐式重开。用户明确「重新读取已保存历史」后才能清除失败；失败重开保留限制，Stop 可取消正在初始化的重开。恢复入口启用原生 `throwIfMissing`，缺失或空文件不被悄悄创建为新历史。

OMP 18.20.0 已有所有者的原生追加路径不会逐次复查同 inode 的历史内容，原先零模型调用复现会在外部同长度改写后继续追加。现通过公开 `FileSessionStorage` 注入 `OmpSessionStorage`（协议 v63），记录原生实际读写的字节基线，在写前、原子发布钩子及每秒检查本进程持有写入权的文件；发现外部修改后锁定失败并停止所属 worker，不接纳外部条目或自动重写。尚未写入的只读窗口不轮询判定另一原生写入者的内容为损坏，首次写入仍由原生所有权派生及严格存储检查保护，见 OMP 架构的多窗口所有权章节。原复现已转为 `tests/omp-external-history-test.mjs`，覆盖同长度修改、外部追加、截断、删除、替换、持有写入权时的空闲检测、touch、会话隔离及显式恢复。

正常追加只更新增量哈希，stamp 未变不扫描全文；stamp 变化时用 64 KiB 缓冲核对全文，相同内容的 touch 可继续。按原始字节严格比较，因此 JSON 格式化／CRLF 改写也要求显式重开；原子替换即使字节相同仍视为外部改动。OMP 自己的标题槽、原子重写、Windows 替换回退与图片外置保持原生实现，由适配器更新基线，兼容性见 `tests/omp-session-storage-test.mjs`。校验是乐观检测，不是对任意外部程序的事务锁；原生 Task 内部独立会话覆盖仍待完成。下方旧 Pi 校验实现仅作迁移对照，不能作为当前 OMP 行为说明。

协议 v64 将失败限制保存在独立的 `<dataDir>/omp/recovery/`，主机重启、换客户端或后台会话恢复均先检查限制；只在显式重开成功后清除本次确认的记录，不删除重开期间新增的失败。失败历史缺失时仍显示原恢复入口，不创建空历史。记录不可读写时明确提示此限制可能无法跨重启保留；成功重开不自动重发。原生独立进程与实际服务重启回归见 `omp-persistence-restart-test.mjs`、`omp-persistence-browser-test.mjs`。


## OMP 树快照与停止后只读（协议 v74）

`harness_history` 同步捕获全部条目的结构及当前原生分支，返回树 revision、leaf、根数、分叉点数和原生 `treeFilterMode`。revision 哈希包含会话 ID、leaf、条目 ID／父节点／类型和标签变更，不重复哈希附件与模型正文。快照的 busy 来自宿主导航和原生恢复操作，externallyModified 来自持久化状态；同步存储校验没有另一个异步 verifying 阶段。打开的面板按 revision 重读，初次元数据晚于首个快照到达时仍采用原生默认过滤。

聊天消息保留书签和稳定的兄弟编号。隐藏的结构条目按最近可显示祖先归组，编号沿用条目写入顺序；每个候选分支定位到其最新保留叶节点。点击仍执行原生 navigate_tree，不重新发模型请求；只有原生导航返回用户草稿时才沿用现有草稿保护。压缩和分支摘要也保留 entryId，避免有摘要却无法关联原生条目。普通对话列表使用活动快照中的分叉计数。

停止后读取树曾会通过 command/open 重开 Agent。现在先等待已在进行的启动或停止，再使用已有 worker；无 worker 时执行独立只读 Bun 投影。正常停止在既有 5 秒期限内尽力读取原生最终历史和树快照，保留未落盘内容与临时选中的 leaf；快照最多 16 MiB，计入会话已有的内存淘汰额度。只读进程接收该快照并使用公开 SessionEntryIndex 和选择器，不创建 AgentSession、加载扩展或调用模型。它不将快照写回原生文件。原生退出时随后追加的 session_exit 元数据不改变冻结的停止视图。

未能保留快照时，只读加载已保存文件；保留已确认的 leaf，检查会话身份、文件读取前后的版本、原生格式和条目重复。缺失或无效的已保存历史明确失败，不重建文件；未保存的树已不可用时保留界面消息并报告读取失败，不伪造空树。关闭／重开／再次停止后，旧只读请求不能应用到新 worker。元数据捕获失败或原生扩展不响应都不能延长 Stop 的既有期限。

历史列表通过原生流式访问器只读计算分叉数，不打开 SessionManager。先排序选取最多 200 条，再最多 8 路读取；按设备、inode、大小及 mtime/ctime 缓存至多 1000 个结果。文件在读取期间变化、损坏或缺失时只省略该条计数，不显示假的零值或改写文件。原生 parentSessionPath 同时保留。

验证入口为 omp-tree-test、omp-tree-projection-test、omp-tree-cancel-browser-test、omp-stop-metadata-test 及 omp-tree-metadata 单测。覆盖真实快照缺失复现、书签更新／清除、兄弟叶节点恢复与零额外调用、浏览器刷新、停止后搜索、不执行扩展、磁盘读取和缓存失效。只读字节断言在 Stop 完成后取基准，避免把原生 session_exit 的最终落盘算成树读取写入。专项结果不替代 Windows 原任务与完整迁移验收。


## OMP 导航预览与自定义摘要

`tree_preview` 现在返回原生摘要准备的条目数和最近共同祖先。Bun 侧使用公开 `SessionEntryIndex` 和 `collectEntriesForBranchSummary`；沿用 OMP 的分支路径、多个根、空 leaf 和跨压缩记录规则，不在 Node 端另写一套摘要算法。只在请求预览时计算，回复绑定原请求的 conversationId／reqId；浏览器沿用既有过期响应过滤和计数展示。

运行中的只读请求使用现有 worker；停止后的内存快照和磁盘历史使用既有只读元数据进程，不创建 Agent、导入扩展、改变 leaf 或改写历史。预览是读取当时的候选摘要范围，不承诺之后历史或原生扩展钩子改变时仍完全相同，也不是 token 费用估算。当前 OMP RPC 对 ask 结果重新回答仍明确返回不支持，预览本身不增加这种能力。

自定义摘要继续通过公开 navigate_tree.customInstructions 交给原生摘要器，保留原生提示词。旧 replaceInstructions=true 被明确拒绝；自定义模式要求字符串、非空且不超过既有 16000 字边界，超限不再静默截断。校验发生在停止任务、重开 worker 和模型调用之前，失败不改变原位置、不重发。默认／无摘要导航与取消协议保持原生语义。

回归覆盖真实宿主预览与实际 session_before_tree 准备数据对照、相同 leaf、未知条目、停止后无启动／无写入、自定义指令进入模型请求及无效参数不能中断运行任务；原生夹具覆盖普通／工具／技能／压缩、多根、空 leaf、内存和磁盘。浏览器覆盖中英文计数、自定义指令、停止后读取和原有取消／刷新／继续流程。执行结果见 [预览专项记录](review-data/omp-tree-preview.json)。

## 投影与读取

`server/session-tree.ts` 从公开的 `getTree()` 派生有序列表、可见父节点、当前路径、分叉点和兄弟目标。按 CLI 选择器优先排列活动分支；五种过滤与多关键词搜索使用锁定版本的实际语义：`usage` 在所有模式隐藏；非当前 leaf 的无文本正常 assistant 消息在所有模式隐藏。消息搜索只使用 CLI 搜索的前 200 个内容字符；摘要搜索遵循 CLI 的区别处理。

过滤先于 5000 节点截断，预览去除 ANSI 与换行并限 120 字符。节点内容由 `tree_content` 按需读取，供摘要全文和复制使用。协议 v52 可选 `codemodeToolCallId` 返回 `tree_content_result.codemode`（序列化后的调用与结果），仅接受当前分支内匹配该调用的 assistant／toolResult 条目；供压缩记录只读弹窗使用，不调用 navigateTree、不改变 leaf 或模型上下文。遍历采用显式栈，避免长路径递归溢出。

`buildSessionProjection().entries[].sourceEntry` 提供 UI 消息的 entryId，包括压缩摘要与分支摘要。保留现有 UI ID 和旧编辑请求的反查兜底。每次原生 revision 变化重新派生 label、siblings 和消息来源映射；只缓存这些展示元数据，不缓存或修改原生树。未变更的 UI 消息继续复用引用。revision 由 sessionId、条目数和 leafId 组成；label 覆盖和清除均追加原生条目，能够使 revision 失效。

快照携带树摘要，完整列表由 `tree_get` 按需读取；`tree_changed` 使已打开面板重新请求。后台变化更新会话摘要，重新连接依靠权威快照恢复 revision，不依赖通知必达。历史会话显示分叉点和 `parentSessionPath`。

## 写操作与生命周期

`SessionTreeController` 只接受活动对话的请求。全部回复携带 conversationId、reqId；客户端丢弃已离开对话与过期搜索请求。压缩或另一次树切换期间返回 busy，不排队。运行中必须显式同意中断：先 `clearQueue()`，再 `await session.abort()`（SDK 等待 idle/agent_settled），重新检查归属后调用 `navigateTree()`。

回收的 steering/followUp 文本与返回的 editorText 通过对话所属的草稿通道恢复，不自动发送。已有草稿时显示替换、追加和保留选项。user 和 custom_message 目标遵循原生退回父节点语义；当前 leaf 的原生 no-op 保持原样。

切换使用原生 `navigateTree`，保留 session_before_tree/session_tree 扩展回调及对应对话的扩展弹窗。仅生成摘要时进入 RecoveryStatus；无摘要切换不显示摘要状态或取消按钮。摘要取消调用 `abortBranchSummary()`。aborted 优先于 cancelled 判定（SDK 取消摘要时可同时返回两者）。失败、取消不把目标标成已选中。操作期间阻止更换活动对话；完成后恢复操作入口。纯切换不追加条目，因此不会把内存 leaf 单独保存到文件；跨端重开后的停留位置沿用 SDK 规则。

label 使用 `appendLabelChange`，允许运行中写入；不自行改写旧条目。此原生调用会推进 leaf 到 label 条目，标签本身不参与模型上下文。

编辑重问默认先原地导航到 user entry，再经既有附件和 prompt 管线发送新文本，原分支留在同一文件。编辑菜单可显式派生新会话；设置中的 `editResendNewSession` 保存于现有界面偏好，默认 false，不注入模型配置。`/tree` 打开树面板；`/fork` 打开用户消息选择；`/clone` 使用 `runtime.fork(leafId, {position: "at"})`；`/name` 使用原生 `setSessionName`。派生后的新 runtime 重新绑定扩展 UI、事件和树监视。

## 外部修改

监视当前会话文件所在目录，同时在写操作前核对文件状态。`SessionTailValidator` 记录已验证的 inode、文件长度和条目 ID。首次绑定已有文件时异步分块只读核对会话头和全部条目的顺序、ID 与内容，每处理 64 KB 主动让出事件循环，成功后才建立基线，防止 SDK 加载后、绑定前的外写被接纳。正常追加只从上次位置读取新增尾部，通过原生 `getEntry(id)` 核对；不重复扫描历史。同 inode、同大小但时间戳改变时，分块完整核对 JSON 记录；内容一致只更新 stamp，因此 touch 不会进入只读或中断运行。核对允许合法 JSON 空白与 CRLF，读前读后核对 fd 和路径状态。首次绑定、首次落盘和同大小 stamp 变化的完整复核属于阻塞校验，快照 `tree.verifying` 为 true，输入框和树写操作暂时禁用；正常增长的尾部校验静默运行，不覆盖恢复状态，不触发额外校验快照。内部 checking 与阻塞 blocking 分开，发现不一致仍进入外部修改状态。prompt 等待已有校验完成并重查活动对话、实例、外写与操作占用；切换、重开或销毁后旧请求失效。只读查看始终可用。超过 256K 字符的单条 JSON 记录交给按需 worker 解析和比较，结束后释放线程。校验期间自身追加会重新采样核对，文件替换、截断或内容不匹配才进入外部修改状态；切换文件、重新打开或释放对话会取消旧校验，旧结果不能恢复新实例的写权限。校验失败保持失败状态，直到重新打开。首次原生延迟 flush 校验会话头与全部首次落盘条目。截断、inode 变化、同长度内容变化、未知/重复条目或不完整追加均标记为外部修改。校验基于原生 append-only 约定，不扫描增长文件的既有前缀。正在运行时请求原生 abort；后续 prompt、树写操作、模型与思考变更及活动文件重命名被拒绝。树仍可只读查看。

“重新打开”直接调用捕获 runtime 的 `switchSession`，避免普通历史打开复用同一路径的旧 runtime。重绑成功才清除外部修改状态。文件监视在替换、移除和释放会话时关闭。

这不是文件锁：检测与其他进程的写入之间仍存在竞态，不能保证两个进程同时写入安全。CLI 与 WebUI 交替操作时应等待一方结束，再在另一方重新打开。

## 验证

- `tests/unit/session-tree.test.ts`：真实 CLI TreeSelectorComponent 的五种过滤与搜索逐项对比，多根、标签覆盖/清除、兄弟目标，以及 10000 节点过滤截断和 200ms 性能门槛。
- `tests/session-tree-test.mjs`：隔离端口和目录、真实 SDK 与本地模拟模型，验证原地编辑、摘要成功/失败/取消、扩展取消/弹窗、运行中取回队列、压缩守卫、外部写入及重新打开、原生派生与命令；`--browser` 验证面板、消息兄弟切换器、书签、全文与草稿保护。
- 新协议纳入 `check:protocol`；协议回归纳入完整冒烟。

历史列表的分叉数通过 `SessionBranchCounts` 异步只读解析原生文件并统计 parentId，按设备/inode/长度/mtime/ctime 缓存（最多 1000 项）。列表先排序截取最多 200 条，再由最多 8 个 worker 并行获取分叉数，按输入位置组装结果；单文件失败只省略该条分叉数。列表读取不调用 `SessionManager.open`，避免旧格式迁移或空文件初始化副作用。

编辑重问的非成功结果由 WebSocket 接收层统一发出对话所属 notice，不依赖树面板是否打开。`tests/unit/session-file-read.test.ts` 覆盖 5000 条、超过 11 MB 的尾部 I/O、大文件连续追加、异常外写、延迟首次落盘和旧/空文件只读读取。

树节点全文面板可按 toolCallId 下载完整工具输出，包括压缩前及其他分支的原生工具结果。中断后的最终落盘及派生后的新文件校验完成后，才执行后续导航或编辑重问。
