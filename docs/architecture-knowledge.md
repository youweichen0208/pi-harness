# 普通会话的 Learn 与 Ask

用户在普通聊天中输入 `/learn`、`/ask` 或对应的 `/skill:名称`。宿主将别名交给原生 Skill 展开，使用会话实际加载的文件。项目或用户同名 Skill 优先。两项资源均设置 `disable-model-invocation: true`。Engineering 的 Knowledge Sync 核对项目文档，Reflect 处理工作方法；用户单独发起 Learn 才会蒸馏会话知识。

## 请求归属与工具

`agent-service.ts` 在发送前确定对话、原生 session、请求 ID、Skill 路径和来源范围。`knowledge-tools.ts` 在 `before_agent_start` 核对原生 Skill 块与请求身份，通过 `tool_call` 在执行前核验工具名及注册来源。只有属于该任务的宿主续接可以沿用同一权限。

| 场景 | 可用知识工具 |
| --- | --- |
| Ask | `knowledge_sources`、`source_list`、`source_search`、`source_read`、`knowledge_investigate` |
| Learn | 前四种读取工具和 `knowledge_write` |
| 普通研发 | 还原原生工具配置，知识工具不可执行 |

与知识请求交错的消息进入所属对话的先进先出队列，保留原始文本、附件与回执。宿主等待当前请求 settled，并在该对话激活后发起下一次独立请求。撤回走现有草稿恢复接口。Wiki、SSH 节点、Playground 和调查子会话分别使用自己的资源加载器。

## 来源与证据

工作区目录来自 ProjectWorkspaceStore，知识库使用当前 KnowledgeLibrary 配置。未分组时读取当前项目和可用知识库。当前项目属于多个分组时先选择一个 Workspace，再根据显式来源名或 sourceId 收窄范围。可唯一解析的名称直接使用，名称冲突时选择来源。每次读取都会重新核对登记状态。

工具只接受已授权 sourceId 和来源相对路径，检查真实根、符号链接、文件类型和读取期间的变化。字面搜索调用随包 ripgrep 并核对命中行。单文件最多 1 MiB，单次读取最多 300 行，工具文本输出预算为 24 KiB。只有实际看到的完整行能签发证据。元数据包含来源、相对路径、起止行和完整文件 SHA-256；Git 可用时记录 revision 与文件工作树状态，取不到时保留未知。

## Ask 与并行调查

内置 Ask 默认由主 Agent 查证完整链路。已知路径直接读取，符号或错误码先精确搜索；跨仓时根据上一处源码中的 RPC 方法、事件或任务键继续定位消费方或状态写入点。仓库数量、模块规模或跨引擎比较本身不足以触发委派。

需要并行验证假设、隔离可独立完成的调查或独立复核时，可调用调查工具处理一至三项任务，每项指明问题、授权来源和预期查证结果。同一父会话串行受理调查调用。子会话共享父模型运行时、模型与 thinking 档位，使用独立的内存 SessionManager，仅获得任务列出的来源、读取工具及 `source_report`。

子会话报告只能引用本次实际观察的证据，提交时回读并比较指纹及行范围。返回的结构化结果区分已检查来源、发现、缺口、失败和截断。每个子任务限制为 180 秒、16 轮和 32 次工具调用。停止父任务或关闭会话会取消调查。主 Agent 回读支撑结论的原文后再引用，并注明历史记录与当前实现的差异。旧 Workspace Subagent 的任务平台已于 `09d05fe` 移除。

### 回答中的证据链

单点问题给出结论和源码引用。多步问题按交接顺序说明每一步的依据。例如，从仓 A 的任务发布者定位到仓 B 的订阅处理函数，需要核对发布键和订阅绑定，再定位写入终态的代码。链路适合图解时，回答使用 Mermaid 代码块，在图下按相同步骤列出普通 Markdown 证据链接。仅凭同名函数或历史说明猜测的连接标为推断或缺口。

排障回答分别说明源码允许的执行路径和该次故障已观测到的路径。缺少部署版本、对应任务的日志或指标时，写明可区分候选原因的观测点。图与逐步说明都属于回答正文，源码预览沿用协议 v66 的 evidenceId。

## Learn 与磁盘写入

Learn 只从当前可见分支提取可长期复用的信息，遇到压缩历史应说明可见范围。主 Agent 核实事实、搜索已有条目、选择增量更新、跳过或提交候选。缺少知识库配置时仍可列出候选。

`knowledge_write` 为单个 Markdown 文件生成精确 diff，并通过已有扩展 UI 逐次确认。服务端从会话 ID、既有来源及本次读取的证据生成 sources。支持 title、type、tags、status、sources、updated；状态为 verified、inferred 或 unverified。创建要求父目录存在并独占创建，更新要求原始内容 SHA-256。确认后重新核对请求、登记来源与磁盘版本，WikiService 记录 Pi 修订并失效索引。取消、同内容及版本冲突均保留磁盘原状。

## 协议 v66 与旧引用

回答使用 `[来源/路径:行](#pi-evidence=ev_…)`。前端以 evidenceId、当前项目与对话身份发送 `read_file`。服务端从当前原生分支的自定义条目查找证据，核对当前登记范围、真实根与完整文件指纹。256 项内存缓存只加速近期查找；重新打开会话时可沿当前分支恢复更早引用。

`file_content` 携带 FileEvidenceView、窗口起始行和有界文本。窗口最多 120 行、64 KiB，保留原始行号。文件已变返回 `stale_evidence`，归属或授权无效返回 `evidence_unavailable`。前端复用 FilePreview 展示只读源码，切换项目或对话时关闭旧证据。普通文件编辑仍使用原有当前项目路径和版本检查。

## 回归入口

`tests/knowledge-engine-test.mjs` 验证真实 SDK、模拟模型、持久引用和确认写入，加 `--browser` 验证 Chromium 交互。`tests/knowledge-investigate-test.mjs` 验证隔离并行、继承和取消，`tests/knowledge-queue-test.mjs` 覆盖跨模式排队及撤回。打包测试从实际应用路径运行相同知识流程。真实模型另用合成仓库验收重复 Learn、新会话读回、跨仓引用、历史冲突与来源限制。

### Ask 策略的行为验收

使用真实 `/ask` 入口比较 A（原 Skill）和 B（主 Agent 优先）。固定来源快照、模型、thinking 档位和工具权限，为每次运行创建独立会话并核对实际加载的 Skill。两组均保留调查工具，以工具轨迹统计实际委派。题集至少包括已知错误码、逐步发现任务键的跨仓异步链、可独立验证的两个假设，以及缺少部署版本或日志的故障。模拟模型回归覆盖机制，策略效果由真实模型重复运行验证。

按题预标注关键事实及其源码行。记录从发问到首次读回支撑其中一项事实的完整源码行所用时间，始终未找到的样本单列。同时核对最终答案正确性与证据覆盖，汇总父子会话 token、总耗时、去重文件数及无效路径次数。重复读取率取同一来源、路径和文件版本中已读行的再次读取量除以全部读取行数，单列主 Agent 为最终引用回读的部分。

### 后续图谱实验

M2 在离线样本上比较候选引擎，先覆盖目标链路使用的代码符号（L1）和一种跨仓契约（L2）。M3 选择有已知答案的真实异步任务，从终态写入方反查触发方，检查同名契约、未授权中间节点，以及单仓文件修改、重命名或删除后的边失效。候选边应能定位到两端版本和原文。

M4 用 C 组（B 加只读图谱工具）测量图谱的独立收益。主 Agent 可查询节点、邻居和路径，再用现有工具回读取证。另计候选关系准确率、首次建索引与增量更新成本。重复运行中保持正确性与覆盖、且能稳定降低成本或取证时间的问题类型，才进入图谱优先路由。M5 再评估 Wiki 业务语义（L3）与代码的关联。
