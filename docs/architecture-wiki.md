# Wiki 文档弹窗

点击文件树、全局搜索或聊天文件链接中的 `.md` / `.markdown`，在当前界面上方打开同一个可编辑文档弹窗。桌面宽 92vw（最大 1440px）、高 90dvh，小屏全屏；顶栏提供文件名、保存状态、最近改动、全屏／退出全屏和关闭。文件栏默认收起，按需展开。格式工具栏、源码切换、搜索、双链、证据只读与改动记录继续复用。

`App.tsx` 独立维护 cwd、原 conversationId、路径及导航 token，不切换主视图，不创建临时会话。弹窗右侧默认显示 400px Agent Chat，可拖动调宽、收起，小屏使用可展开的覆盖式面板。`ChatDock` 通过固定 portal 容器移动原有 MessageList 和 ChatInput，始终只挂载一份消息、草稿和附件状态，回复正常更新；关闭弹窗将原实例移回并恢复进入前的聊天滚动位置。服务端原有 Wiki prompt/new-conversation 接口保留兼容，但文档弹窗不调用它们。

## 保存、关闭与原聊天引用

`WikiWorkbench` 继续通过 `useWikiAutosave` 在停止输入 800ms 后保存；写入以字节 SHA-256 比较版本，保存确认只更新基线，不覆盖新输入。加载、原聊天运行及恢复操作期间保持编辑保护，证据快照继续只读。关闭按钮、遮罩与 Escape 都经过同一导航守卫：先排空保存，失败则保留弹窗，可继续编辑、重试或明确放弃。冲突必须先重载或保留自己的版本。切换文档也经过守卫。

选区「问 pi」捕获点击时的文字与文件路径，保存成功后回调 App，展开右侧 Agent Chat 并追加到原聊天输入末尾，保留已有草稿和附件、聚焦但不发送，文档弹窗保持打开；引用操作本身不额外附加整篇文档。保存失败不转移引用。请求带唯一 ID、cwd 和原 conversationId，App 与 ChatInput 都检查归属，ChatInput 消费 ID 去重；卸载或文档读取序号变化后丢弃迟到结果。工作区或会话变化清除待传引用。

右栏输入框自动显示当前 Wiki 文档的 `@文件名` chip，切换文档时替换，关闭弹窗后恢复普通文件预览上下文。Wiki 独立注册当前文件读取器，避免后台预览覆盖；发送时沿用完整编辑器快照、512 KiB 上限与同路径附件去重，保存成功后读取最新正文和版本。可手动移除 chip，重新打开文档恢复；无文本的媒体不产生 chip。选区「问 pi」仍只追加选中文字，整篇文档是否携带由当前文件 chip 决定。

右栏发送通过 `ChatInput.beforeSend` 排空 Wiki 保存队列；冲突或失败时不发送且保留聊天草稿。保存完成后再次检查打开请求 token、cwd 与 conversationId，关闭或导航后的迟到操作不发送。模型设置入口先经过文档关闭保护再打开设置。

`WikiDocumentModal` 使用原生模态 dialog，让后台界面 inert 并约束焦点，关闭恢复原焦点且不滚动背景。编辑器的浮动工具条与嵌套弹窗 portal 挂入文档 dialog，Escape 优先关闭内部菜单、搜索及确认框。全屏按钮对 `document.documentElement` 调用 Fullscreen API（规范不允许 dialog 自身全屏），弹窗同时铺满视口；进入全屏后 `fullscreenchange` 会关闭并重新 `showModal()` 弹窗，让它回到顶层最上方（Electron 会把全屏页面画在已打开的 dialog 之上，#89），同时保留滚动、焦点与选区；Esc 或系统控件退出全屏时监听 `fullscreenchange` 恢复原尺寸，关闭弹窗时退出由它进入的全屏。退出前先等待进入请求完成；桌面版还要等 macOS 全屏动画结束（主进程在 `enter-html-full-screen` 到 `enter-full-screen` 之间发布 `fullscreenSettling`），动画中途退出会让页面停在全屏且退出请求永不返回。请求被拒绝时只做窗口内铺满。全程只改变尺寸，保留编辑器实例、草稿与光标。Electron 主进程同步 `enter/leave-html-full-screen` 窗口状态。回归：`tests/wiki-fullscreen-electron-test.mjs`。同项目同文档的滚动位置保存在最多 100 项的内存缓存中，重新打开时恢复。

## 阅读交互

正文默认直接编辑，独立 44px 插入工具栏、选区浮动格式栏和源码切换。标准正文 760px、宽版 1000px；标题使用本地 Source Serif 4 / Noto Serif SC，正文 IBM Plex Sans，代码 JetBrains Mono。元信息保留更新时间、阅读时间和标签，frontmatter、重复 H1 及开头属性表隐藏于正文但保存时保留原文。

隐藏根目录分组、文件栏拖动宽度、目录树按需加载、双链和索引详情沿用已有行为。搜索支持 Cmd/Ctrl+P（兼容 Cmd/Ctrl+K），Cmd/Ctrl+Enter 把命中路径与片段按保存后的引用流程送回聊天。右栏使用原聊天完整能力，不创建文档专用会话，不显示底部输入胶囊或「对话 | Wiki」切换。

## 文件与索引

OKF 扩展已移除；此前导出的知识目录中，带有效知识 manifest 的 evidence 副本仍排除后台索引与撤销快照并保持只读，显式打开保留；明确相对文件链接不依赖索引命中。

文件栏使用与普通文件树一致的顶部搜索、32px 行高、18px 缩进与线框图标；悬停／聚焦的浅黄色链接按钮把文件或目录以 reference 附加到右侧原聊天，不自动发送或打开目录。文件栏提供新建文件，默认填入当前文档的父目录；与普通文件树共用创建表单和独占创建接口，详见 [附件与文件处理](architecture-attachments.md#手动新建文件)。创建成功后经过自动保存导航保护打开新文件。

`wiki-service.ts` 负责工作区索引、文档读取、搜索和文件历史；`wiki-links.ts` 定义标签与链接解析。HTTP 类型只在 `server/protocol.ts` 声明，经现有 type-only shim 供浏览器使用。

正文使用 `document-content`：仅校验目标真实路径，读取文件和元数据、SHA-256 版本，返回 `WikiDocumentContent`，不等待索引。引用使用独立 `document-references`（`WikiDocumentReferences`）；索引缓存各文件已解析链接及反向引用表，后台引用只更新链接，不覆盖编辑草稿。引用尚未返回时显示加载状态，不显示 0 篇。原 `document` 完整接口保持兼容。只读 HTTP 查询允许同项目原生会话切换；项目变化拒绝旧结果，写入/发送仍校验原会话。正文响应由组件存活状态和读取序号丢弃迟到结果。

- Markdown / txt 默认在渲染预览中直接编辑，复用 `RichMarkdownEditor` 的格式栏、斜杠插入、截图粘贴及段落原文保真。frontmatter、重复 H1 与已识别的开头连续字段/值属性在正文中隐藏但保存时保留；属性在元信息下以可折叠表格展示，由 `wiki-properties.ts` 返回源文范围，正文其他位置不提取；双链、目录及代码配色继续可用。Markdown 提供源码/富文本切换；代码编辑共用保存机制，保存、冲突、发送前保存及导航保护沿用同一路径；运行和加载期间只读，自动保存期间仍可编辑。源码模式使用现有 `CodeFileEditor`。代码默认只读，可显式点击「编辑源码」手工编辑。保存只接受未截断的 UTF-8 文本，并比较原始字节 SHA-256。write 返回轻量 WikiDocumentContent，不等待引用索引；保存后后台刷新索引，点击发送立即显示「发送中」，失败保留输入。
- 目录：插入工具栏和斜杠菜单的「插入目录」（`/ml`）在标题下方插入一次 `<!-- toc -->` … `<!-- /toc -->` 块，已有则只滚动到它。块内列表由 `markdown-toc.ts` 根据块之后的顶层 H1–H3 生成，锚点与 GitHub 一致（重复标题按全文编号）。富文本编辑器把标记区间作为一个只读块渲染为可点击目录（点击滚动到编辑器内对应标题，「移除目录」删除整块）；每次编辑序列化时只重写标记之间的内容，其余字节不变。仅打开文件不会写入：过期目录在界面上按当前标题显示，下一次编辑时才写回。源码模式与 pi 直接改文件时不自动更新，回到富文本编辑后再生成。
- 标签读取 YAML 风格 `tags: [a, b]`、逐行列表与正文 `#标签`。通过 Markdown 语法树排除围栏、行内代码、缩进代码及链接地址；3/4/6/8 位十六进制颜色值不计为标签。解析结果用于索引元数据和标题下的 #标签；不提供标签筛选或 `#` 候选，原文件内容不变。
- `[[文件名]]`、`[[路径|显示名]]` 优先解析同目录、再解析工作区相对路径，最后只接受唯一的同名文件。重复文件名必须写明路径。Markdown 相对链接与行内代码文件路径也参与引用索引。反向链接包含来源路径和引用句子；每次展示 100 条，可继续加载，避免大型引用表阻塞正文交互。
- 文件树包含文档、代码、媒体和其他文件类型，依赖目录与 `.git` 等基础噪声目录除外；目录按需分页读取（每页 500 条），树行按可见窗口挂载。空目录保留。目录符号链接不递归建立索引，可以手动展开；读取必须通过真实路径边界检查。
- 搜索匹配文件路径与文本内容，结果按文档 / 代码 / PDF / 其他分组；支持方向键、Enter 打开、Cmd/Ctrl+Enter 引用给 pi。
- 后台索引和任务撤销快照跳过 `.claude/worktrees` 重复检出、`.venv`、`__pycache__`、`.pytest_cache`、`.mypy_cache`、`.ruff_cache` 目录，不让它们占用主项目预算；显式目录浏览与文件打开仍可用，`.claude/skills` 等上下文保留，直接打开某个 worktree 作为项目时仍正常索引其正文。索引最大 20,000 项、深度 32、文本单文件 2 MiB、总读取量 64 MiB。`WikiState.index` 返回已读取文件数、已发现文件总数、受限路径/字节数/原因；底栏入口打开详情，不再常驻顶部黄条。底栏只显示已索引/总数与跳过数量（千分位、黄色），原因置于悬停和详情，详情按原因分别计数。因项数、深度或目录权限中止扫描时标记 `totalIsLowerBound`，总数位置显示「统计中」，列出未扫描目录；没有扫描的后代不伪造数量。二进制文件仍按文件名索引，PDF 文本按搜索时提取；搜索最多返回 100 项。索引缓存约 30 秒，同一项目并发扫描合并；有缓存时立即返回并后台更新。进入/切换 Wiki 不强制扫描，手动刷新、保存和撤销会失效更新；任务前后撤销快照独立遍历最新文件并读取字节，不等待索引，也不解析 Markdown 元数据或引用。仅可见的 Wiki 轮询，普通周期 30 秒，任务运行及历史收尾期间缩短为 1 秒。只有文档（`.md`／`.markdown`／`.txt`）解析标签、标题和引用，代码文件只按全文与文件名索引；解析结果按内容 SHA-256 缓存，保存或任务后的重建只解析变化的文档。引用解析使用路径集合与文件名表查找，不逐条扫描全部路径。修复前，代码项目在每次保存和任务后都要把全部源文件当 Markdown 解析，并对每个引用遍历全部路径，单次重建可达数分钟并阻塞事件循环，表现为「发送中」和「保存中」长时间不结束。
- PDF 使用 [PDF.js 的 Node API](https://github.com/mozilla/pdf.js/blob/master/examples/node/getinfo.mjs) 提取文字，独立进程最多并行 2 个，每份 8 秒硬超时；每次搜索最多 8 份 PDF，每份 ≤20 MiB、≤200 页。纯扫描 PDF 需要已有文字层，当前不做 OCR。超限、加密或解析失败有结果限制提示。
- 图片与 PDF 走同源、鉴权、cwd 归属与真实路径检查的 `/api/wiki-media`。其他文件在浏览器中下载后打开；Electron 的固定 IPC 经本机服务校验当前工作区后调用系统默认应用。

## 改动记录与恢复

记录保存在 `<dataDir>/wiki/<real-workspace-hash>/`，与项目文件分离。每次 Wiki 提问开始前独立遍历并读取最新文件字节，任务结束后同样读取并比较；手工编辑保存单独记为「我」。新增、修改、删除与二进制改动均可恢复。列表仅提供短预览，展开大文件时读取完整前后版本。

历史按工作区保留最近 100 次有改动的请求，同时按 128 MiB 字节预算清理旧记录及未引用的内容文件。每次快照受 2 MiB 单文件、64 MiB 总量约束，未记录文件明确列出。记录比较请求期间观察到的磁盘版本；同时由外部编辑器或其他会话写入的文件也可能被包含。它不是 Git 事务或跨进程写锁；进程意外退出前未结束的请求不保证有完整撤销记录。

恢复支持整次请求和单个文件：先验证所有目标文件仍等于该记录的预期版本，再恢复原始字节；任一文件有后续修改则整组拒绝，保留现场。本进程写入失败会回滚本次已恢复的文件。撤销后可重做；新建文件的撤销为删除，删除文件的撤销为恢复。撤销不改写 pi 对话历史。

目录蓝点表示有未查看的历史 pi 改动，打开文件清除蓝点。完整的原始前后版本在改动抽屉中。普通聊天任务的改动继续走聊天改动面板，不自动生成旧 Wiki 提问记录。

### 历史导航性能复测（2026-10-05，旧 Wiki 模式，本机 Chrome）

服务预先启动，以正文实际出现且编辑器 `contenteditable=true` 为就绪；会话就绪单独计时。500 文件隔离项目中，切换目标约 98 KB，首次进入、连续切换、返回 Wiki 各 20 次，编辑器 P95 分别为 235 / 338 / 341 ms，会话 P95 为 353 / 401 / 399 ms；正文 HTTP 请求 P95 为 18 ms。人为延迟索引/会话动作 5 秒时，正文仍在 1 秒内可编辑，发送保持禁用，初始化完成后草稿不丢失。

对本机 `blog/docs` 做只读浏览器复测，三种场景各 20 次，编辑器 P95 为 125 / 134 / 159 ms，会话 P95 为 162 / 164 / 205 ms，正文 HTTP P95 为 12 ms；读取文件哈希前后一致。独立服务读取 60 次的正文 P95 为 8.8 ms，包含冷索引的完整接口单次约 5.1 秒。以上是本机结果，不将大于 100 KB 文档或网络文件系统延迟计入 1 秒验收。

大文档单独复测：约 1 MiB 的纯 Markdown，三种场景各 5 次，编辑器 P95 为 727 / 1121 / 1233 ms，正文 HTTP P95 为 84 ms；测试时同时运行其他冒烟检查。当前没有可用的慢速网络文件系统，未测该场景。

### 大量代码块文档（2026-10-09）

Wiki 富文本代码只生成一份可编辑的纯文本 DOM，由 CSS Highlight API 着色；不再先生成高亮 span 再重复解析。进入视口及其前后 400px 的代码块才计算颜色，编辑当前代码仍立即刷新。未变的内容和仍连接的文本节点复用高亮范围；卸载时清理观察器和范围。全文保留在 DOM 中，浏览器搜索、目录跳转、跨块选择和原生撤销保持可用。源码行号按段落累计，避免对每个段落重新扫描全文。

`tests/wiki-large-document-test.mjs` 使用 23,803 行、735,708 字节、200 个 TypeScript 代码块，浏览器 CPU 降速 4 倍。相同本机环境，优化前打开约 12.7 秒、最长任务 7.5 秒；优化后两次打开约 3.1/3.4 秒、最长任务约 2.5/2.7 秒。测试覆盖文末滚动后的颜色、自动保存及未修改块原文保真。该结果为 macOS Chromium 的 CPU 降速测量，不代表 Windows 真机数据，也不保证所有 Markdown 结构达到相同耗时。

### 发送前准备耗时（2026-10-05，本机）

修复前 `blog/docs` 只读复测 `WikiService.begin` 单次 3552 ms，主要耗时为发送前强制重建索引及引用解析。撤销快照独立读取最新字节后，20 次 P95 50 ms、最大 99 ms。该指标不包含原生会话初始化及模型网络响应，未调用模型、未修改用户项目文件。

完整发送链路在隔离的 500 文件项目中验证：点击到原生 prompt 接受，普通 hello 为 85 ms，先保存草稿再发送为 89 ms；模拟模型延迟独立于发送准备。

## 22a 编辑态与自动保存

`use-wiki-autosave.ts` 在停笔 800ms 后保存，Cmd/Ctrl+S、导航及桌面关闭立即保存。写请求串行；每次使用最近确认的磁盘版本，响应只推进基线，不替换当前草稿。排空队列会继续保存等待期间输入的新内容。普通失败显示红点「保存失败 · 重试」，不循环重试；CAS 冲突返回 HTTP 409 / `WikiApiError.code = version_conflict`，保留草稿并显示「文件已在外部修改 · 重新载入 / 保留我的版本」。保留版本先读最新磁盘版本，再进行 CAS 写入，外部再次修改仍会冲突。元信息末尾显示黄点保存中、绿点已保存；顶栏不再有保存按钮或额外未保存文案。

桌面使用固定 `onBeforeClose` 桥等待保存，然后隐藏到托盘或退出；保存失败保留窗口和草稿。浏览器 beforeunload 立即尝试保存并保留原生离开保护，不能保证强制关闭进程或断电时异步请求完成。

Wiki 的 `/` 菜单在文本块开头或空格后触发，排除代码、链接、列表和保护块。中文、英文、拼音及旧别名均可搜索；空格/标点关闭，方向键选择、Enter 插入、Esc 关闭并保留输入。300px 单列、最多 8 行、上下翻转适配光标。顺序为正文、H1–H3、列表、编号、任务、引用、代码、提示、3×3 表格、分隔线、图片和文档链接；右侧显示 Markdown 记法。直接输入 `#`–`######`、列表、引用等前缀加空格转换块，H4–H6 保留这种入口。图片复用安全上传与相对路径保存；`[[` 打开文档搜索，普通链接支持 URL 输入。

选区浮条位于选区上方，空间不足时放下方，提供粗体、斜体、H2、H3、链接、黄/绿背景和问 pi。再次点击同色清除标记；继续使用已有固定色值 mark 序列化和原生撤销栈，已有五色标记可正常读取。撤销/重做只用快捷键，普通文件预览仍保留其格式栏。完整索引成功后隐藏底栏索引项，有未完成/跳过项仍保留详情；状态栏不显示消息计数。

历史 Wiki 提问记录携带 `conversationId`、`requestId` 和 `assistantTimestamp`，弹窗的最近改动继续读取这些记录与手工保存记录，展开时读取完整 diff；撤销仍按整个请求做版本预检。

回归：`tests/wiki-editing-test.mjs` 覆盖延迟确认期间继续编辑、立即导航保存、失败重试、冲突处理、紧凑菜单、Markdown 简写、选区格式和窄屏；`tests/wiki-desktop-save-test.mjs` 在真实 Electron 验证关闭、退出及失败保留窗口；`tests/wiki-modal-browser-test.mjs` 验证弹窗、保存保护及选区回填。设计稿待定的 AI 续写/总结命令、最近使用分组及问 pi 结果替换流程未加入。
