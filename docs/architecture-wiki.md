## 知识库入口（ADR-0006）

左侧「知识库」打开独立 Wiki 窗口。一个本地文件夹就是整个知识库，子目录用于分类；配置独立于 Workspace。首次选择目录，后续恢复上次打开的 Markdown；空目录可直接打开，目录失效时重新选择。窗口内「更换知识库文件夹」沿用保存与中断保护，更换成功后保存配置，保留原目录的文件和聊天历史。

`server/knowledge-library.ts` 将配置与最近文档原子写入 `<dataDir>/knowledge-library.json`。`POST /api/knowledge-library` 提供 read/configure/remember，沿用鉴权与同源检查；目录规范化为真实路径，最近文档须位于目录内且为 Markdown，旧窗口不能覆盖新目录的记录。新入口同步打开带 `knowledge-library=1` 的 Wiki 窗口，在窗口内读取配置，避免异步弹窗拦截。旧 Wiki URL 继续兼容；知识库窗口不会切换主聊天项目。

普通模式的文件树、聊天链接、工具卡片和本轮文件入口打开 Markdown 时，使用单文件弹窗与主聊天，详见 `architecture-attachments.md`。Wiki 内部链接仍在 Wiki 内导航。回归：`tests/knowledge-library-browser-test.mjs` 与 `tests/unit/knowledge-library.test.ts`。


### 打开与恢复的职责

`wiki-window-session.ts` 的 WikiWindowSession 持有本地知识库启动与恢复状态；`use-wiki-window-session.ts` 是 React／窗口／网络 adapter。配置读取、明确选择目录、URL 目标、模型和思考继承、服务端确认、运行实例恢复在同一 module 内排序。明确选择目录使迟到的配置读取失效，卸载后忽略异步结果；模型继承最多等待 5 秒，切目录只在权威状态确认后进入 Wiki 对话。恢复必须同时匹配窗口客户端、cwd、sessionId、conversationId 及明确的 URL 文档。

App 保留展示和用户交互；已打开窗口的保存、中断与切换仍由 WikiCoordinator 准入，更换目录成功后才调用 folderOpened 提交知识库配置。文档记忆串行写入，旧窗口不能覆盖新的库根目录。自动保存 module、发送回执和聊天归属规则保持不变。

回归：`tests/unit/wiki-window-session.test.ts` 控制配置读取和切目录确认的顺序，覆盖迟到结果、关闭、刷新、模型继承超时、失效目录和配置失败；浏览器与 Electron 回归继续覆盖真实窗口 adapter。

## 文档绑定与 Workspace 追加分析（当前规则）

每篇 Markdown 按工作区真实根目录和文档规范路径绑定独立 chat；`chat-document` 恢复该文档最近会话，首次打开创建并记录 sidecar `documentPath`，历史按文档过滤。仍有消息的旧会话不自动绑定新文档。无消息的 SDK SessionManager 在客户端保留最多 32 篇文档以支持空白草稿切回，不增加后台 Agent；重启后非空历史从原生 transcript 恢复。媒体、代码等非文档文件（`isWikiDocumentPath` 之外）不绑定会话：点击只切换正文只读预览（图片 / PDF / 源码 / 下载），沿用当前 Wiki 会话，不产生当前文件 chip、不清空追加项目，也无需中断运行中的任务；当前不是 Wiki 会话时（刷新后直接打开媒体）先建空白会话。回归：`tests/wiki-media-preview-test.mjs`（issue #119）。

追加分析范围来自已有 Workspace 分组下一个项目／知识库。`chat-projects` 返回现有目录，`chat-validate-project` 校验分组成员和目录存在性；选中项目以可见提示文本随本次问题发送，由原生工具按需读取，不放宽 Wiki 文件服务或附件路径边界，也不接入额外检索服务。当前 Markdown 固定携带编辑器快照。切换文档清空追加项目，返回旧文档也不恢复该选择；既有历史消息保持原样。项目选择在发送时冻结并再次校验，删除或移出分组后阻止发送。刷新同样回到仅当前文档。

回归：`tests/wiki-assistant-test.mjs` 覆盖每文档会话、项目清除、原生提示范围、历史隔离、草稿、服务重启与窄屏；`tests/wiki-assistant-window-test.mjs` 覆盖原生浮窗。

## Wiki 右栏与编辑回归（#116–117）

## 窗口与会话

Wiki 使用独立顶层窗口（ADR-0003）：浏览器命名弹窗 `pi-wiki`，Electron 第二个 BrowserWindow；主窗口保持普通对话。URL 契约仍为 `?wiki-window=1&cwd=&doc=&client=&model=&thinking=`，客户端独立，token 不进 URL。标题栏和面包屑保持桌面拖动区，控件为 no-drag。原生模型／思考档位继承保持原有校验与超时兜底。

**Wiki 对话**按工作区持久保存，每篇文档独立恢复对话；切换正文、新建或打开历史时切换 SDK 会话。`hello.wikiCwd` 在独立目录初始化空白会话，前端 `chat-document` 恢复目标文档的会话；无历史时创建或复用初始空白实例。SDK transcript 位于 `<dataDir>/wiki/<sha256(realpath(cwd))>/sessions/`，设置 sidecar 保存标题、额外文档引用和最近打开时间。普通会话仍使用 SDK 默认目录，普通历史不会扫描 Wiki 目录。未发送的空白会话不进入历史。旧临时会话已经清理的内容不能迁移恢复。

`WikiChatStore` 提供路径受限的列表、查找、设置与删除；`/api/wiki` 新增 `chat-list/context/references/validate-references/resume/new/open/rename/delete`。写操作验证当前 conversationId、工作区和 quiesce，异步切换按工作区串行准入，跨窗口打开同一 transcript 时检查占用；已断开且无任务／终端的旧客户端先释放再恢复。会话文件路径由服务端根据稳定 SDK sessionId 查询，不接受任意客户端文件路径。删除先释放对应运行实例，只删除对话和设置，不删除文档；带运行任务或终端的会话拒绝删除。

**退出与恢复**：关闭窗口先走文档保存和运行中断确认。关闭后运行实例可由闲置客户端清理，持久 transcript 保留。刷新优先复用仍存活的 runtime；服务重启后旧 conversationId 不再有效时重新按工作区恢复历史。明确指定的 URL 文档决定正文，恢复对话不会强制打开历史里的某篇文档。新建／切历史前保存文档，保存失败或中断取消保留现场。聊天草稿按工作区及稳定 sessionId 存 sessionStorage，额外引用随对话持久保存。运行中切换文档、工作区或对话仍先确认中断并等待 `agent_settled`。

`WikiWindowShell` 管理浮动／固定展示，`ChatDock` 移动同一个 MessageList + ChatInput 宿主，切换布局不重建聊天。默认收起问 pi、显示大纲；打开问 pi 默认浮动（420px，视口内拖动与缩放），固定模式替换右侧大纲，收起恢复大纲。localStorage 保存布局选择和浮动位置／尺寸，sessionStorage 保存展开状态。小于 900px 使用覆盖面板，暂不提供固定和拖动。文档改动抽屉在浮动助手之上。`WikiDocumentModal` 同时承载数据库与普通单文件文档弹窗。

聊天正文文件链接继续在当前 Wiki 窗口内打开，保留保存与中断保护；不导航到裸文件 URL。回归：`wiki-chat-links-desktop-test.mjs` 覆盖 Electron 流式、冻结和完成回复的链接、切文件夹、空目录与主窗口隔离。

## 多文档引用与历史面板

`WikiAssistantSheet` 使用原生 modal dialog 保证焦点约束，关闭后恢复触发控件焦点。文档选择支持标题／路径过滤、按本地日历日的今天及滚动七／三十天修改时间过滤、文件夹分页浏览；范围为当前工作区 `.md/.markdown/.txt`，最多 100 个额外引用。时间来自 mtime，文案为“修改”而不是“我编辑”。索引受限时提示并提供文件夹继续查找。选择在点击确定后应用，取消不修改；文件夹只用于浏览，不隐式全选。

当前文件 chip 继续镜像正文，手动额外引用独立保存，切文档保留、发送后保留；相同文件只发送一次，当前编辑器快照优先。旧版额外文档使用现有 reference 模式按需读取，既不自动注入所有全文，也不改变 Agent 工具权限。服务端校验路径及真实路径边界、存在性和文件类型；缺失引用阻止发送并保留输入，可移除后重试。发送冻结选择列表，预检仅验证文件、不覆盖期间改变的持久选择；排空正文保存后再次校验文档 token、工作区及会话；切换对话期间不发送旧草稿。

历史按更新时间排列，支持标题搜索、重命名和确认删除；默认标题来自首条用户消息，不调用模型。文件改动记录保持独立，新 HTTP prompt 记录带稳定 sessionId，旧记录不推测归属。

回归：`tests/wiki-assistant-test.mjs`（本地模拟模型，布局、引用、草稿、历史、重启、跨窗口占用、缺失文件、小屏和删除），`tests/unit/wiki-chat-store.test.ts`（原生持久化、路径与工作区隔离）。

## 切换文件夹

左侧目录栏默认常驻，切换文档或文件夹后保持展开；标题栏不再显示目录开关。窄窗口缩小目录栏宽度，与正文并排显示，宽版阅读模式仍可临时隐藏侧栏。

Wiki 左侧目录栏顶部的「打开文件夹」复用 `FolderPickerModal` 与 `browse_dirs`，从当前工作目录开始浏览，也支持手动输入服务器本地路径（桌面版为本机目录）。选择后先走自动保存导航守卫；运行中的任务先确认中断，等待 settle 后再保存和切换。取消或保存失败保留原文档，目录校验失败显示可重试错误。

切换沿用 `set_cwd`，等待 `useChat` 收到请求确认及目标权威快照后恢复目标工作区的 Wiki 对话；主窗口客户端不变。旧运行实例由既有项目切换生命周期回收，历史保留。成功后同步 URL 的 cwd/doc、窗口恢复记录和最近 Wiki 工作区，保持同一个窗口及 client。新目录优先打开根 README/index.md，否则打开索引中的首篇文档；自动选中文档同样走 `openDocument`，保证 URL、会话和当前文件 chip 一致。没有文档时展开目录树，支持搜索与新建文件。

回归：`tests/wiki-chat-links-desktop-test.mjs` 覆盖跨目录、无效路径、保存失败／重试、中断取消／确认、主窗口隔离、刷新恢复及空目录。

## 保存、关闭与会话引用

`WikiWorkbench` 继续通过 `useWikiAutosave` 在停止输入 800ms 后保存；写入以字节 SHA-256 比较版本，保存确认只更新基线，不覆盖新输入。加载、会话运行及恢复操作期间保持编辑保护，证据快照继续只读。退出与切换文档经过导航守卫：先排空保存，失败则保留现场，可继续编辑、重试或明确放弃。冲突必须先重载或保留自己的版本。

选区「问 pi」捕获点击时的文字与文件路径，保存成功后回调 App，展开右侧 Agent Chat 并追加到Wiki 对话的输入末尾，保留已有草稿和附件、聚焦但不发送，Wiki 视图保持打开；引用操作本身不额外附加整篇文档。保存失败不转移引用。请求带唯一 ID、cwd 和会话 conversationId，App 与 ChatInput 都检查归属，ChatInput 消费 ID 去重；卸载或文档读取序号变化后丢弃迟到结果。工作区或会话变化清除待传引用。

右栏输入框自动显示当前 Wiki 文档的 `@文件名` chip，切换文档时替换，退出 Wiki mode 后恢复普通文件预览上下文。Wiki 独立注册当前文件读取器，避免后台预览覆盖；发送时沿用完整编辑器快照、512 KiB 上限与同路径附件去重，保存成功后读取最新正文和版本。可手动移除 chip，重新打开文档恢复；无文本的媒体不产生 chip。选区「问 pi」仍只追加选中文字，整篇文档是否携带由当前文件 chip 决定。

右栏发送通过 `ChatInput.beforeSend` 排空 Wiki 保存队列；冲突或失败时不发送且保留聊天草稿。保存完成后再次检查打开请求 token、cwd 与 conversationId，关闭或导航后的迟到操作不发送。模型设置入口先经过文档关闭保护再打开设置。

`WikiDocumentModal`（现仅数据库弹窗使用）使用原生模态 dialog，让后台界面 inert 并约束焦点，关闭恢复原焦点且不滚动背景。编辑器的浮动工具条与嵌套弹窗 portal 挂入文档 dialog，Escape 优先关闭内部菜单、搜索及确认框。Wiki 全屏对 `document.documentElement` 调用 Fullscreen API，视图同时铺满视口；Electron 会把全屏页面画在已打开的 dialog 之上（#89），全屏时保留滚动、焦点与选区；退出全屏监听 `fullscreenchange` 恢复原尺寸，退出 Wiki mode 时退出由它进入的全屏。退出前先等待进入请求完成；桌面版还要等 macOS 全屏动画结束（主进程在 `enter-html-full-screen` 到 `enter-full-screen` 之间发布 `fullscreenSettling`），动画中途退出会让页面停在全屏且退出请求永不返回。请求被拒绝时只做窗口内铺满。全程只改变尺寸，保留编辑器实例、草稿与光标。Electron 主进程同步 `enter/leave-html-full-screen` 窗口状态。回归：`tests/wiki-fullscreen-electron-test.mjs`。同项目同文档的滚动位置保存在最多 100 项的内存缓存中，重新打开时恢复。

## 阅读交互

正文默认直接编辑，统一 40px 顶部工具栏、选区“问 pi”和源码切换。标准正文内容最宽 760px，宽版内容 1000px（均不含响应式内边距）；标题与正文使用系统无衬线字体，代码 JetBrains Mono，最新尺寸与配色见 `ui-design.md` 的语雀桌面参考。元信息保留更新时间、阅读时间和标签，frontmatter、重复 H1 及开头属性表隐藏于正文但保存时保留原文。

正文图片与直接打开的图片文件点击进入全屏查看器（`WikiImageZoom`）：默认适应窗口，按钮／滚轮以 1.25 倍步进缩放（5%–800%），百分比按钮重置为适应窗口，拖动平移，Escape／点击空白／✕ 关闭；只读查看，不写回文档。宽屏下正文与右侧大纲作为一个组合排在 `.wiki-scroll` 内，大纲贴着正文而不是贴住窗口右缘；组合从阅读区左侧开始排列，保留正文内边距，正文伸展填满可用空间，大纲靠右，不再留下空白列，全屏时目录树与正文保持稳定距离。宽版（↔）模式隐藏文件栏，组合恢复居中。回归：`tests/wiki-image-zoom-test.mjs`。

隐藏根目录分组、文件栏拖动宽度、目录树按需加载、双链和索引详情沿用已有行为。搜索支持 Cmd/Ctrl+P（兼容 Cmd/Ctrl+K），Cmd/Ctrl+Enter 把命中路径与片段按保存后的引用流程送回聊天。右栏默认显示目录，切换文档和刷新保留助手展开选择；点击「问 pi」、文件引用或选区提问时展开助手；它是当前Wiki 对话的完整聊天能力（附件、斜杠命令、模型选择），不显示底部输入胶囊或「对话 | Wiki」切换。

### 编辑与阅读回归（#109–112）

标题末尾按 Enter 回到普通段落；Shift+Enter 保留标题内换行。正文与 H1/H2/H3 使用各自字号。表格左上角选择手柄使用原生选区，选中后单元格整体高亮，不显示操作浮栏；选中后可按 Delete／Backspace 删除整表，保存走原有自动保存路径。表头和内容默认居中，Markdown 显式列对齐优先，列之间显示分隔线。

## 文件与索引

OKF 扩展已移除；此前导出的知识目录中，带有效知识 manifest 的 evidence 副本仍排除后台索引与撤销快照并保持只读，显式打开保留；明确相对文件链接不依赖索引命中。

文件栏使用与普通文件树一致的顶部搜索、32px 行高、18px 缩进与线框图标；悬停／聚焦的浅黄色链接按钮把文件或目录以 reference 附加到右侧Wiki 对话，不自动发送或打开目录。文件栏提供带文字的「新建文件」按钮，默认填入当前文档的父目录；与普通文件树共用创建表单和独占创建接口，详见 [附件与文件处理](architecture-attachments.md#手动新建文件)。创建成功后经过自动保存导航保护打开新文件。

`wiki-service.ts` 负责工作区索引、文档读取、搜索和文件历史；`wiki-links.ts` 定义标签与链接解析。HTTP 类型只在 `server/protocol.ts` 声明，经现有 type-only shim 供浏览器使用。

正文使用 `document-content`：仅校验目标真实路径，读取文件和元数据、SHA-256 版本，返回 `WikiDocumentContent`，不等待索引。引用使用独立 `document-references`（`WikiDocumentReferences`）；索引缓存各文件已解析链接及反向引用表，后台引用只更新链接，不覆盖编辑草稿。引用尚未返回时显示加载状态，不显示 0 篇。原 `document` 完整接口保持兼容。只读 HTTP 查询允许同项目原生会话切换；项目变化拒绝旧结果，写入/发送仍校验当前会话。正文响应由组件存活状态和读取序号丢弃迟到结果。

- Markdown / txt 默认在渲染预览中直接编辑，复用 `RichMarkdownEditor` 的格式栏、斜杠插入、截图粘贴及段落原文保真。frontmatter、重复 H1 与已识别的开头连续字段/值属性在正文中隐藏但保存时保留；属性在元信息下以可折叠表格展示，由 `wiki-properties.ts` 返回源文范围，正文其他位置不提取；双链、目录及代码配色继续可用。Markdown 提供源码/富文本切换；代码编辑共用保存机制，保存、冲突、发送前保存及导航保护沿用同一路径；运行和加载期间只读，自动保存期间仍可编辑。源码模式使用现有 `CodeFileEditor`。代码默认只读，可显式点击「编辑源码」手工编辑。保存只接受未截断的 UTF-8 文本，并比较原始字节 SHA-256。write 返回轻量 WikiDocumentContent，不等待引用索引；保存后后台刷新索引，点击发送立即显示「发送中」，失败保留输入。
- 目录：插入工具栏和斜杠菜单的「插入目录」（`/ml`）在标题下方插入一次 `<!-- toc -->` … `<!-- /toc -->` 块，已有则只滚动到它。块内列表由 `markdown-toc.ts` 根据块之后的顶层 H1–H3 生成，锚点与 GitHub 一致（重复标题按全文编号）。富文本编辑器把标记区间作为一个只读块渲染为可点击目录（点击滚动到编辑器内对应标题，「移除目录」删除整块）；每次编辑序列化时只重写标记之间的内容，其余字节不变。仅打开文件不会写入：过期目录在界面上按当前标题显示，下一次编辑时才写回。源码模式与 pi 直接改文件时不自动更新，回到富文本编辑后再生成。
- 标签读取 YAML 风格 `tags: [a, b]`、逐行列表与正文 `#标签`。通过 Markdown 语法树排除围栏、行内代码、缩进代码及链接地址；3/4/6/8 位十六进制颜色值不计为标签。解析结果用于索引元数据和标题下的 #标签；不提供标签筛选或 `#` 候选，原文件内容不变。
- `[[文件名]]`、`[[路径|显示名]]` 优先解析同目录、再解析工作区相对路径，最后只接受唯一的同名文件。重复文件名必须写明路径。Markdown 相对链接与行内代码文件路径也参与引用索引。反向链接包含来源路径和引用句子；每次展示 100 条，可继续加载，避免大型引用表阻塞正文交互。
- 文件树包含文档、代码、媒体和其他文件类型，依赖目录与 `.git` 等基础噪声目录除外；目录按需分页读取（每页 500 条），树行按可见窗口挂载。空目录保留。目录符号链接不递归建立索引，可以手动展开；读取必须通过真实路径边界检查。
- 搜索匹配文件路径与文本内容，结果按文档 / 代码 / PDF / 其他分组；支持方向键、Enter 打开、Cmd/Ctrl+Enter 引用给 pi。
- 后台索引和任务撤销快照跳过 `.claude/worktrees` 重复检出、`.venv`、`__pycache__`、`.pytest_cache`、`.mypy_cache`、`.ruff_cache` 目录，不让它们占用主项目预算；显式目录浏览与文件打开仍可用，`.claude/skills` 等上下文保留，直接打开某个 worktree 作为项目时仍正常索引其正文。索引最大 20,000 项、深度 32、文本单文件 2 MiB、总读取量 64 MiB。`WikiState.index` 返回已读取文件数、已发现文件总数、受限路径/字节数/原因；底栏入口打开详情，不再常驻顶部黄条。底栏只显示已索引/总数与跳过数量（千分位、黄色），原因置于悬停和详情，详情按原因分别计数。因项数、深度或目录权限中止扫描时标记 `totalIsLowerBound`，总数位置显示「统计中」，列出未扫描目录；没有扫描的后代不伪造数量。二进制文件仍按文件名索引，PDF 文本按搜索时提取；搜索最多返回 100 项。索引缓存约 30 秒，同一项目并发扫描合并；有缓存时立即返回并后台更新。进入/切换 Wiki 不强制扫描，手动刷新、保存和撤销会失效更新；任务前后撤销快照独立遍历最新文件并读取字节，不等待索引，也不解析 Markdown 元数据或引用。仅可见的 Wiki 轮询，普通周期 30 秒，任务运行及历史收尾期间缩短为 1 秒。只有文档（`.md`／`.markdown`／`.txt`）解析标签、标题和引用，代码文件只按全文与文件名索引；解析结果按内容 SHA-256 缓存，保存或任务后的重建只解析变化的文档。引用解析使用路径集合与文件名表查找，不逐条扫描全部路径。修复前，代码项目在每次保存和任务后都要把全部源文件当 Markdown 解析，并对每个引用遍历全部路径，单次重建可达数分钟并阻塞事件循环，表现为「发送中」和「保存中」长时间不结束。
- PDF 使用 [PDF.js 的 Node API](https://github.com/mozilla/pdf.js/blob/master/examples/node/getinfo.mjs) 提取文字，独立进程最多并行 2 个，每份 8 秒硬超时；每次搜索最多 8 份 PDF，每份 ≤20 MiB、≤200 页。纯扫描 PDF 需要已有文字层，当前不做 OCR。超限、加密或解析失败有结果限制提示。
- 图片与 PDF 走同源、鉴权、cwd 归属与真实路径检查的 `/api/wiki-media`。其他文件在浏览器中下载后打开；Electron 的固定 IPC 经本机服务校验当前工作区后调用系统默认应用。

## 改动记录与恢复

记录保存在 `<dataDir>/wiki/<real-workspace-hash>/`，与项目文件分离。每次 Wiki 提问开始前独立遍历并读取最新文件字节，任务结束后同样读取并比较；手工编辑保存单独记为「我」。新增、修改、删除与二进制改动均可恢复。列表仅提供短预览，展开大文件时读取完整前后版本。

历史按工作区保留最近 100 次有改动的请求，同时按 128 MiB 字节预算清理旧记录及未引用的内容文件。每次快照受 2 MiB 单文件、64 MiB 总量约束，未记录文件明确列出。记录比较请求期间观察到的磁盘版本；同时由外部编辑器或其他会话写入的文件也可能被包含。它不是 Git 事务或跨进程写锁；进程意外退出前未结束的请求不保证有完整撤销记录。

恢复支持整次请求和单个文件：先验证所有目标文件仍等于该记录的预期版本，再恢复原始字节；任一文件有后续修改则整组拒绝，保留现场。本进程写入失败会回滚本次已恢复的文件。撤销后可重做；新建文件的撤销为删除，删除文件的撤销为恢复。撤销不改写 pi 对话历史。

目录蓝点表示有未查看的历史 pi 改动，打开文件清除蓝点。完整的原始前后版本在改动抽屉中。普通聊天任务的改动继续走聊天改动面板，不自动生成旧 Wiki 提问记录。

### 历史导航性能复测（2026-10-05，旧 Wiki 模式，本机 Chrome）

服务预先启动，以正文实际出现且编辑器 `contenteditable=true` 为就绪；会话就绪单独计时。500 文件隔离项目中，切换目标约 98 KB，首次进入、连续切换、返回 Wiki 各 20 次，编辑器 P95 分别为 235 / 338 / 341 ms，会话 P95 为 353 / 401 / 399 ms；正文 HTTP 请求 P95 为 18 ms。人为延迟索引/会话动作 5 秒时，正文仍在 1 秒内可编辑，发送保持禁用，初始化完成后草稿不丢失。

对本机 `blog/docs` 做只读浏览器复测，三种场景各 20 次，编辑器 P95 为 125 / 134 / 159 ms，会话 P95 为 162 / 164 / 205 ms，正文 HTTP P95 为 12 ms；读取文件哈希前后一致。独立服务读取 60 次的正文 P95 为 8.8 ms，包含冷索引的完整接口单次约 5.1 秒。以上是本机结果，不将大于 100 KB 文档或网络文件系统延迟计入 1 秒验收。

大文档单独复测：约 1 MiB 的纯 Markdown，三种场景各 5 次，编辑器 P95 为 727 / 1121 / 1233 ms，正文 HTTP P95 为 84 ms；测试时同时运行其他冒烟检查。当前没有可用的慢速网络文件系统，未测该场景。

### 大量代码块文档（2026-10-09）

Wiki 富文本代码只生成一份可编辑的纯文本 DOM，由 CSS Highlight API 着色；不再先生成高亮 span 再重复解析。进入视口及其前后 400px 的代码块才计算颜色，编辑当前代码仍立即刷新。未变的内容和仍连接的文本节点复用高亮范围；卸载时清理观察器和范围。全文保留在 DOM 中，浏览器搜索、目录跳转、跨块选择和原生撤销保持可用。源码行号按段落累计，避免对每个段落重新扫描全文。

`tests/wiki-large-document-test.mjs` 使用 23,803 行、735,708 字节、200 个 TypeScript 代码块，浏览器 CPU 降速 4 倍。相同本机环境，优化前打开约 12.7 秒、最长任务 7.5 秒；优化后两次打开约 3.1/3.4 秒、最长任务约 2.5/2.7 秒。测试覆盖文末滚动后的颜色、自动保存及未修改块原文保真。该结果为 macOS Chromium 的 CPU 降速测量，不代表 Windows 真机数据，也不保证所有 Markdown 结构达到相同耗时。

### 发送前准备耗时（2026-10-05，本机）

修复前 `blog/docs` 只读复测 `WikiService.begin` 单次 3552 ms，主要耗时为发送前强制重建索引及引用解析。撤销快照独立读取最新字节后，20 次 P95 50 ms、最大 99 ms。该指标不包含原生会话初始化及模型网络响应，未调用模型、未修改用户项目文件。

完整发送链路在隔离的 500 文件项目中验证：点击到原生 prompt 接受，普通 hello 为 85 ms，先保存草稿再发送为 89 ms；模拟模型延迟独立于发送准备。

## 22a 编辑态与自动保存

`use-wiki-autosave.ts` 在停笔 800ms 后保存，Cmd/Ctrl+S、导航及桌面关闭立即保存。写请求串行；每次使用最近确认的磁盘版本，响应只推进基线，不替换当前草稿。排空队列会继续保存等待期间输入的新内容。普通失败显示红点「保存失败 · 重试」，不循环重试；CAS 冲突返回 HTTP 409 / `WikiApiError.code = version_conflict`，保留草稿并显示「文件已在外部修改 · 重新载入 / 保留我的版本」。保留版本先读最新磁盘版本，再进行 CAS 写入，外部再次修改仍会冲突。元信息末尾显示黄点保存中、绿点已保存；顶栏不再有保存按钮或额外未保存文案。

桌面使用固定 `onBeforeClose` 桥等待保存，然后隐藏到托盘或退出；保存失败保留窗口和草稿。浏览器 beforeunload 立即尝试保存并保留原生离开保护，不能保证强制关闭进程或断电时异步请求完成。

Wiki 的 `/` 菜单在文本块开头或空格后触发，排除代码、链接、列表和保护块。中文、英文、拼音及旧别名均可搜索；空格/标点关闭，方向键选择、Enter 插入、Esc 关闭并保留输入。300px 单列、最多 8 行、上下翻转适配光标。顺序为正文、H1–H3、列表、编号、任务、引用、代码、提示、3×3 表格、分隔线、图片和文档链接；右侧显示 Markdown 记法。直接输入 `#`–`######`、列表、引用等前缀加空格转换块，H4–H6 保留这种入口。图片复用安全上传与相对路径保存；`[[` 打开文档搜索，普通链接支持 URL 输入。

选区浮条位于选区上方，空间不足时放下方，提供粗体、斜体、H2、H3、链接、黄/绿背景和问 pi。再次点击同色清除标记；继续使用已有固定色值 mark 序列化和原生撤销栈，已有五色标记可正常读取。撤销/重做只用快捷键，普通文件预览仍保留其格式栏。完整索引成功后隐藏底栏索引项，有未完成/跳过项仍保留详情；状态栏不显示消息计数。

历史 Wiki 提问记录携带 `conversationId`、`requestId` 和 `assistantTimestamp`，Wiki 的最近改动继续读取这些记录与手工保存记录，展开时读取完整 diff；撤销仍按整个请求做版本预检。

回归：`tests/wiki-editing-test.mjs` 覆盖延迟确认期间继续编辑、立即导航保存、失败重试、冲突处理、紧凑菜单、Markdown 简写、选区格式和窄屏；`tests/wiki-desktop-save-test.mjs` 在真实 Electron 验证标题栏连续拖动区、控件 `no-drag`、关闭、退出及失败保留窗口；`tests/wiki-modal-browser-test.mjs` 验证默认目录、聊天替换及收起恢复目录、覆盖式改动抽屉、保存保护及选区回填。设计稿待定的 AI 续写/总结命令、最近使用分组及问 pi 结果替换流程未加入。

## Wiki 切换协调与发送准入（2026-10-23）

`wiki-coordinator.ts` 集中操作租约与中断等待，`use-wiki-coordinator.ts` 是薄 React adapter；App 的文档/目录/历史切换、退出与 ChatInput 发送共用一个协调实例。先到的操作拥有执行权，后续切换和发送被拒绝，不排队替换。现有 `useWikiAutosave` 继续拥有串行写入、版本冲突与草稿，不把这些规则复制到协调 module。

导航保存失败保留取消／放弃／保存继续；取消释放操作。HTTP 结果同时核对操作租约、工作区和来源/目标对话，不能应用已经失效的结果。目录切换仍等请求确认和权威快照后创建 Wiki 对话。可中断的导航和桌面原生关闭先通过 `chat-context` 核对服务端当前运行状态，并同步权威快照，避免接收回执先于运行快照抵达时误判为空闲。中断等待只接受原对话及原生 sessionId 的就绪权威状态，30 秒超时表示失败，不继续导航；其他对话变为空闲不能满足等待。桌面原生关闭也经过同一准入、保存与中断确认。

发送在保存和接收回执期间占用操作，收到回执后释放，不等模型完成；结果未知保留草稿、不自动重发。普通聊天与 Wiki 共用持久回执，详见 [核心架构](architecture-core.md#发送回执协议-v44)。浏览器自身的强制关闭无法运行异步中断确认，应用内退出和桌面原生关闭使用上述协调流程。

验证入口：`wiki-coordinator.test.ts` 控制时间与权威状态；`wiki-modal-browser-test.mjs` 覆盖保存/放弃、中断、延迟导航时的重复操作和发送隔离；桌面接线由 `wiki-assistant-window-test.mjs` 覆盖。

### 服务端 Wiki 对话生命周期 module（2026-10-23）

`server/wiki-conversations.ts` 的 `WikiConversations.execute` 统一处理文档绑定、历史列出／恢复／新建／重命名／删除、引用与当前对话读取。`AgentService` 持有唯一实例，`wiki-routes.ts` 负责 HTTP 校验与响应；项目目录选择校验仍在路由中。module 内部按真实工作区目录拒绝重叠操作（包括兼容的 `new-conversation`），集中跨客户端占用检查、历史选择、SDK manager 打开和元信息更新顺序。

运行实例通过 `WikiConversationClient` 内部 seam 使用现有 ClientSession；不复制 SDK 状态、不新增运行队列。ClientSession 继续拥有实际运行实例的创建／切换／回收及空白文档缓存，WikiChatStore 继续拥有受限路径和原生持久历史。已连接或仍有运行任务／终端的另一个客户端不能被抢占；断开且空闲的旧客户端先释放，再恢复其历史。

异步查找或释放后重新校验客户端、工作区、来源会话、quiesce 与运行状态；切换失败不更新文档绑定，删除前须成功离开活动会话并回收目标运行实例。此顺序不声称 SDK 与磁盘之间存在事务；与前端 WikiCoordinator 的操作租约及发送回执保持独立。

回归：`tests/unit/wiki-conversations.test.ts` 使用真实临时目录和 SDK SessionManager、受控运行实例 adapter，覆盖文档恢复、占用、并发准入、迟到操作、替换／回收失败和删除保护；`wiki-assistant-test.mjs`、`wiki-media-preview-test.mjs`、`wiki-protocol-test.mjs` 验证真实接线。
