# Subagents：按任务分派的只读调查

修改任务分派、多来源读取、执行记录、取消、协议或任务列表／抽屉时阅读本文。

## 任务边界

内置 `subagent` 默认开启，由父模型通过原生扩展工具决定是否调用。简单已知文件问题、常识或已有证据支持的追问可以直接回答，不由宿主强制委派。子代理使用父会话相同模型、thinking 和 ModelRuntime，独立上下文并产生额外用量。它们不能修改代码、执行 shell、加载任意扩展或继续派发子代理。

`action=sources` 获取当前 Workspace 仓库及配置知识库；歧义 Workspace 必须显式选择。`action=inspect` 对最多八个指定来源返回有界本地简介，不启动模型。`action=run` 接收显式 tasks，每项为 `title`、`task`、`sourceIds`。任务是运行与界面的核心身份，同仓可以有多个任务，一个任务可读取最多八个指定来源。只合并任务内重复的 sourceIds，不合并同仓任务，也不默认遍历整个 Workspace；用户要求完整覆盖时由父模型安排显式任务。

旧 `tasks[].sourceId` 兼容为单来源任务；旧 question-only 调用兼容为一个多来源任务，超过八个来源要求显式拆分，不静默裁剪。旧 scope=selected 必须有 tasks。原有 remainingSourceIds 兼容字段为空，不再承担自动分页。

每批最多八个任务，批内并发三、服务级并发六、等待槽最多二十四。每父请求保留 `max(12, 来源数 + 4)` 个 child 预算，每 child 最多三十二次工具启动、十六轮，服务排队最多一百八十秒，取得槽位后另计一百八十秒合作式执行超时。父模型等待本批结果后再综合回答；不引入后台执行或整任务自动重跑。仅单次模型请求的瞬时错误使用下述有界重试。

## 多来源工具与证据

`planning.ts` 校验所选来源属于当前授权来源清单。`runner.ts` 创建独立 pi 子会话，不加载父 transcript、上下文文件、技能、扩展或原生文件／命令工具。子会话只获得 source_list、source_search、source_read、source_report。

前三个工具接受 sourceId。多个来源时必填；只有一个来源时可省略。每个来源使用独立受限读取器，保持 canonical root、inode/device、相对路径、符号链接和生成目录检查；不允许访问任意绝对路径。文件最多 1 MiB，单工具输出 24 KiB，读取三百行、列表二百项、搜索一百项且五秒上限。不是操作系统沙箱，不提供恶意并发目录替换的内核级隔离。

报告在一个任务内汇总多个来源。证据 ID 绑定来源根身份、路径和文件指纹；服务端从实际读过的证据推导 citation.sourceId，模型不能自行声称来源。引用需覆盖实际返回的完整行，并在提交时向对应来源回读指纹。相同文件名在不同仓库不冲突；来源或文件变化使核验失败。每任务最多八条 finding、每条三个引用、每引用一百行，报告总量 24 KiB。

findings 区分 implementation、documentation、inference；connections 和 openQuestions 保留缺口。checked 只表示引用原文及指纹核验，不证明结论正确。没有有效结构化报告的自由文本仍标 unverified，不为补报告追加模型请求。

新任务必须成功执行至少一次 source_list/search/read 才能完成。纯文本、仅提交报告、全部调查工具失败标 failed，保留有界原始回答和原因；不通过编造步骤或强制无意义读取凑数。

## 任务生命周期与记录

`tasks.ts` 为每次尝试生成 taskId，绑定原生 sessionId、父 toolCallId 和用户 turnId。每任务独立 AbortController；排队可取消，运行中进入 stopping，SDK 实际结束后进入 cancelled。停止一个任务不影响兄弟任务；父取消和 session shutdown 取消所属任务。最终状态以原生 agent_settled 和 prompt promise 为准，清理监听、定时器、slot 和会话。

原生 source 工具开始／结束自动产生步骤，包含工具 ID、工具名、sourceId、目标、状态及实测耗时。执行记录另保存工具参数、工具输出和公开回答，不采集内部思考。每任务最多 2 MiB，事件部分最多 1.5 MiB／128 条，每事件文本最多 24 KiB；超限标截断，继续保存状态、步骤和最终结果。结果文本每任务最多 12000 字符。

记录在 `<dataDir>/subagent-tasks/<session hash>/<taskId>.json`，配套轻量 summary 文件。按任务串行原子写入，目录／文件权限分别为 0700／0600。最终结果保留在原生 tool details，父模型紧凑 JSON 总预算仍为 60 KiB；裁剪父模型文本不删除独立执行记录。存储失败通过结果警告说明。

会话加载恢复轻量摘要，未终结且没有活动运行的任务显示中断失败，不自动恢复模型。详情读取可将孤立记录固化为中断结果。旧 transcript 不改写，旧记录缺少步骤时只显示说明，不伪造过程。

## 协议与授权

协议 v49。`UiSubagentProgress` 增加可选 taskId/title/sources/startedAt/durationMs，以及 stopping 状态。最终工具消息的 subagents 是有界白名单元数据，不透传任意 native details。`UiState.subagentTasks` 仅提供当前分支活动／中断任务摘要，用于重连与刷新；最终报告继续从原生工具结果恢复。

`subagent_request` 包含 requestId、conversationId、taskId、action=detail|stop 以及可选 cursor。`subagent_response` 返回同一请求归属、detail 或 error。请求先验证该任务属于当前客户端可访问会话及当前分支工具调用。停止不是新的父模型请求。详情每页最多五十个事件，结果按需传输；全量工具输出不进入聊天快照。

## 前端

同一真实用户轮次的所有 action=run 汇聚为一个任务列表，跨助手正文保留聚合；不同轮次、会话、分支隔离。自动提醒不拆轮，sources／inspect 保留通用卡片。稳定 taskId 标识新记录，旧记录按父调用 ID 与任务序号适配。

统一列表替代旧单／多报告及跨调用分组布局。每行显示任务、来源、当前动作、状态和实测耗时。运行或含成功项默认展开，全部未成功默认收起，用户手动展开选择优先。未成功尝试在底部默认折叠，全部失败时给出简短说明；错误不充当结论。无法解析的历史数据保留通用原始输出入口。

点击任务打开右侧覆盖抽屉，窄屏全屏。首次打开运行任务选“执行过程”，终结任务选“结果”；更新不强制换页签。过程显示真实步骤，参数与输出可展开；仅在用户处于底部时跟随新记录。结果显示回答、发现、带来源的引用、证据边界、问题及用量。停止独立任务；准备重试保留所有选定来源并追加到当前草稿，由用户发送新尝试，不删除旧记录。

抽屉按需分页读取，运行时定期拉取，关闭释放监听与定时器；支持 Escape、焦点约束和返回触发行。工具定位直接打开对应任务。切换会话关闭旧抽屉。

## 配置与验证

`<dataDir>/subagents.json` 的全局 enabled 默认 true。原生 defaultTools 过滤优先；关闭后新调用被拒绝，已有运行由原取消信号管理；重新启用后会话需要重载或新建以曝光工具。设置版本校验与其他内置扩展一致。主模型仍需核实业务语义；模拟模型测试验证执行契约，不代表真实模型研究质量。

## 任务恢复与结果判定（2026-11-07）

最终结果保留 `taskIndex`，重试在原父调用内还原对应任务参数和所有来源，不使用裁剪摘要。同来源多任务按序号区分；旧记录只接受唯一映射。省略 question 的调用从按需详情的完整指令恢复隐含用户背景，无法确认时说明原因，不准备不完整重试。完整指令仍只在独立记录和按需详情中传输，不扩大聊天快照。

父工具最终结果的状态优先；尚无父结果时采用详情终态，列表和抽屉共用合并规则，已结束任务／步骤不退回运行中。详情读取错误只影响记录加载，不丢失现有报告、状态或所选页签。详情加载与任务状态独立：运行记录每秒读取，终态首次读取也有十秒超时；超时提示并自动补发一次，再失败则等待手动重试。完整快照确认连接恢复后从原事件游标续读，事件按 seq 去重、过期响应忽略，关闭／切换会话释放请求。停止和详情各有请求身份，停止不自动补发。

`truncated` 标记模型以 length 停止；已成功提交有效报告且有成功调查步骤时仍为 completed，常显总结截断提醒；没有有效报告时 failed 并保留部分回答和过程，不自动续写。`outputTruncated` 单独标记宿主显示／父输出裁剪，不改变研究结果状态。旧历史标记保持原样。

服务槽位排队和实际执行分别最多 180 秒，排队失败明确尚未开始调查，durationMs 只计取得槽位后的时间（未开始为 0）。批内三、服务六、二十四等待槽不变。coverage.attemptedSourceIds 为每项任务全部选定来源的去重集合，并不表示每个来源都成功完成研究。

当前记录缺失时，只有 detail 可以沿原生 parentSession 链只读追溯，最多 32 层，检测路径及 session ID 循环。当前持久分支必须含精确 taskId 与父 toolCallId 的终态结果；每级祖先也校验该结果自身分支及记录 sessionId、taskId 和终态。祖先通过内存 SessionManager 解析，不打开可迁移／写入的文件管理器，不复制记录、不修复祖先孤立运行记录。stop 永不回退祖先；删除或不匹配只提示详情不可用，聊天报告仍保留。

## 单请求容错（issue #164）

子会话开启原生 SDK 请求重试，最多两次，退避为 1 秒、2 秒；provider 内部重试关闭，避免叠加。网络／临时服务错误沿用 SDK 分类，认证、额度等永久错误不重试。`request-recovery.ts` 仅将没有宿主或 SDK 取消信号的 AbortError／aborted 响应归为可重试的请求中断，不推断网关或连接的具体来源，不修改 SDK。

重试在同一子会话中继续失败的模型请求，保留已完成工具结果及证据；原生历史保留失败尝试，用量包含所有尝试。runner 只在最终 settle 后判定请求错误，单次错误不触发任务级 abort。重试仍受原 180 秒执行时限、16 轮和 32 次工具预算约束；父取消、独立停止、超时或预算耗尽不重试，退避可立即取消。重试次数与退避原因记入执行记录。

最终失败／取消时保留已有核验报告，状态仍为未完成。父结果附带原因、实测耗时、最后活动、重试数、已完成步骤、最近公开回答（最多 2000 字符）和成功工具输出摘录（每项最多 2000、合计 6000 字符），总结果仍不超过 12000 字符；裁剪标 outputTruncated，不包含内部思考，不把摘录当作已核验结论。完整工具过程仍由独立执行记录保留。

回归：`tests/unit/subagent-retry.test.ts` 使用真实 SDK 会话与确定性模拟模型流，覆盖读取后中断恢复、异常抛出、aborted 响应、重试耗尽、已完成证据保留、用量、永久错误及退避取消。
