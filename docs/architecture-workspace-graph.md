# Workspace 图谱

用户在主窗口选择一个已登记的 Workspace，打开「图谱」并建立索引。左栏选择来源、搜索或返回概览，中间查看仓库关系和模块，右栏查看一条关系的证据。打开源码证据会再次核对文件。选择分组沿用窗口内的 Workspace 选择，聊天 cwd 保持独立。

## 同一份图的入口

页面通过 `POST /api/workspace-graph` 提交 `workspaceId` 和 `request`。服务在本机运行。页面上的构建、更新、检索、影响分析与证据核对不需要模型。普通对话通过两个显式 Skill 启动相同作业，短命令为 `/build-graph` 和 `/update-graph`。管理操作覆盖整个 Workspace。命令可不带参数，也可填写当前项目所属分组的完整唯一名称或 ID；其他参数会在启动模型与作业前被拒绝。用户通过 `/ask --graph 问题` 临时开放状态、搜索、邻居和路径工具，最终引用仍由本次请求回读源码生成。项目同名 Skill 的优先级以及 Wiki、SSH 和 Playground 的隔离规则继续生效。

`WorkspaceGraphService` 负责范围、版本和发布。查询接口的节点、边和证据类型在 `server/protocol.ts` 中定义，图数据按需读取，不放入聊天快照。每个来源沿用 Knowledge Engine 的稳定标识。索引器的后台 worker 单独处理受支持文件，更新时允许查询此前发布且仍能核验的仓内结果。

| 状态 | 可查询的数据 |
| --- | --- |
| 未构建、首次构建中 | 尚无已发布数据，Ask 继续查源码 |
| 就绪 | 当前来源指纹与发布记录一致的节点和关系 |
| 过期、更新中 | 已重新核验的来源。受变更影响的仓内关系暂时不可用 |
| 失败 | 上次成功版本仍可查，仅返回当前可核验的部分，并保留失败原因 |

本地 SQLite 位于 `<dataDir>/graph/catalog.db`。同一来源和内容指纹的仓内节点、导入边仅保存一次。Workspace 发布记录保存成员指纹及跨仓关系。单个事务同时发布仓内产物和新版本。各进程用同一 Workspace 的作业租约合并并发请求，失效租约不能发布。来源内容或成员变化会终止版本发布。无变化的增量更新保留版本号。已有基线的显式重建会重新计算并替换派生产物。关闭聊天和切换页签不会撤销作业。

查询只扫描该请求可见的登记来源。返回跨仓关系前保守核对完整成员集合及各自指纹，覆盖中间仓的类型声明、导出和配置依赖。缩小来源范围时，仓内导入关系仍可独立使用。不完整路径和脱离当前工作区的旧节点不能用作证据。查询有界；截断标记表示仍有未返回的结果。

## 已支持的关系与限制

首版扫描 TypeScript 源文件、TSX、MTS、CTS 及相关包声明和 TypeScript 配置。仓内模块显示可解析的相对导入和重导出。跨仓包关系核对精确依赖版本、唯一目标包、公开入口及源码中的具名或默认导入，提供源模块到目标模块的边和仓库级概览。同名歧义、未公开子路径和无法映射到源码的入口不会生成这类边。跨仓事件规则检查带判别值的对象、生产者、监听器集合、订阅注册、接收者类型、回调传参及状态写入。其中每个公开锚点携带来源、相对路径、行范围和文件字节 SHA-256。规则只描述源码可支持的结构路径。部署、实际订阅实例和某次请求的运行情况应从 Trace 或运行日志核实。

图谱按文件清单及内容指纹判断变化，包括未提交修改、增加、删除和重命名。跨源解析在同一组可见类型中重新绑定。首次版本对单文件设置 1 MiB 限额，对一份扫描设置 8,000 文件、64 MiB 限额，重型 worker 单次最长 120 秒。隐藏目录、依赖、生成目录、凭据、符号链接和 ignore 规则排除的文件不参与。超过预算或解析失败会报告失败并保留上一成功版本。

影响分析从所选节点沿导入关系反查使用者，并沿已识别的事件流正向查消费者。每条边保留原方向和证据。Engineering 与 Ask 可以用这些线索定位应当复核的改动范围。未解析的语言、动态分派及条件控制流会限制覆盖。

## Wiki 引用质量

在图谱页显式给出当前知识库内一篇 Markdown 文档的相对路径，可以检查 Learn 保存的来源记录。当前库、Workspace 成员、原文指纹和行范围共同决定结果。有效引用可跳转到已有图谱模块。已变的文件显示过期，缺少可用依据显示未验证，来源撤销或文件不可读显示不可用。每次最多检查 32 项、64 KiB 文档头和累计 8 MiB 来源正文。检查不会改写文档或调用 Reflect。`verified` 表示该引用仍指向相同源码与行范围，文档中的业务结论需要单独判读。

## 引擎验证

M2 在预先标注的双仓样本上比较 Graphify、GitNexus 和轻量 TypeScript 解析器。三者都能定位五个关键方法。两项外部候选的原生关系均缺少这道题的订阅桥。共用的源码规则能验证 SDK 会话通道的 1150 行到宿主状态写入的路径，并排除相邻的扩展派发。选用本地 TypeScript 规则后，完整的两个固定源码标签也能找到这条路径。其他语言、框架及 RPC 与队列契约需分别增加样本和规则。[M2 样本和复现步骤](../dev/graph-eval/README.md)

M5 在同一公开问题上使用六个独立会话比较普通 Ask 和图谱增强 Ask，图谱组的耗时与可点击引用覆盖未出现稳定收益。默认 Ask 保留源码检索，可按需使用 `--graph`。[A/B/C 实验结果](../dev/graph-eval/ask-results.md)
