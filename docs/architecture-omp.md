## 已实现：Node → Bun → OMP SDK

依赖精确锁定 OMP 18.20.0、Bun 1.4.4。`server/omp/runtime.ts` 从安装包解析 Bun 可执行文件，启动编译后的 worker；开发态可运行 TypeScript worker。不查找全局 omp/bun，不在启动时下载。

每个运行会话一个 Bun 进程，SDK 的进程级状态不跨顶层会话共享。启动环境覆盖原生 agent 目录、剥离继承的 Pi/OMP profile/session 选择器及 `ELECTRON_RUN_AS_NODE`。初始化参数放在子进程环境，worker 读取后移除；凭据不放命令行参数。历史按会话类型和工作目录哈希隔离，恢复路径经过真实路径校验，不能越出该目录。

worker 使用公开 `createAgentSession`、`SessionManager` 和 `runRpcMode`。RPC 接收 OMP 自己的队列、分支、取消、扩展 UI、工具及子代理事件；原生 `session_settled` 区别于 `agent_end`。普通配置使用原生默认工具；受限配置关闭文件/命令工具、上下文、技能、MCP、扩展和模型回退，只允许明确声明的业务工具。

启动握手校验 bridge v1、OMP 和 Bun 版本，随后协商原生 RPC v2，默认开启 delta 和子代理事件；产品会话层目前选择 full 消息更新，并在宿主投影为有界 UI 消息。Node 端不加载 SDK。物理帧最多 1 MiB，v2 base64 分片最多重组 64 MiB，校验顺序、长度、编码和嵌套分片；默认 30 秒请求确认超时表示执行结果未知，不能据此重发。compact/navigate_tree 的原生回复代表执行完成，等待期间不套用准入超时，仍可取消或停止所属进程。进程事件带会话、代数和本地序号。stdout 是协议，console 走 stderr；当前宿主丢弃原始 stderr，避免暴露上游凭据。

`OmpHostTools` 将原生 host-tool 事件接到显式业务处理器。处理器负责参数、授权及数据校验；桥只接受所属会话/代数，去重调用，转发取消，并抑制已取消或已关闭调用的晚到结果。结果上限 1 MiB，原始异常不发给模型。Playground 的 propose_playground_code 已迁移为 host tool，显式校验所属会话、取消信号、参数及本轮代码基准。主聊天的 database_read 已接入现有只读连接授权；SSH 三个远端工具已迁移为 host tools，保留逐次确认与连接归属校验。

产品 Stop 先通过独立 worker 控制路径撤回队列、取消原生压缩／重试／分支摘要，让被串行摘要阻塞的 abort 命令得以处理；不重新提交用户输入。原生清理最多等待 5 秒，扩展钩子卡住时也进入所属进程关闭流程，不伪造 RPC 取消确认。关闭传输先结束输入让 OMP dispose，5 秒后 SIGTERM 触发 worker 的 dispose，10 秒后对本次启动的进程树强制清理。`stopOmpRuntime` 先撤回待发并中止，再释放整个进程及其原生后台工作；调用方保留 sessionFile，在用户下一次显式发送时才能打开新代数。已验证后台 bash 停止后重开无待执行任务、无自动请求。该入口已接入主聊天与 Playground 停止按钮；原生 task 多层任务树仍需补充验证，不能仅复用原生 abort 命令。

## 产品会话层与首个调用方

`server/omp/session.ts` 管理原生进程、工具注册准入、模型目录、消息投影、停止和显式恢复。`presentation.ts` 只允许展示字段通过，不转发模型 headers、密钥和任意 SDK 元数据；模型历史仍由 OMP 保存，UI 投影不回写 transcript。容量判断使用未截断原生历史字节数。业务会话采用 OMP Settings overlay，模型与思考切换不写全局 config.yml。

## 队列撤回

主聊天和 Wiki 的 `recall_queue` 调用 OMP 公开 `clearQueue()`，只撤回尚未消费的用户输入，不中断当前回复；完整文本和原生图片返回既有草稿保护流程。OMP 可能在入队时转码图片，恢复的是原生队列中的表示。worker 在清理前检查待发内容总量，超过 16 MiB 拒绝撤回，不截断或丢弃内容。

发送准入与撤回按会话串行，防止清队列越过尚未确认的 steer/follow-up。Stop 使尚未开始的准入失效，不允许其随后重新打开进程。原生 `queue_update` 驱动显示；已 live-steered 的前缀不再属于可撤回队列，快照预览每项最多 2000 字符，完整内容仍由 OMP 保存。

服务端只保留撤回交付回执，不维护另一套可执行队列。每客户端最多 8 个未确认请求，同一 requestId 的并发请求只撤回一次；未确认结果在重连时重放，只有所属对话的确认才能移除。最近 256 个已确认 ID 作为去重记录；结果不明的请求不自动重做。这个保证限于宿主进程生命周期，服务重启不自动恢复队列或重放任务。

真实入口回归覆盖重复文本和图片、重连重放、重复请求不清新输入、后台对话隔离及撤回后继续；运行时回归覆盖 Stop 取消待准入输入。恢复阶段见下节；分支摘要仍待单独接入。

## 压缩、重试与取消

worker 订阅 OMP 原生压缩/重试事件，按会话生成 operationId；取消在同一 worker 校验当前 ID 后调用 `abortCompaction()` 或 `abortRetry()`，过期或其他会话的 ID 无效。取消走独立控制路径，不排在正在等待完成的压缩请求之后。主界面分别显示手动、阈值、溢出、空闲和不完整响应触发的压缩；跳过、中止、失败与完成保持不同结果。

重试倒计时基于 worker 单调时钟采样为 remainingMs，宿主按耗时更新，不向浏览器暴露绝对时钟或原始供应商错误。异步快照以事件代数避免覆盖更新的状态。autoCompaction/autoRetry 使用原生会话级设置，Stop 后显式重开及 reload 保留同一产品会话的选择，不修改 config.yml，也不扩散到其他对话。

`tests/omp-recovery-test.mjs` 使用真实 SDK、本地 Anthropic 流式夹具验证重试取消、压缩中止/成功、过期 ID、会话隔离及重载/重开后的设置。已加入冒烟与三平台桌面 CI；本机 Node 与 2026-11-15 macOS arm64 目录包均通过。分支摘要的阶段和取消仍需接入，不以压缩回归代替它。

## 会话树写入归属

树写操作与编辑重问持有当前对话操作权，使用捕获的 OMP 会话，阻止期间切换对话、切工作区、新建和重复写入。Stop 使等待步骤失效；待发附件处理结束时也要核对停止代数。读回复保留所属对话 ID；详情只返回白名单内容。原地编辑使用原生 navigate_tree，原分支保留。摘要期间产品仍显示忙碌，Stop 先取消摘要再关闭进程，真实回归要求 5 秒内完成且无自动重发。

`tests/omp-tree-test.mjs` 已验证这些行为。分支摘要独立取消、外部修改检测、完整树元数据和附件草稿恢复仍待实现。

## 配置一致性

模型管理的获取列表、刷新与复制草稿已接入 OMP worker。草稿使用原生 `discoverModelsByProviderType` 解析能力和默认额度，不持久化临时密钥；OpenAI 兼容及 Anthropic 列表走原生 `/models` 发现，Google 列表仅转换公开响应外壳再交给同一原生解析。探测限制响应大小，拒绝重定向，不回传上游错误正文。保存的原生 discovery 配置使用 `refreshDiscoverableProviders`；普通自定义供应商通过原生认证与请求头解析后探测。

刷新与写配置共用跨进程锁，只追加新聊天模型，保留已有行、显式额度、已清空的额度覆盖以及未知原生字段。OMP 的 `kind` 和旧配置的 `type` 均用于区分非聊天条目，聊天表单不覆盖 embedding 等配置。复制使用原生目录的白名单投影，不带凭据或请求头、不自动保存，自动建议未占用 ID；当前表单只有供应商级协议，因此多协议目录延续原有行为，复制模型最多的协议与地址组合，并在通知中显示协议与数量。

`tests/omp-model-catalog-test.mjs` 通过真实 OMP 和本地目录验证请求关联、认证请求头、原生能力与默认值、无认证探测、404 路径回退、响应限额、禁止重定向、失败不写配置、非聊天模型保留、清空额度后刷新不复写、其他空闲 worker 更新以及复制草稿不落盘。此测试也进入三平台桌面 CI 的源码与打包产物验证；本机通过不等于 Windows 已验收。

模型配置写入由各 Bun worker 对同一 models.yml 获取跨进程锁，覆盖读取、合并、原生校验及失败回滚。空闲会话以内容指纹发现配置变化，通过原生 modelRegistry 刷新并重新绑定当前模型，不保存新的全局模型偏好。主聊天、SSH 和 Playground 共用会话层；宿主保存成功后刷新已打开的空闲会话，运行中的任务保持当前配置，到结算或下一次明确发送时同步。已删除或无凭据的模型不会继续发送。

内置供应商密钥使用 OMP `authStorage.credentials` 原生持久化接口；保存前检查已有 OAuth，避免用密钥静默覆盖账号。清除仅移除该供应商的 API-key 行，不删除 OAuth、环境变量或 models.yml 中的认证。界面来源由原生 `keys.source` 投影，只有 stored 来源显示清除按钮。空闲同步同时轮询原生凭据代数，因此不同 worker 及时更新可用模型。

自定义模型的显式密钥仍保存在 models.yml，空白编辑框保留原值。OMP 的自定义模型校验要求认证配置，清除已保存的内置供应商密钥不修改自定义配置，也不将其伪装为无凭据状态。OAuth 登录使用独立受限认证 worker，接原生 login/get_login_providers；登录窗口映射原生 open_url/input，输入按请求与提示 ID 校验且不回显。取消关闭认证 worker，不停止聊天。退出仅移除原生 OAuth 凭据行，保留 API key 和配置覆盖。原生 RPC 不支持的交互登录会返回失败，不伪装成功。真实供应商账号登录仍需验收。

## 原生子任务接入

主界面的任务页投影 OMP `subagent_lifecycle/progress/event` 及 `get_subagents`；只读调查扩展不参与原生 `task`。任务视图包含原生状态、当前工具、耗时和用量。终态生命周期优先于晚到进度。父工具必须仍在当前分支，嵌套任务通过已观察到的子任务工具调用关联；浏览器使用独立随机任务句柄，不能指定原生子会话文件或拿旧进程句柄操作新运行。

协议 v60 的 `omp_task_request` 接收 conversationId/taskId/requestId、detail/stop 和消息游标。详情调用 `get_subagent_messages` 后白名单投影、分页并明确标出显示裁剪，不传 SDK entries、headers 或 sessionFile。停止先核对当前原生 roster 的归属，再调用 `cancel_subagent`；可停止当前客户端所属的后台对话任务，不切换前台，也不自动重发。整个会话停止时，未终结任务标中断；旧任务操作不自动重开 worker。

浏览器详情复用现有覆盖抽屉、焦点约束和 Escape 关闭；执行过程与助手输出分别查看，进行中的记录按需轮询，关闭后释放监听和计时器。停止不自动补发。`tests/omp-tasks-test.mjs` 用真实 OMP 和本地模型夹具验证派发、读取、详情、独立及后台停止、兄弟/父会话隔离、嵌套任务、分支归属和父停止后不复活。`tests/omp-tasks-browser-test.mjs` 使用确定性 wire 数据验证抽屉分页、停止、结果过滤、窄屏、焦点和清理。

历史恢复使用 `task-history.ts`：从当前原生分支的 `task` 工具结果及 `async-result` 元数据恢复目录，通过公开原生 loader、内存迁移和 `SessionEntryIndex` 读取子会话的完整当前分支，关联压缩前的嵌套任务；不扫描废弃分支。详情仍使用 `loadSessionMessagesReadOnly` 的压缩展示。它不创建子会话 writer，不调用 revive 或 prompt，不解析正文中的工具描述。没有可靠终态证据的任务显示中断；初始异步进度中的零计数不当作最终用量。历史任务不提供停止能力，旧 worker 的句柄不能操作新进程。

浏览器仍只发送任务句柄。worker 每次读详情前重新校验当前分支；文件名只从原生任务 ID 和所属父会话派生，拒绝路径分隔符与符号链接，文件状态改变后重新读取。详情使用原生只读 transcript 语义（包含摘要后的展示历史），投影后按页返回，不传原始 entries 或文件路径。当前 worker 已关闭时，旧详情请求仍不会擅自重开进程；用户重新打开会话后才恢复历史目录。

主聊天工具卡按 parentToolCallId 关联任务，Wiki 助手提供折叠的完整任务列表；两处复用任务详情。浮动助手的 portal 与焦点使用所属窗口，关闭/移动/切文档时释放详情，迟到响应不能打开到新会话。OMP 初始快照不再提前开放前端准入，Wiki 恢复等 `ready` 握手后才请求工作区。

压缩前嵌套任务目录与当前分支恢复已通过 `tests/omp-task-compaction-test.mjs`；工具结果完整输出下载见 `tests/omp-task-output-test.mjs`。详情仍有展示裁剪，不能据此推断原始输出丢失。原生 Task 内部 writer 保护、Windows 和当前桌面包验收仍未完成。

## 失败限制跨宿主重启（2026-11-15，协议 v64）

持久化／外部修改失败不再仅保留于 `OmpSession` 内存。原生失败回调先在 `<dataDir>/omp/recovery/<历史路径的 SHA-256>/` 写入独立的私有恢复记录，再通知宿主；目录独立于 transcript 目录，按历史文件而非客户端或当前窗口归属。记录不包含原始路径、消息、工具参数或凭据。宿主构造会话与写入准入、worker 启动分别检查记录；普通打开、模型切换和直接启动 worker 都不能隐式解除限制。

显式重开在旧 worker 完全停止后读取恢复记录集合，作为内部启动确认；新 worker 成功读取历史后，仅删除本次明确确认的记录。每次失败使用独立记录，重开过程中新增的失败不会被旧操作清除。重开失败或被 Stop 取消继续保留限制；成功恢复不自动发送。损坏的恢复记录仍按失败处理。恢复目录本身不可读写时显示专门提示，说明须先修复数据目录，不能承诺此类故障的限制一定跨重启保留。

普通聊天与 Wiki 共用的会话初始化允许显示失败状态而不启动 worker；失败历史缺失时保留原路径和恢复入口，不静默新建空历史。恢复前没有重新加载模型目录，不因此显示未配置模型引导。宿主重启后仅显示恢复提示，消息在明确重开后从原生历史读取；未保存内容无法据此恢复。SSH／Playground 共用的底层会话也拒绝失败历史的隐式写入，其专用恢复交互仍须补齐。

## 请求结构诊断与 SDK／CLI 边界（2026-11-16）

`PI_WEB_MODEL_DIAGNOSTICS_DIR` 在创建 worker 时映射为专用内部环境变量；metadata-only 子进程不启用诊断，外部传入的内部变量先清除。普通会话使用公开 additionalExtensionPaths，受限会话通过 preloadedPreparedExtensions 只绑定同一观察器；无工具、提示词或模型调用注入。文件扩展能由原生 Task 重新绑定及在 CLI 线程中加载。宿主和 provider 文件共享本轮随机 runId；事件内容与标识按白名单和 HMAC 投影，不写响应 headers 或原文。详见 [采集范围与限制](deepseek-windows-validation.md#本地事件与请求诊断)。

OMP 的 workerHostEntry 在 SDK 嵌入模式为 null，这是上游设计；declareWorkerHostEntry 明确禁止嵌入方调用，宿主没有伪造 CLI 身份或私有 dispatch。应用九个同时运行的 Task 子会话由原生 SDK 在进程内执行；真实原生 CLI RPC 对照使用相同本地 provider 和同一观察器，确认有 Task 进入工作线程、所有子会话被记录，最终 prompt_result 为 completed。该事实不覆盖 Task 存储保护或 CLI 线程代理路由。

JSON/print 模式的同一九子任务对照在有／无观察器时都出现 agent_end 后事件循环提前退出、退出码 1；保留 `HARNESS_TEST_OMP_CLI_MODE=print`／`print-control` 诊断分支，不混入通过的 RPC 默认回归，也不修补 SDK。
