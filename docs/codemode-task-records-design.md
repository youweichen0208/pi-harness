# 右栏 Codemode 执行记录

本文件记录 grill-with-docs 讨论并经用户最终确认的产品决策，作为本次实现与验收依据。

## 已确认

- 展示脚本实际发起的内部工具或模型调用，不生成预计待办队列，不把调用解释成目标级任务。
- 展示入口位于右侧任务／步骤区域；聊天里的 Codemode 卡片保留。
- 每次 Codemode 脚本调用作为一组，组内展开实际调用记录，避免循环调用平铺整个右栏。
- Codemode 执行记录独立展示，不归入或移动到计划步骤下。已有计划继续维护自己的进度与状态。
- 内部调用失败记录保留。外层脚本成功结束时，若含失败调用，显示“已完成 · 含失败调用”的含义，不因此判定整个计划失败；具体状态文案遵循已有英文状态偏好。
- 运行中的组默认展开，显示最近 8 条已收到的记录；完成后保持展开状态。用户手动折叠后不自动重开；新记录不强制滚动右栏。提供展开其余已收到记录的入口。
- 每条记录展示工具／模型调用名称、简短参数、状态和已有耗时；点击跳转到聊天中对应的外层 Codemode 卡片。右栏不重复展开完整参数、错误和脚本输出。
- 仅展示当前请求的执行记录，结束后保留至下一条真正的用户请求开始；自动提醒与内部续接不建立新的请求范围。旧记录仍在聊天历史中查看，切换会话或历史分支时从对应记录重建。

## 已核对的数据边界

- 当前原生 Codemode 详情包含调用名称、参数摘要、状态、耗时及部分调用的费用／错误。调用随运行产生，不提供完整的未来执行清单或任务依赖图。
- 当前传输最多包含 256 条详情，另保留实际总数。展示需要明确区分传输省略与界面折叠，不能将局部记录计数冒充完整结果。
- SDK 的运行中调用标识可能暂时重复并在完成时改变；实现不能直接将该标识当作稳定唯一的列表标识。
- 运行中状态可能包含等待内部限流的模型调用，不能据此声称真实并行度。

## 最终核对的边界规则

- 分组放在右栏现有进度／步骤之后、输出文件之前，标题为“Codemode 执行记录”。无 Codemode 调用时不显示该区块。
- 按实际调用的追加顺序展示，不推断串并行依赖或未来任务；内部重试各自保留，不把旧失败改写成成功。
- 有明确取消终态时显示 Cancelled；外层结束但某条记录缺少终态时显示 Unfinished，不再保持转圈，也不推断完成。单纯断线不等于取消或结束，重连后依据权威状态恢复。
- 沿用现有 256 条详情传输上限。默认的最近 8 条指已收到记录的末尾 8 条；超过传输上限时明确提示仍有调用未展示，不称为整个执行的最新 8 条，不根据局部记录声称全部成功。实际调用总数与已收到状态统计分开表达。
- 保留现有聊天卡片布局；为保证定位与实时列表稳定，允许修正重复调用标识造成的列表键问题，以及补充跳转展开的必要接线。
- 仅使用已有调用事件与历史详情，不改变脚本执行、计划状态或模型提示词，不额外调用模型；不升级或修改 Pi SDK。

## 实施与验收

- 在展示层统一整理已完成详情、实时详情和旧历史 nestedCalls 回退，避免同一调用被重复计算；调用身份以外层调用加稳定序号等方式保留，不直接使用运行中可重复的临时 ID。
- 右栏区块独立于计划投影，复用当前请求边界及会话归属；手动展开状态按会话和外层调用隔离，首次加载已完成的历史组默认折叠。
- 覆盖串行、并行、循环、重试、部分失败后外层成功、取消、缺失终态、无内部调用、超过 8/256 条、临时 ID 重复及完成时变化、旧历史回退。
- 浏览器验证实时追加、手动折叠不被打断、完成不自动收起、跳转展开聊天卡片、请求／会话／分支切换、重连恢复、中英文、窄窗口和 Web／Desktop 外壳。
- 使用隔离服务和本地模拟接口，执行类型检查、构建及相关单测，不调用付费模型。本次默认只完成本地实现与验证，不升级版本、推送或发布。

定义见根目录 GLOSSARY.md 的“Codemode 执行记录”。Q1–Q9 及边界规则已经用户确认。

## Review 修复补充（已确认实施）

- 断线状态与原生任务生命周期分离，不能由浏览器 `streaming=false` 推断结束。
- 为修复压缩后当前请求边界丢失，原「不新增协议」约束调整为允许协议 v52 的只读展示字段：快照携带持久分支的本轮元数据及最新运行详情，历史详情通过现有树读取通道按需获取；不改模型协议、上下文或 SDK。
- 原生持久分支是请求范围事实源，不依赖 plan；压缩、刷新及分支恢复不会清空本轮记录。目标已不在聊天上下文中时，使用只读 Codemode 弹窗查看，不切分支。
