## 统一空状态：网格纸标语

主聊天与问 pi 的空状态共用英文标语“There are many agent harnesses / but this one is yours”：无装饰背景、深灰衬线斜体、蓝色 yours。主聊天的品牌图标和标语作为整体，在顶栏与输入框之间水平、垂直居中；图标下方仅显示标语，不显示网格背景、目录和快捷提问；问 pi 移除标语下的文档／追加项目文字区，项目选择统一从上方模式菜单进入；当前文档保留输入框引用 chip。浮窗默认尺寸 375 × 820px（与参考图 750 × 1640 的比例一致，可手动缩放），输入框空白时为单行高度，长输入最多增长到 120px；欢迎区占据输入框上方空间，避免覆盖输入框；窗口标题和正文不使用此装饰字体。窄面板允许自然换行，深色主题使用对应令牌。

## 问 pi：文档会话与项目分析范围

每篇 Markdown 恢复自己的 chat，切换文档清除所选 Workspace 项目，不恢复上次的追加范围。空状态用实际模型名称与「文档问答／结合知识库」胶囊，以及「根据 当前文档」「添加项目／知识库」「进行分析」排版；不显示旧说明和三个建议按钮。项目选择器按已有 Workspace 分组展示项目目录，也可返回仅文档。当前文档引用固定，额外项目选择显示可移除 chip，发送时按需读取并要求引用来源，不预加载整个项目。历史只列出当前文档的对话。

## Desktop 问 pi 独立浮窗

桌面打开问 pi 时，浮动模式使用独立无边框窗口，可拖动标题栏跨屏移动并用系统窗口边缘缩放；固定按钮移回 Wiki 右栏。关闭浮窗只收起助手，保留对话、草稿与引用。Web 继续使用页面内浮动。浮窗沿用当前主题、字体和浅灰表面。

## 1. 设计令牌

所有颜色和圆角只能通过 CSS 变量使用，组件里不写十六进制颜色（终端 ANSI 调色板和第三方渲染器配置除外，见 1.4）。

### 1.1 颜色

| 变量 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--accent` | `#008AC4` | `#52B5E5` | 选中状态、链接、开关 |
| `--accent-soft` | `#E0F3FC` | `#203A49` | 开关打开时的底色（如「π 对话」按钮） |
| `--green` / `--green-soft` | `#12A453` / `#E6F4EA` | `#79C68E` / `#243C2B` | 完成、成功 ✓、diff 新增行 |
| `--red` / `--red-soft` | `#DC4848` / `#FBE9E7` | `#EF9689` / `#452B29` | 失败、中断 ✗、diff 删除行、危险操作 |
| `--yellow` | `#F2BC4E` | `#EDC765` | 进行中的圆点（左栏会话运行点用更深的 `--progress-text` 加 `--progress-soft` 光晕，保证 6px 圆点在暖白底上可见） |
| `--yellow-fg` / `--yellow-bg` | `#8A5A00` / `#FDF1D6` | `#EDC765` / `#463C22` | 改动数、待发标签、「工作中」文字 |
| `--bg` | `#F6F5F2` | `#17191D` | 窗口背景 |
| `--bubble-bg` | `#F1EEEA` | `#2C3037` | 用户消息气泡 |
| `--output-bg` | `oklch(0.97 0.003 80)` | `#202329` | 命令输出、代码块 |

**规则**
- 一种颜色只有一个含义：蓝色表示选中或链接，绿色表示成功，红色表示失败，黄色表示有改动或进行中。
- 界面不使用紫色。珊瑚色 `#EE8C7C` 只出现在图标和等待指示器的方块里。
- Git 标签使用独立深色数量徽标（text 背景、bg-elev 文字）；顶栏移除独立「改动」按钮。文件栏标题与目录行不展示改动数量，分支名在状态栏显示；对话内改动汇总及快捷键入口保留。
- 每个基础颜色变量只定义一次：浅色在 `:root`，深色在 `:root[data-appearance="dark"]`，不在后面重复覆盖。

### 1.1a 背景色调（设置 → 外观）

五种底色：1a 暖白（默认，即上表浅色）、1b 雾蓝、1c 鼠尾草、1d 燕麦、1e 石墨。只改变底色与中性色（`--bg`、`--bg-elev(2)`、`--border(-soft)`、`--text*`、`--heading`、`--bubble-bg`、`--output-bg`、`--input-border`、`--sidebar-bg`、`--row-active`），蓝色强调色和状态色不变。

- 1e 石墨就是深色外观：`data-appearance="dark"` 的唯一实现；1a–1d 为 `data-appearance="light"` 加 `data-theme`。`<html>` 上始终同时有两者。
- 浅色色调在 `:root[data-theme="…"]` 中各定义一次；设置页预览色块用同名 `.theme-swatch[data-theme="…"]` 重声明令牌（检查脚本只放行这两种选择器）。
- 「跟随系统深浅色」：系统深色时用石墨，浅色时用最近选择的浅色色调（从石墨切回时用暖白）；开启后石墨卡片置灰不可选。
- 存储：`pi-harness:theme`、`pi-harness:theme-follow`；旧 `pi-harness:appearance`（light/dark/system）只读一次迁移。
- 组件不写死中性灰：表面、边框、次要文字一律用上述令牌，否则换色调时会漏改。

### 1.2 圆角

| 变量 | 值 | 用于 |
|---|---|---|
| `--r-sm` | 6px | 按钮、图标按钮、列表项、标签 |
| `--r-md` | 8px | 输入框、卡片、代码块、命令组 |
| `--r-lg` | 12px | 弹窗、设置窗口 |

圆点状态指示使用 50%；开关轨道使用 `--r-switch`，等待方块使用 `--r-waiting`（1.5px，见 4.4）。词级 diff 高亮使用 `--r-diff-word`（2px，内容专用）。其余圆角使用上表三个令牌；`0` 用于直角，`inherit` 只用于继承父元素圆角。

### 1.3 字体
- 界面与正文使用「最新视觉基准」中的语雀字体回退。
- 命令、路径、版本号、代码用本地 JetBrains Mono，关闭连字；依次回落到 Cascadia Mono、SF Mono、Menlo、Consolas。
- 正文 15px，行高 1.74；界面 13px，辅助文字 12px；状态栏 11px。

### 1.4 允许写死颜色的地方
- 终端 ANSI 调色板（`--term-*`，光标使用 `--accent`）。
- Mermaid 等第三方渲染器配置读取 CSS 变量。独立代码配色（`--file-code-*`、`--wiki-code-*`、`.hljs-*`）可以定义内容色板，关键字使用蓝色系。
- 文字高亮色板（`remark-text-highlight` / `.fp-highlight-*`）。这是用户可选的内容颜色，不属于界面颜色。
- 系统关闭按钮悬停红色（`.desktop-window-close:hover`）。深色浮层及阴影统一读取根变量。
- 深色命令输出中的 Git 状态使用 `--out-green`、`--out-yellow`、`--out-red`，与界面状态色分开。

`npm run check:design` 扫描 `web/src` 下全部 `.css`、`.ts`、`.tsx`，禁止色板及上述例外之外的十六进制颜色、RGB/HSL、颜色名和紫色 OKLCH；非令牌圆角报错并给出行号。颜色名只检查样式值，避免误报文案、路径和标识符。透明色与 `currentColor` 可用。图片转码的白底和文档高亮序列化色板属于内容处理，检查只豁免对应文件中的指定声明。`npm test` 先运行此检查。根色板只允许根选择器中的变量声明，不能通过带 `data-appearance` 的组件规则绕过检查。

## 3. 布局

### Workspace 项目分组（#53）

单栏宽 240px，顶部 Workspace 浮层承载分组管理，项目树与对话、小记同栏，设置固定底部。支持 56px 图标栏与悬停展开；沿用既有图标。具体尺寸与交互以上文「单栏导航」为准。900px 以下导航用抽屉覆盖正文。

分组标题加号打开名称弹窗，创建后选中空分组；每行更多菜单提供重命名和确认删除。无分组时仅显示新建入口，不自动创建或导入项目。沿用既有 catalog、ID、成员和选中偏好。点击 Workspace 只改变目录展示；项目和会话仍走原有切换与草稿保护。添加项目只登记目录，删除分组只移除索引。保存失败保留表单，过期版本要求重试。

小记是服务数据目录级的独立内容，不属于任何 Workspace。目录显示搜索与列表，正文提供标题、Markdown 编辑/预览、待办插入、预览勾选、置顶和确认删除。置顶优先，其次按修改时间排列；无标题显示“无标题小记”，空列表与无匹配结果分别提示。600ms 自动保存，显示等待、保存中、已保存或失败；切换时提交待保存内容，失败草稿保留，页面关闭提供保护。版本冲突提供重新读取（确认丢弃草稿）或另存副本。返回对话恢复原会话和草稿。实现与回归见 [全局小记](architecture-notes.md)。

- 主聊天内容与输入框共用自适应最大宽度 clamp(760px, 76vw, 1800px)，不超过可用空间；桌面两侧 32px，窄屏 20px。
- 顶栏 48px，内置 40px 标签栏，背景与顶栏共用 bg-elev；页签 32px，图标 16px、文字 13px，当前页签为白色全圆角胶囊、轻投影与加粗；触屏指针下页签与操作按钮保留 44px 点击区域；非 Git 仓库时 Git 禁用。
- 标签栏不再重复显示新建对话和设置按钮，使用左栏现有入口。数据库、节点和插件直接展示在顶栏；导航使用可用宽度，不沿用桌面端旧的 34vw/340px 上限，避免节点入口被裁切；窄屏导航横向滚动，侧栏和窗口按钮始终可用。
- 状态栏 26px，显示连接状态 · 版本 · 分支 · 路径，不显示消息数。
- 宽度 ≤900px 时，文件栏变成抽屉；≤768px 时，用移动端抽屉。

### 流畅界面（Web / Desktop 共用）

采用白底正文、浅灰导航、绿色主操作与蓝色链接，保留 pi 图标和已确认字体。导航为实色平面列表；弹窗沿用主题令牌。顶栏采用 48px，保留桌面窗口避让、拖动区。

按钮按下立即反馈，不等待请求完成；键盘焦点使用明确轮廓。移动端侧栏和窄屏文件抽屉使用可中断、携带当前速度的临界阻尼弹簧，进出沿同一路径。抽屉顶部专用拖动区支持指针捕获、速度投射和边界阻尼，正文滚动不被手势接管；关闭按钮和 Escape 均可关闭，隐藏抽屉不可获得焦点。宽屏面板宽度拖动保持 1:1，支持取消和键盘方向键调整。

减少动态效果时抽屉直接到位、浮层静态显示；减少透明度或提高对比度时使用实色背景和清晰边框。动画仅改变 transform/opacity，不给文本流添加入场位移，不循环播放装饰动画。

## 4. 对话流

通知：同一对话、级别和正文完全相同的可见通知合并为一条，以「×N」显示出现次数；不同对话的通知独立。重复信息通知刷新自动关闭计时，警告与错误保留到手动关闭。

### 4.1 消息
- 用户消息：靠右，`--bubble-bg`，圆角 8px，最宽 75%，内边距 8px × 12px，首尾 Markdown 块不额外添加外边距；时间以 10px 弱化文字放在气泡下方右对齐，间隔 4px。内容完全相同、中间没有回复的连续用户消息只显示一次，时间旁标「已重发 N 次」（N 为多发的次数），其余保留定位锚点（3a）。
- 折叠与展开回复的头像、pi 名称左边缘保持一致：头像 18px，头像到名称间距 8px（只使用头像右边距，不叠加 gap），名称统一 13px/600。
- pi 回复：一轮只有一行头部（18px logo · pi · 时间，时间紧跟 pi），模型名放在时间的悬停说明；正文不加气泡，和过程列表左对齐在同一列。
- system 消息是系统提示词快照，显示为居中分隔线「已加载系统提示 · 时间」，不作为聊天行（3a）。
- 过程说明：工具调用前后的短句（少于 40 字，说的是下一步要检查、读取或修改什么），用 12.5px 灰字。结论和要点保持正文样式。
- 长历史摘要每组保持单行，并沿用正常消息流的形状：用户摘要是靠右的单行气泡 + 时间；pi 摘要是 logo · pi · 时间 · 灰色预览；system 摘要同样是分隔线。用户摘要不显示附件原文（`<file …>` 包装）：技能显示为 `/名称` 蓝色等宽小标签，问题文字居中省略，附件显示为带回形针的文件名标签（多个时「+N」），重复发送在气泡下方与时间并列「已重发 N 次」；用户摘要气泡显示完整问题（最多 4 行）和全部附件名。被折叠的 pi 回复与随后展开的同一轮回复共用一个头像和名称。没有正文、思考、工具或错误的空回复（如中断的重试）在折叠区和完整视图都不显示，也不打断重复问题的合并。工具次数、思考和附件统计放在悬停说明，不再单独占一行；没有正文时用统计作为摘要。整行可点击或键盘展开，完整内容与搜索定位保留。
- 长历史的折叠摘要也参与惰性窗口化，首次加载先用等高占位；视口附近才挂载摘要。占位保留消息定位，搜索、展开与问题跳转仍可恢复完整内容。

- 对话里的 Markdown 标题末尾的括号说明（如「(不用你回答)」）显示为同行灰色小字副标题；紧贴在标题上方的分割线不显示，其余分割线为 1px 浅色。
- 顶栏会话标题去掉「skill:」前缀（显示「grill-with-docs · 问题」）；空间不足时分支标签和项目名先收缩，标题优先保留。

### 4.2 过程列表与命令组（3a / 27a / 29a）
- 两段正文之间的思考、bash、read、grep 合成一个带细边框的过程列表，每项一行、行间细分隔线，不再混用灰底单行、卡片和独立卡片。跨消息合并：只含这些步骤的后续消息并入上一组；下一条回复开头的思考/步骤也接在上一组末尾，其正文另起。编辑、其他工具、错误/中断消息和历史折叠边界会结束列表。
- 思考用时满 60 秒改写为「1m 17s」，满 1 小时为「1h 2m」（思考行、工具组标题、右栏步骤一致）。
- 执行步骤文案统一英文（中文界面也一样）：「Thought for 2s」、进行中「Thinking · 6s」、「Ran 4 commands」「Running N commands」「· N failed」、「42 lines」「2 commands」。用户消息、回复正文与其余界面文案保持中文。
- **工具组（Tool Group）**：含 bash/read/grep 的过程列表是一个可折叠卡片，只有一行标题：「› Ran 3 commands · Thought 3s」，可再加「Read N files」「N searches」；右侧状态为红色「N failed」、灰色「N failed · recovered」、蓝色转圈「Running」、灰色「all passed」或「未执行」。失败按每条命令最后一次尝试计数，与行显示一致。失败之后组内还有成功的调用，或这一轮在本组之后继续（有正文或后续回复，不算并入本组的消息），即视为已恢复：灰色、默认收起；只有本轮停在失败上才是红色并默认展开。失败的那一行始终保留 ✗ 和 exit 码。
  - 默认展开：本轮仍在进行这一段（后面还没有正文）、有工具在运行或有未恢复的失败；否则收起。用户点击后以用户选择为准。收起时行仍挂载，跳转、搜索与「pi:reveal-tool」会自动展开并定位。
  - 行：等宽 12.5px、左右 14px、行间无分隔线；✓ 绿 / ✗ 红 / › 灰（思考行「Thought for Ns」）。右侧元信息：失败为「exit N」，成功为实测用时（≥0.1s），否则为行数。失败的行保持单行，点开才显示输出（组本身已因失败展开）。
  - 只有思考、没有工具的列表不加组标题，保持原单行样式。
- 思考行：过程列表内的思考行用浅灰底色（`--output-bg`）弱化，不与工具行争夺注意力。完成时为「› Thought for Ns」（无实测耗时显示「Thought」，悬停说明耗时未记录），点击在行下展开正文；进行中为转圈 + 蓝色「Thinking · Ns」+ 最新一行斜体灰字单行省略，计时从该行出现开始。
- 连续的 bash 调用合成一组。组标题写「Ran N commands」，有失败时再加「· N failed」，展开箭头靠右。只有 1 条命令时不显示组标题。历史组收起为一行时显示首条命令的摘要，多于 1 条时右侧标「N commands」，不重复上方的叙述句。运行中的命令用转圈代替圆点。
- 运行中的命令行（#106）：右侧显示实时计时「执行中… Ns」（满 60 秒改写为「Nm Ss」，同思考行）；收起时标题旁用斜体灰字单行省略显示最新一行输出（同进行中的思考行），展开时输出区显示最后 6 行而不是前 6 行，行号保持真实编号。
- 每条命令一行：
  - 如果命令带 `echo "=== 标题 ==="`，就用这个标题当名字，后面跟灰色等宽字体的真实命令（单行，超出部分截断）。
  - 可以识别的 `sed -n` 读取，显示文件名和行号范围。
- 去掉开头的 `cd 项目目录 &&` 和结尾的 `2>/dev/null`。展开、复制和重跑都使用完整的原命令。
- 标题相同的连续命令合成一行，标「试了 N 次」，显示最后一次的命令和结果。
- 输出默认收起；工具组之外的命令组里失败的那一条自动展开。输出最多显示 6 行，带行号，用 `--output-bg` 底色。
- 组内只显示最后 8 条，上面显示「展开全部」。
- 工具组行显示 ≥0.1s 的实测用时；其他位置不到 1 秒不显示用时；没有实测数据时显示「耗时未记录」。

### 4.3 文件改动（35a）
- 对话与代码改动遵循 [35a 设计](chat-diff-design.md)。成功改动在每轮汇总卡与独立 ChangesPanel 中显示；失败和运行中的调用保留状态。历史命令组默认收为一行，当前运行组展开。
- 面板默认本轮，支持整个分支与未提交；600px 对话列，面板最小 560px；1200px 以下使用抽屉。
- 以下旧卡片规则只用于失败详情及兼容视图。
- 标题行：操作 · 文件路径 · `+N −M` · 状态。
- diff 在浅色模式下：新增行用 `--green-soft` 底，删除行用 `--red-soft` 底，行号那一栏颜色再深一档。深色模式下用对应的深色变量。
- 相邻 3 次及以上的编辑合成一个文件列表，每个文件的 diff 默认收起。

### 通用工具卡片（#45）
- 自定义/MCP 工具使用紧凑标题行：工具图标、可点击折叠的名称、状态与耗时；放大和复制参数使用带可访问名称的图标按钮。
- 简短标量参数按键值展示，复杂参数保留可滚动原文；输入区明确标为「参数」，输出区保持既有截断与展开行为。
- 完整输出下载位于卡片底部的轻量操作区，不使用突兀的默认按钮。没有文本但有输出文件时说明可下载完整结果，不展示空输出框。
- Bash、文件读取、编辑和 Codemode 专用卡片保持各自布局。窄屏标题允许名称截断，参数自动换行，所有操作可键盘访问。

### 4.4 等待指示器（31a）
- 三个 6×6px 方块（`#EE8C7C` `#3E8FC0` `#F2BC4E`），圆角 1.5px，间距 3px，依次呼吸，周期 1.2s。
- 文字 13px，字重 500，灰色加流光（1.8s）；用时 12px 灰字。
- 位置：最后一个内容下方 8px，左边留 2px。
- 聊天运行状态文案固定使用英文（包括中文界面），计时用 sec/min，等待指示器里的停止链接为 Stop：

| 阶段 | 文案 |
|---|---|
| 刚发出消息 | Understanding your question |
| 工具调用刚结束 | Reading command results / Reading files |
| 有思考但还没有正文 | Thinking |
| 测试或构建命令超过 4 秒 | Waiting for test results / Waiting for build results |
| 插话已送达 | Processing your direction |

- 300ms 后才出现；4 秒后显示用时；60 秒以上显示「M min SS sec · Stop」。
- 收到正文或思考内容时立刻消失。断线、重试、压缩或静默告警时由对应的状态接管。
- 系统开启减少动态效果时，方块和文字都静止。
- **不再使用**：「正在分析请求」「仍在思考」「响应较慢」「等待模型」，以及显示在标题行的蓝色等待状态。

### 4.5 工具调用未执行（33a）
- 完整交互与验收见 [33a 设计说明](tool-unexecuted-design.md)，取代 32a。
- 每次用户请求最多自动提醒一次；同一次异常用稳定 incidentId 关联，真实工具调用后恢复正常。
- 首次漏出调用只留灰色说明；自动提醒显示居中事件行，跳过问题导航、编辑和折叠摘要。
- 最终停住只在最后回复后显示一张白底、浅红标题的恢复卡，原文按尝试次数集中展示。
- 换模型使用可键盘操作的自定义菜单，重发原始问题及其附件。
- 自动提醒中三栏统一黄色工作中；最终停住统一红色中断，无计划时显示说明代替空状态。
- system 消息只显示为分隔线（见 4.1）；回到底部的出现条件见 4.6；上下文与缓存为零时隐藏。

### 4.6 结构化回复（4a）
- 回复里的盒线字符树（`├──` / `└──`，每行都是分支，至少 3 行）渲染为浅色结构化树：顶部「根 · 根标题 · N 个分支」，节点编号用灰色等宽字，副说明灰字，子层用左侧细线缩进。多数节点共有的 `← 本轮` 类标注只在顶部说明一次，各节点只显示与之不同的部分（黄色标签）。用户粘贴的树保持原样。保留复制原文。
- 同一回复里有 2 个及以上 `❓ **Q1** - **标题**：问题` 时，问题渲染为卡片：编号、标题、问题说明；`(a) …;(b) …` 选项逐行可点（单选，再点取消）；`➡️ 推荐 (c)。理由` 的推荐项带「推荐」标记并默认选中，理由显示在选项下。没有字母选项的开放问题，推荐答案作为一个可选项（默认选中）。每张卡片最后都有「其他」行：单选圆点 + 下划线输入框（占位「不采纳以上选项？写下你的答案或原因…」），聚焦或输入即选中；写了内容才计为已答，空内容列入「Qx 待回答」。发送时「其他」按「Qx 标题：其他 · 内容」附上（多行合成一行）。「全部采纳推荐」覆盖所有题的选择，已写的「其他」文字保留，可重新选回。卡片之间的普通段落照常显示。
- 只有最新且已结束的回复可作答。此时输入框上方出现回答栏：「已选 N / M」「Qx 待回答」、「全部采纳推荐」、「发送回答」；占位文字为「补充说明，或直接输入其他回答…」。发送内容为每题一行「Q1 标题：(c) 选项」，输入框里的文字附在最后，走普通发送流程（附件、当前文件、排队规则不变）。「全部采纳推荐」在所有推荐已选中时也必须给出可见确认（按钮短暂变为绿色「已采纳推荐」），多轮提问中新旧卡片混排时不能无反馈；带字母后缀的题号（Q1a/Q1b）保持独立答案键，不截断碰撞。回归：`tests/question-accept-test.mjs`（#100）。
- 「回到底部」是 28px 圆形箭头按钮，放在阅读列右侧留白、输入框上方，不覆盖正文和用户气泡；只在离底部超过一屏且正在向上滚动时出现，不推动输入框。文字放在悬停说明与可访问名称。

## 代码搜索（⌘P）
- 文件栏「搜索文件」与 ⌘P 打开代码搜索弹窗，宽 min(980px, 94vw)；⌘K 全局搜索不变。
- 顶部：搜索图标 · 「代码 / 文件名」分段切换（Tab 切换）· 输入框 · Aa（区分大小写）/ ab（全词）/ .*（正则），选中为 `--accent-soft` 底与 `--accent` 字。第二行「范围」填 glob，逗号分隔（如 `src/**/*.ts, !**/*.test.ts`），右侧「N 处匹配 · M 个文件」。
- 代码模式由服务端 ripgrep 搜索（随应用打包，遵守 .gitignore，字面量默认；单文件 20 条、总 500 条、5 秒、单行 300 字符），300ms 防抖，结果分批流入；新请求立即终止旧进程，关闭弹窗也会终止。正则无效时提示「正则表达式无效」且不发请求。
- 左栏按文件分组：文件名 · 目录 · 匹配数；每行行号 + 片段，命中用 `mark`（`--accent-soft` 底）。右栏预览命中行前 8 行到后 12 行，命中行浅蓝底与左侧色条。
- ↑↓ 选择，Enter 打开文件并滚动到命中行（复用 `pi-harness:open-tool-file`），Esc 关闭。文件名模式保留原交互，服务端改用 `rg --files`（含点文件、跳过 gitignore 目录），ripgrep 不可用时回退到原遍历。
- 窄屏隐藏预览，输入框换到第二行。跳转到定义、查找引用与符号索引尚未实现（指导文档第 2、3 步）。

## 5. 输入框（28a）
- 文件拖放结束、取消或窗口失焦后立即清除窗口遮罩；输入框等子区域独立接收文件时也必须清除。
- 圆角 8px，描边 `oklch(0.88 0.005 80)`。只有聚焦且有内容时，描边才变成 `--accent`，不加外部光晕。
- 底部一行依次是：附件 · 模型 ▾ · 思考 ▾ · 插话/排队 ▾（只在运行中显示）· 上下文 [36px 进度条] N% · ■ 停止 · ↑。缓存命中率放在上下文弹层里；只有缓存数据时触发器才显示缓存。
- 图标按钮 28×28px，圆角 `--r-sm`：
  - ↑ 发送：没有输入时是灰色，不能点；有输入时是 32px 圆形 `--heading` 底、`--bg` 色加粗向上箭头。
  - ■ 停止：只在运行时显示，是运行中的主按钮（3a）：`--heading` 底、`--bg` 字，32px 圆形底配实心圆角方块，与发送按钮同尺寸；仅保留图标，名称和 Esc 提示通过 aria-label／title 提供。发送与停止悬停均使用中性色。运行中输入为空时隐藏发送按钮，有内容时再出现。
- 快捷键：↵ 按选中的方式发送，⌥↵ 用另一种方式，⇧↵ 换行。Esc 在有文字时清空，空输入时停止。
- 待发消息固定在输入框上方，只占一行：黄色标签 · 摘要（超出部分用省略号）· 撤回。
- 宽度不够时：先缩短模型名，输入框 ≤530px 时隐藏缓存摘要，按钮不缩小。

## 6. 右栏
- 普通文件栏与 Wiki 目录统一使用顶部「搜索文件」入口（Cmd/Ctrl+P）、32px 树行、18px 层级缩进及中性线框文件／文件夹图标。同级预留相同的展开箭头位置，名称用界面字体。悬停／键盘聚焦使用暖灰背景，右侧引用按钮为浅黄色底；引用文件或目录只附加路径、不自动发送。触屏持续显示引用入口。
- 目录已删除、无权限或不可读取时，在对应树节点下显示原因和刷新按钮，不弹出重复通知；根目录失效提示重新选择项目。刷新成功清除错误。
- 文件标题栏提供新建文件与刷新按钮；新建在标题下输入工作区相对路径，父目录需已存在，创建空文件后打开，重名报错并保留输入。刷新保留展开状态并更新已展开目录。Wiki 文件栏共用新建入口，默认填入当前文档所在目录。
- 上半部分是文件树，下半部分是「进度 / 输出」两个平铺分区，用细分隔线隔开，不再套卡片（3a）；分区标题 11px 灰色，两区可以分别折叠。空状态只有一行说明文字，紧贴标题，不显示占位图形。
- **进度**：优先显示原生 plan 的步骤；无计划的任务显示按工具步骤归并的阶段行（同一行样式，标题下一行 10px 单行摘要，不虚构计划）；此时分区标题改为「步骤」，右侧灰字「N 步」。每步一行：绿色 ✓（进行中转圈；只有之后再无成功步骤的失败才是红 ×，探索中失败后继续推进的算成功）· 标题（模型的叙述标题原样保留；「读取 2 项」这类通用标题按实际内容改写为「读取 N 个文件 · 运行 M 条命令」）· 右侧用时（≥0.1s）；下方逐行列出涉及的文件或命令（等宽 12px，工作区内用相对路径，短的家目录路径保留 `~/`，其余只显示文件名，同名文件补上一级目录；最多 4 行，其余「还有 N 项」）。点击文件打开预览，点击命令跳到对话中的对应行。本轮已采用计划的当前步骤用 `--accent`；尚未用于本轮的历史计划中，未完成步骤统一显示待办，不高亮或自动滚动到历史当前项。完成用 `--green` ✓，失败或中断用 `--red`。历史计划仅显示「此前未完成计划」，不提示用户确认；计划工具不引入单独的审批步骤。本轮结束但计划未收尾时显示「本轮已结束 · 计划待继续」（issue #63）。
- **步骤轻量精简**：无计划步骤的文件／命令明细默认折叠，点击步骤标题展开，保留最多 4 行及跳转行为。通用标题简化为「读取文件／修改文件／运行命令」，混合活动保留各类别，原数量摘要放在标题悬停提示中；自动生成的「运行 + 原始命令」（含截断标题）同样使用简短类别标题，避免重复展示命令；模型具体叙述标题不改写。仅当阶段全部命令为明确的 typecheck 与 build 且两者都有时显示「验证类型与构建」，其他命令不推测用途。当前步骤使用 accent 浅底、左侧细线与「进行中」文字；已完成标题弱化，文件／命令 11px，耗时 10px；失败继续红色显示。原生计划清单与生命周期不变。
- **本轮文件**（原「输出」）：只列当前任务里有成功结果的 write/edit 文件，标题右侧显示去重文件数量。文件名为主，下一行仅显示目录（单行省略，完整路径悬停可见，同名文件由目录区分），点击打开预览。可统计的编辑保留 `+N −M`，以 11px 次要文字显示，悬停说明为累计编辑行数而非最终净改动；未知行数不显示为零。无记录时仅显示一行「本轮暂无文件写入记录」。
- 计划完成标准为可选项；为空时，聊天计划卡片与右侧进度均不显示「完成标准」行。
- 不显示命令记录、读取记录、「计划有变」提示或总耗时。

## 7. Wiki（34a）
- 左侧目录栏「打开文件夹」在当前 Wiki 窗口切换工作目录，复用文件夹选择器；取消、保存失败或路径无效保留当前页面，空目录默认展开文件树。
- 右侧提供「问 pi / 目录」页签，目录按当前正文 H1–H6 层级跳转并实时更新，不写入 Markdown；保留用户手动插入的正文目录。
- 文件栏提供可聚焦拖动手柄，记忆宽度；方向键以 10px 调整，双击或 Home 恢复默认。窄屏文件抽屉保持固定宽度，手柄隐藏。
- 索引未完整时才显示黄色状态「已索引 N / M · 跳过 K」，数字带千分位；未统计完的总数显示「统计中」，不用 +。原因放悬停提示和详情，详情逐类统计。
- 面包屑只显示项目相对目录，空间不足中间省略、悬停显示完整路径。树行 32px，文件预留箭头宽度，与同级目录名对齐。
- 标题信息到正文 22px，段落间距 .6em；开头连续的字段/值作为可折叠的 12.5px 属性表，保留 Markdown 原文。输入框禁止手动缩放。表格图标带表头，引用图标用左竖线，宽版用横向双箭头。
- 文档页以 [Wiki 文档页 v2](wiki-doc-v2-design.md) 为准：默认直接编辑，独立 44px 插入栏，标准正文 760px、宽版 1000px。标题与正文统一使用 `--sans`（MiSans 优先）；保存状态位于顶栏。
- 明确的 `./`、`../` 文件链接可直接打开未参与后台索引的知识证据；服务端仍校验工作区真实路径，缺失文件显示读取错误，模糊双链继续要求索引中的唯一匹配。
- 已登记知识目录的 evidence 快照在 Wiki 中只读，知识正文继续使用现有编辑与保存流程。
- 工具栏按「导航（目录/文档链接）· 标题（正文/H2/H3）· 列表与插入 · 代码」四组以分隔线分组，「编辑源码」为低强调次级按钮；工具栏与 `/` 共享全部 11 个插入项，不再使用「＋」菜单；表格 8×6 尺寸格，代码语言含 Mermaid，渲染图表并保留源码。
- 目录选中项使用中性 `--bg-elev2` 底色，不显示蓝色竖条或蓝色背景；文件名显示中性线框图标。标题元信息显示日期、阅读时长和标签。
- 普通文件预览的 Markdown 表格外框随实际列宽收缩；Wiki 正文表格默认铺满可用宽度。超宽表格限制在正文宽度内并横向滚动。编辑器里无任何单元格内容的空模板表格（如 /table 尺寸格新插入）例外：占满正文宽度、列均分且不受单元格最小宽限制，填入内容后按所在视图的宽度规则展示。文档表格规则优先于祖先 `.msg-text` 的聊天表格样式；通过 `/table` 尺寸格新插入及保存重开后均遵循同一布局。回归：`tests/markdown-table-layout-test.mjs`、`tests/wiki-table-insert-test.mjs`。
- 表格尺寸格和行内代码分别使用 `--r-wiki-grid`（3px）、`--r-wiki-code`（4px），为文档内容专用令牌。
- 文档正文最宽 760px（宽版 1000px），两侧各 64px 留白；左栏 250px，对话面板 400px。
- Markdown 统一打开独立可编辑文档窗口（ADR-0003），不再渲染主应用的顶栏、视图切换与底部 Git 状态。专用标题栏依次提供文档图标、路径／文件名／保存状态、目录、搜索、最近改动、「问 pi」和关闭／系统窗口控制；桌面端标题栏与面包屑形成连续拖动区，所有交互控件为 `no-drag`，macOS 左侧避让红绿灯。
- 右栏默认显示当前文档目录；展开「问 pi」时在同一栏替换目录，收起聊天后恢复目录，宽度保持不变。右栏可拖动调宽，刷新保留窗口级聊天／目录选择。小屏默认收起目录，手动打开后以覆盖式面板展示。复用原聊天的消息和输入框实例，保留草稿、附件和进行中的回复；发送前保存文档，保存失败保留输入。选区「问 pi」先保存，再把路径与点击时选中文字追加到右栏输入并聚焦，不自动发送；文件引用同样自动展开。左侧文件栏默认常驻，切换文档保持展开，移除标题栏目录开关；最近改动使用右侧覆盖抽屉，不压缩正文。
- 关闭与 Escape 共用保存保护；失败后可继续编辑或明确放弃。Escape 先处理内部菜单和弹窗，重开同文档恢复滚动位置。

- Wiki 代码配色跟随应用外观，浅色和深色色板分别在根变量中定义一次；不再使用独立 `data-code-theme` 覆盖。
- 保存状态的圆点用 `--green`；改动提示的图标用 `--green`。
- 停止输入 800ms 后自动保存；选中文字时才显示格式工具条；`/` 打开 300px 宽的单列菜单。
- 选区浮动格式栏提供正文 T、标题 H2/H3，支持将标题转回普通段落；正文按钮执行 `formatBlock p`，不清除行内格式。标题 2/3 与顶部插入栏使用同一组 H2/H3 图标，不能共用正文 T 图标；点击分别生成 h2/h3，保存为 `##`/`###`。回归：`tests/wiki-heading-toolbar-test.mjs`（#99）。
- 空行提示只显示在编辑器聚焦且光标折叠的空段落内，输入空格／文字、中文输入法组合、选区或失焦时隐藏；不用于表格、列表或代码。提示锚定段落，单行省略且不覆盖相邻行，不写入文档。回归：`tests/wiki-placeholder-browser-test.mjs`（#98）。

## SSH 节点工作台

节点连接后左侧显示 SSH 终端与文件，右侧显示 Agent Chat，并自动准备使用本机模型配置的隔离会话。无需远端安装 pi 或再次点击启动。准备期间显示状态，输入框常驻；准备完成后即可发送。失败时在右侧显示错误与重试入口，SSH 终端保持可用。正文按用户消息、助手回复、思考与工具结果展示；发送确认后才清空草稿，保留排队/纠正、停止、模型选择及新对话。远端目录在会话准备前或重开时设置，工具明确作用于当前节点；左侧页脚说明共享终端及执行期间的输入锁定。关闭 Agent 后保留重新打开入口，不立即自动重开。

Wiki 插入菜单在输入触发浏览器自动滚动时继续跟随可见光标定位；光标离开视口或窗口改变尺寸时关闭。菜单自身的列表滚动不关闭菜单。

### UI/UX Pro Max 全页优化

## Playground（Java 代码运行，2026-10-21）

Java 运行入口属于核心界面，不是插件。默认关闭；开启后，对话消息与小记里的 `java` 代码块、以及右栏文件预览里的 `.java` 文件出现运行按钮。功能与安全边界见 `docs/architecture-playground.md`。

- 运行按钮放在代码块 chrome 内、复制按钮旁边，图标用 Lucide `play` 线框 16px，与既有 chrome 按钮同一尺寸与弱化样式；悬停提示「运行」。
- 按钮可用性：总开关关闭、JDK 未探测到、或已有运行在进行时显示**禁用态 + tooltip 原因**；**不隐藏**——隐藏会让用户以为功能不存在。
- 结果区位于代码块正下方，可折叠、默认展开；显示状态、耗时与退出码。stdout 用等宽字体，stderr 用错误色。编译错误原样展示 `Main.java:3: error: ...`，不做额外排版或折叠。
- 运行中显示可取消的停止按钮与计时；输出按 60ms 微批合并渲染，不逐 chunk 重排。
- 小记里的运行结果渲染在编辑器**下方临时区**，不写入正文、不参与保存与版本；代码块文本一变，结果立即失效并标记「代码已改变」。
- 设置页新增「代码运行」分组（现有 prompt / appearance / skills / extensions / native-mcp / updates 之外），含总开关、超时（1–60s）与 JDK 探测状态及「重新检测」。开关默认关闭，开启时弹一次二次确认，文案明确「不是沙箱，执行的是你自己机器上的任意 Java 代码」；被 `PI_WEB_PLAYGROUND` 锁定时显示为只读并说明原因。
- 右栏文件预览的运行按钮放在 `fp-header-actions`（或「更多」菜单）里，不对 `.java` 以外的文件出现；`CodeFileEditor` 本体不加控件。它运行**编辑器缓冲区**（含未保存改动）且**不保存**，tooltip 必须写明这一点；切换文件即清空结果。因为不保存，运行后文件仍是未保存状态，离开时的未保存保护照常生效。
- 左栏全局导航「对话」与「小记」之间新增 **Playground 草稿页**（2026-10-22）：入口**不受总开关隐藏**（写代码不等于运行代码），但页内运行按钮的可用性与其它入口同规则。页面为极简 scratchpad：等宽编辑器（Tab 缩进）、运行/停止、共用 `PlaygroundResult` 结果区；⌘/Ctrl+Enter 运行。草稿全装一份，服务端持久化（`<dataDir>/playground-scratch.json`），600ms 去抖自动保存、失败显示错误；运行结果不持久化，改码后结果打「代码已改变」。首访无草稿时种入可运行的模板。颜色与圆角只用既有令牌。
- 颜色与圆角只用既有 CSS 变量；运行中／成功／失败／超时沿用既有语义色，不新增令牌。

### Playground 方法测试

草稿页仅提供方法测试，顶部直接显示「运行全部用例」，不再显示模式切换。首次使用填入 非 private 方法示例，已有草稿保留原文。方法测试采用并排调试台：左侧约 60% 为代码编辑器，右侧为 非 private 方法选择器与用例列表；两栏独立滚动，窄屏（1100px 以下）改为上下布局。用例默认展开第一条，新增后展开新用例；收起时显示参数摘要与运行状态，展开后输入、预期值和实际结果就近显示。每条用例按参数名称和类型输入，可启用预期值断言，支持新增、删除、单条运行和全部运行。引用类型有显式 null 选项，数组和 List 用 JSON，嵌套 List 用嵌套 JSON 数组；输入框按 List 元素类型显示示例（如 `[1]`、`[["a"]]`），字符串直接输入。结果逐条显示返回值、通过／失败／异常／未断言／未执行与汇总，日志仍分 stdout/stderr。代码或用例变化标记结果过期。方法和用例随草稿自动保存。窄屏用例纵向排列；沿用现有颜色、圆角与字体令牌。

方法测试调试台：载入已存草稿即显示保存状态；运行汇总明确区分进行中、完成、结束及停止。内容容器不足 850px 也切为上下布局，500px 以下编辑器默认 260px 高；深色编辑器复用已有深色语法色变量。用例展开、入口与按钮反馈遵循减少动态效果偏好。

草稿编辑器提供「格式化」按钮和 Shift+Alt+F 快捷键（#127）：服务端使用 Prettier Java，仅调整代码、不执行；支持方法片段和完整 class，执行关闭或没有 JDK 时仍可使用。解析失败保留原文；请求期间编辑过代码时不应用旧结果，离开页面取消请求，格式化可撤销。`POST /api/playground/format` 接受 `{code}` 并返回 `{code}`，沿用鉴权与 256 KiB 源码限制。方法识别支持 public、protected 和默认访问权限，private 方法保持作为辅助方法；旧签名的用例保留，选择新方法后可添加新用例。
