## Pi 1.5.2 适配（2026-11-12）

- 普通聊天历史提供默认收起、按需加载的「原目录已失效的会话」。恢复弹窗展示原目录和当前目标目录，提供「继续」「复制到当前项目」「取消」，复制为主操作；继续仅临时使用当前目录，不修改原历史。Wiki 不显示此入口。有效项目外的启动失败展示重启到有效目录的指引。

## 统一空状态：网格纸标语

主聊天与问 pi 的空状态共用英文标语“There are many agent harnesses / but this one is yours”：无装饰背景、深灰衬线斜体、蓝色 yours。主聊天的品牌图标和标语作为整体，在顶栏与输入框之间水平、垂直居中；图标下方仅显示标语，不显示网格背景、目录和快捷提问；问 pi 移除标语下的文档／追加项目文字区，项目选择统一从上方模式菜单进入；当前文档保留输入框引用 chip。浮窗默认尺寸 375 × 820px（与参考图 750 × 1640 的比例一致，可手动缩放），输入框空白时为单行高度，长输入最多增长到 120px；欢迎区占据输入框上方空间，避免覆盖输入框；窗口标题和正文不使用此装饰字体。窄面板允许自然换行，深色主题使用对应令牌。

## 问 pi：文档会话与项目分析范围

每篇 Markdown 恢复自己的 chat，切换文档清除所选 Workspace 项目，不恢复上次的追加范围。空状态用实际模型名称与「文档问答／结合知识库」胶囊，以及「根据 当前文档」「添加项目／知识库」「进行分析」排版；不显示旧说明和三个建议按钮。项目选择器按已有 Workspace 分组展示项目目录，也可返回仅文档。当前文档引用固定，额外项目选择显示可移除 chip，发送时按需读取并要求引用来源，不预加载整个项目。历史只列出当前文档的对话。

## Desktop 问 pi 独立浮窗

桌面打开问 pi 时，浮动模式使用独立无边框窗口，可拖动标题栏跨屏移动并用系统窗口边缘缩放；固定按钮移回 Wiki 右栏。关闭浮窗只收起助手，保留对话、草稿与引用。Web 继续使用页面内浮动。浮窗沿用当前主题、字体和浅灰表面。

- 覆盖式文件抽屉只在握持区显示一个「文件」标题，面板内不再重复标题；新建、刷新、更多与关闭操作保留。常驻桌面文件栏标题不变。

## 1. 设计令牌

所有颜色和圆角只能通过 CSS 变量使用，组件里不写十六进制颜色（终端 ANSI 调色板和第三方渲染器配置除外，见 1.4）。

### 增删差异配色

增删行在所有外观下采用深绿／深红实色底，配浅色文字：新增背景 `--diff-add-bg`（#14532D），删除背景 `--diff-del-bg`（#7F1D1D），文字分别为 `--diff-add-fg`（#F0FDF4）和 `--diff-del-fg`（#FFF1F2）。词级变化使用 #166534／#991B1B 的独立底色；保留行号和加减号。适用于工具编辑卡、Git 差异、文件差异、对话改动面板和 Wiki 改动记录。增删行内语法文字统一使用对应浅色前景，避免普通浅色主题的语法色落在深底上；未变行沿用原语法配色。成功／错误等通用状态色不变。

### 1.1 颜色

| 变量 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--accent` | `#008AC4` | `#52B5E5` | 选中状态、链接、开关 |
| `--accent-soft` | `#E0F3FC` | `#203A49` | 开关打开时的底色（如「π 对话」按钮） |
| `--green` / `--green-soft` | `#12A453` / `#E6F4EA` | `#79C68E` / `#243C2B` | 完成、成功 ✓、diff 新增行 |
| `--red` / `--red-soft` | `#DC4848` / `#FBE9E7` | `#EF9689` / `#452B29` | 失败、中断 ✗、diff 删除行、危险操作 |
| `--yellow` | `#F2BC4E` | `#EDC765` | 改动数、待发标签等黄色语义的底色来源 |
| `--progress-text` / `--progress-soft` | `#0E7C36` / `#E4F7E9` | `#79C68E` / `#243C2B` | 唯一的「进行中」指示色：左栏会话运行点、任务面板进行中、计划步骤、进度条、命令转圈与计时。浅色取比 `--green` 更深的绿（`--green` 在暖白侧栏上只有 3.1:1，6px 圆点看不清；`#0E7C36` 为 5.1:1，与旧黄色持平） |
| `--yellow-fg` / `--yellow-bg` | `#8A5A00` / `#FDF1D6` | `#EDC765` / `#463C22` | 改动数、待发标签、警告与「工作中」文字 |
| `--bg` | `#F6F5F2` | `#17191D` | 窗口背景 |
| `--bubble-bg` | `#F1EEEA` | `#2C3037` | 用户消息气泡 |
| `--output-bg` | `oklch(0.97 0.003 80)` | `#202329` | 命令输出、代码块 |

**规则**
- 一种颜色只有一个含义：蓝色表示选中或链接，绿色表示运行中与成功，红色表示失败，黄色表示有改动或待发。**所有进行中的指示统一用 `--progress-text`**（含 bash 运行灯、命令转圈与计时、任务面板与计划步骤、左栏运行点），不得再用 `--accent` 或 `--yellow-fg` 表示运行中——命令跑完的一瞬间从蓝跳绿会被误读为状态含义变了。
- 界面不使用紫色。珊瑚色 `#EE8C7C` 只出现在图标和等待指示器的方块里。
- Git 标签使用绿色数量徽标（green-soft 背景、green 文字）；顶栏移除独立「改动」按钮。文件栏标题与目录行不展示改动数量，分支名在状态栏显示；对话内改动汇总及快捷键入口保留。
- 每个基础颜色变量只定义一次：浅色在 `:root`，深色在 `:root[data-appearance="dark"]`，不在后面重复覆盖。

### 1.1a 背景色调（设置 → 外观）

五种底色：1a 暖白（默认，即上表浅色）、1b 雾蓝、1c 鼠尾草、1d 燕麦、1e 石墨。只改变底色与中性色（`--bg`、`--bg-elev(2)`、`--border(-soft)`、`--text*`、`--heading`、`--bubble-bg`、`--output-bg`、`--input-border`、`--sidebar-bg`、`--row-active`），蓝色强调色和状态色不变。

- 1e 石墨就是深色外观：`data-appearance="dark"` 的唯一实现；1a–1d 为 `data-appearance="light"` 加 `data-theme`。`<html>` 上始终同时有两者。
- 浅色色调在 `:root[data-theme="…"]` 中各定义一次；设置页预览色块用同名 `.theme-swatch[data-theme="…"]` 重声明令牌（检查脚本只放行这两种选择器）。
- 「跟随系统深浅色」：系统深色时用石墨，浅色时用最近选择的浅色色调（从石墨切回时用暖白）；开启后石墨卡片置灰不可选。
- 存储：`pi-harness:theme`、`pi-harness:theme-follow`；旧 `pi-harness:appearance`（light/dark/system）只读一次迁移。
- 组件不写死中性灰：表面、边框、次要文字一律用上述令牌，否则换色调时会漏改。

## 4. 对话流

通知：同一对话、级别和正文完全相同的可见通知合并为一条，以「×N」显示出现次数；不同对话的通知独立。重复信息通知刷新自动关闭计时，警告与错误保留到手动关闭。

### 4.1 消息
- 用户消息：靠右，`--bubble-bg`，圆角统一 `--r-md`（8px，四角一致，只有助手侧才用不对称圆角），最宽 75%、最宽 90%（≤768px 窄屏），内边距 8px × 12px，行高沿用正文 1.74 而不是单独压低；首尾 Markdown 块不额外添加外边距；时间以 10px 弱化文字放在气泡下方右对齐，间隔 4px。
- 用户气泡的宽度、内边距与圆角**只允许有一处声明**（`.msg-user > .msg-body`），后续规则只能改变窄屏断点下的宽度；旧实现同一属性被声明四次（78%／75%／90%），看似改了却由后声明的值生效，排查时极易误判。内容完全相同、中间没有回复的连续用户消息只显示一次，时间旁标「已重发 N 次」（N 为多发的次数），其余保留定位锚点（3a）。
- 折叠与展开回复的头像、pi 名称左边缘保持一致：头像 18px，头像到名称间距 8px（只使用头像右边距，不叠加 gap），名称统一 13px/600。
- pi 回复：一轮只有一行头部（18px logo · pi · 时间，时间紧跟 pi），模型名以中性胶囊显示在名称与时间之间，同时保留时间的悬停说明；正文不加气泡，和过程列表左对齐在同一列。
- system 消息是系统提示词快照，显示为居中分隔线「已加载系统提示 · 时间」，不作为聊天行（3a）。
- 消息节奏（29b / 29d）：消息盒**没有下内边距**，间距只有一条 `margin-top`，量的是盒子与盒子之间（旧实现 padding 14px 叠 margin，写着 14px 实际读出 28px）。轮与轮之间 36px、用户问题前 28px；上一条回复以正文收尾、下一条回复另起时同样是 36px（原实现只有 21px，比回复内部 10px 的头部间距都不成立，视觉上两段回复粘在一起）。继续上一条的回复（`msg-continuation`，无头部）14px；首条消息不加间距，列表 padding 已有留白。
- 一次连续执行（29d / 29e）：一轮里「句子 → 命令 → 句子 → 读取」是一条连续流，每一段距上一段 **10px**（两个过程块相邻时 4px），只有真正的轮与轮之间才是 36 / 28px。否则会出现「已运行 2 条命令」与「已读取 1 个文件」之间空出 36px 的断档，把一次连续工作切成几段。
  - 实现要点（踩过的坑）：① 消息外固定套两层 LazyMount 包装（`.messages > div > div > .msg`）；② `:is()` 取参数里**最高**的特异性，写 `:root … :is(.messages > *, …)` 实际只得 1 个类，与基础 `.msg` 打平而被后者赢；③ 不要在间距规则上使用 `!important`——之前 continuation 上的一条 `!important` 静默压掉了后面所有间距规则，导致 36px 断档反复出现。现在的写法是显式层级 + 额外 `.msg` 令牌，禁用 `!important`。
  - system 分隔线上下各 34px，负责把「已加载系统提示」两侧的两个轮次分开。
- 回复内部排版（29f）：`.msg-text` 用 `display: flow-root`，把末段图块的 12px 外边距收进盒子内——否则它会“穿透”盒子叠到下一个间距上，10px 实际读成 20px（标题、单行段落后面都能看到）。首/末图块的边距归零必须用 **8 个类**的写法才压得过段落规则 `.view-pane .main .msg-assistant .msg-text .md p`（6 个类），否则回复正文永远比头部低 12px。回复内相邻两个文本块之间 10px，和一轮里其余间距同一个刻度；`margin-top` 只有一条声明，不再用多条同选择器规则叠出最终值。
- 折叠摘要行沿用同一套行结构：无左边框、无圆角、无底色，头像/名称 · 预览 · 时间，与展开的消息同一列对齐；悬停只变文字颜色。
- 回复头部：头像、pi、时间与「折叠」按钮同一行，行高固定 22px。折叠按钮只在悬停、键盘聚焦或触屏（无 hover）时出现，出现与隐藏不改变高度，所以正文起始位置不会跳动。
- 过程说明：工具调用前后的短句（少于 40 字，说的是下一步要检查、读取或修改什么），用 12.5px 灰字。结论和要点保持正文样式。
- 长历史摘要每组保持单行，并沿用正常消息流的形状：用户摘要是靠右的单行气泡 + 时间；pi 摘要是 logo · pi · 时间 · 灰色预览；system 摘要同样是分隔线。用户摘要不显示附件原文（`<file …>` 包装）：技能显示为 `/名称` 蓝色等宽小标签，问题文字居中省略，附件显示为带回形针的文件名标签（多个时「+N」），重复发送在气泡下方与时间并列「已重发 N 次」；用户摘要气泡显示完整问题（最多 4 行）和全部附件名。被折叠的 pi 回复与随后展开的同一轮回复共用一个头像和名称。展开一轮里**其中一条**时，这一轮剩余的消息会重新合成一个摘要行（`buildCollapsedGroups` 把展开项 flush 出去，后面的同角色消息另起一组），那一行**不再重复角色名**——身份已由被展开消息的头部提供；否则同一轮会出现两条 `pi`，看起来像两轮。没有正文、思考、工具或错误的空回复（如中断的重试）在折叠区和完整视图都不显示，也不打断重复问题的合并。工具次数、思考和附件统计放在悬停说明，不再单独占一行；没有正文时用统计作为摘要。整行可点击或键盘展开，完整内容与搜索定位保留。
- 长历史的折叠摘要也参与惰性窗口化，首次加载先用等高占位；视口附近才挂载摘要。占位保留消息定位，搜索、展开与问题跳转仍可恢复完整内容。
- 整列只有一种纵向节奏：同一回复内 `.md p` 段间距 = 相邻 `.msg-text` 块间距 = 10px（文档 4.1）。此前段内是 12px、块间是 10px，长回复里两种节奏并存。
- 时间分隔行（`.time-gap`）上下留白 10 / 12px，共约 38px：它只是一条 1px 细线加时间，分段已由细线表达，不再用大留白配送（原 17 / 22px 叠上相邻消息边距后每处吃掉 55px，长对话被切成一段段）。分隔行前后的 `.msg` 上边距归零，避免叠加。
- 命令行末尾的展开箭头同样紧贴内容（耗时之后），不用 `margin-left: auto` 推到右端：用户读完命令和耗时视线就停了，几十个字符外的提示等于看不见。箭头仍只在展开或悬停时出现，收起态的行首行尾不因鼠标移动而跳动。
- 折叠行末尾的展开箭头（`>`）紧贴文字结尾，不推到容器最右边：预览不能撑满整行宽度，否则用户视线停在省略号上就看不到几十个字符外还有一个可点击的提示。预览仍受行宽约束并省略，箭头不会被挤出可视区。

- 对话里的 Markdown 标题末尾的括号说明（如「(不用你回答)」）显示为同行灰色小字副标题；紧贴在标题上方的分割线不显示，其余分割线为 1px 浅色。
- 顶栏会话标题去掉「skill:」前缀（显示「grill-with-docs · 问题」）；空间不足时分支标签和项目名先收缩，标题优先保留。

### 4.2 过程列表与命令组（3a / 27a / 29a）
- #167：历史正文取消折叠不应禁用过程分组；同一轮两段正文之间的连续思考和命令跨消息合并为一行统计，数量与思考用时按真实步骤累计。点击或 Enter／Space 展开全部步骤，再点收起；搜索与工具定位自动展开目标。用户消息、正文、编辑、错误及事件边界仍隔离，不吞正文、不合并不同请求。
- 已结束的命令输出自动排版，不显示原始输出切换：同一文件连续匹配共用一个路径标题，代码按紧凑行展示高亮正文，不展示源码行号；默认展示 3 条匹配、混合日志最多 3 行。按钮按当前视图实际隐藏内容决定是否出现，展开显示全部内容且取消固定高度限制，收起恢复预览；明确带行号的搜索结果分条展示文件位置与正文，Markdown 片段排版、已知代码语言高亮；明确单文件 cat/head/tail/sed 读取按扩展名展示文档或代码。混合输出仅在确认末尾为单文件带行号搜索时分段：前部作为「执行日志」，末尾匹配记录作为「代码匹配」，保持顺序；支持 Python heredoc 后接搜索，脚本正文中的搜索字符串不作命令解析。来源不明、运行中或失败的输出保持终端原文；超过 100KB 不自动排版。合法完整 JSON 按原始 token 缩进，保留大整数精度。代码预览移除共同前导缩进并取消额外左内边距，保留相对缩进和正文中的数字。复制始终取完整原文，自动排版不执行代码、不增加模型调用。
- 展开的命令首行左侧显示装饰性 `>` 提示符，独立占一列，多行正文对齐；提示符不参与复制和屏幕阅读。命令使用 Bash 语法高亮；输出按终端日志展示原始缩进与空行，不添加行号和顶部总行数，路径采用普通文字颜色；明确带 `-n`／`--line-number` 的 rg/grep 搜索结果，隐藏原生源码行号及冒号；命令输出经管道 rg/grep -n 过滤产生的日志编号也隐藏，正文测试数量、耗时和其他数值保留，不新增编号栏，不改变原始缩进或复制内容；AssertionError／TypeError 等错误标题及错误码用红色，堆栈保持中性色。Git diff stat 的加减符号与增删统计分别用绿／红色。普通日志不强行按代码解析，错误优先显示错误色；颜色只辅助阅读，不改变复制、换行、搜索和执行。配色跟随应用浅深主题。
- 读取结果使用与改动汇总相同的卡片外观。单文件不再叠加读取组和文件行，直接显示文件预览卡；多文件组展开后直接列卡片。卡片头只展示一次路径、状态及操作，正文不重复路径；图片在随内容宽度收缩的浅色预览底板内等比显示，底板靠左、不铺满整行；高度上限为视口的 65%、最多 560px，窄屏不溢出；图片下载放在底板底部右侧。读取卡片移除「下载完整输出」，成功图片读取的纯 `Read image file [...]` 提示及其 `[Image: original …]` 尺寸／坐标缩放说明不再展示，也不显示对应的「文件内容·仅供模型读取」标题，其他文本与错误继续保留。
- 两段正文之间的思考、bash、read、grep 合成一个过程列表，每项一行，**不套卡片外框、不需要边框就能读**（29a）：行间不用分隔线，靠缩进、等宽字和状态点区分。不再混用灰底单行、卡片和独立卡片。跨消息合并：只含这些步骤的后续消息并入上一组；下一条回复开头的思考/步骤也接在上一组末尾，其正文另起。编辑、其他工具、错误/中断消息和历史折叠边界会结束列表。
- **点击查看细节**：任何一行都可用鼠标或键盘（Enter／Space）展开，细节直接落在该行下面（不再另开弹窗或侧栏），再点收起；跳转、搜索与「pi:reveal-tool」会自动展开并定位。收起时行仍挂载。
- 思考用时满 60 秒改写为「1m 17s」，满 1 小时为「1h 2m」（思考行、工具组标题、右栏步骤一致）。
- 执行步骤文案统一英文（中文界面也一样）：「Thought for 2s」、进行中「Thinking · 6s」、「Ran 4 commands」「Running N commands」、「42 lines」「2 commands」。用户消息、回复正文与其余界面文案保持中文。
- **工具组（Tool Group）**：含 bash/read/grep 的过程列表按状态分两种形态，都不加外框（29a）。
  - 已结束且无失败、且收起时：没有组标题、没有边框，只在过程行位置留一行灰色统计（「Ran 3 commands · Thought 3s」，可点开查看步骤），读起来像两段正文之间的一句说明。
  - 运行中或用户展开时：显示一行组标题（「› Ran 3 commands · Thought 3s」，可再加「Read N files」「N searches」），右侧状态为绿色转圈「Running」（`--progress-text`）、带可访问说明的小绿勾（all passed）或「未执行」。展开时步骤行直接跟在标题下面。
  - **失败的 bash 调用不进入对话记录**（2026-11 用户决定，选 A）：命令失败后模型会自己换做法继续推进，`✗ exit 1` 留在时间线上既占视觉噪音，又让人误以为任务没做完。过滤发生在渲染前（`Message.tsx` 的 bash 分支），因此分组计数、折叠统计、本轮命令数与任务进度自然一致，不会出现「显示 3 条实际 4 条」。仍在运行、排队或从未执行的调用保留，它们的结论还没定。
  - 默认展开：有工具在运行或未执行；否则收起。用户点击后以用户选择为准。
  - 行：等宽 12.5–13px、无左右内边距（与正文左对齐），行间无分隔线；✓ 绿 / › 灰（思考行「Thought for Ns」）。右侧元信息：成功为实测用时（≥0.1s），否则为行数。
  - 只有思考、没有工具的列表同样不加外框；思考行不再用浅灰底，只用灰色斜体正文缩进。
- 思考行：完成时为「› Thought for Ns」（无实测耗时显示「Thought」，悬停说明耗时未记录），点击在行下展开正文；进行中为转圈 + 蓝色「Thinking · Ns」+ 最新一行斜体灰字单行省略，计时从该行出现开始。
- 连续的 bash 调用合成一组。组标题写「Ran N commands」（只计实际渲染的命令，失败调用已过滤），展开箭头靠右。只有 1 条命令时不显示组标题。历史组收起时只在过程位置留一行统计（见上）；运行组显示组标题。
- 运行中的命令用转圈代替圆点。转圈与右侧「执行中… Ns」都使用进行中色 `--progress-text`：29a 行的成功态本来就是绿点，运行态若仍是蓝色，命令结束的一瞬间会由蓝跳绿、看起来像换了含义。运行行的转圈在 `.bash-state` 内单独上色，不改共享的 `.thinking-spinner`（思考行仍使用蓝色）。
- 运行中 bash 卡片头部改用运行灯（Claude Code 式）：7px 实心圆点，内核在 `--progress-text` 与 62% 混背景间呼吸，外圈光晕 0→3px 周期涨缩（读 `--progress-soft`），1.5s `ease-in-out` 无限循环；浅色／深色共用令牌，不写死颜色，`prefers-reduced-motion` 下静止为实心圆点。同行计时色同步使用 `--progress-text`，保持「一个颜色一个含义」：绿色＝运行中与成功，蓝色只留选中与链接。
- 运行中的命令行（#106）：右侧显示实时计时「执行中… Ns」（满 60 秒改写为「Nm Ss」，同思考行）；收起时标题旁用斜体灰字单行省略显示最新一行输出（同进行中的思考行），展开时输出区显示最后 6 行而不是前 6 行，不添加行号。
- 每条命令一行（29a）：可识别的可读名称 / 灰色等宽命令 / 右侧结果计数，例如 `models.json 50–60 行` + `sed -n 50,60p ~/.pi/agent/models.json` + `2 行`。
  - 如果命令带 `echo "=== 标题 ==="`，就用这个标题当名字，后面跟灰色等宽字体的真实命令（单行，超出部分截断）。
  - 可以识别的 `sed -n` 读取，显示文件名和行号范围。
  - 行尾变展开箭头与上一个的状态点都不额外占位：箭头只在悬停或已展开时出现。
- 去掉开头的 `cd 项目目录 &&` 和结尾的 `2>/dev/null`。展开、复制和重跑都使用完整的原命令。
- 完整命令相同的连续调用合成一行，标「试了 N 次」，显示最后一次的命令和结果。
- 命令行的头部按内容高度收缩（`align-items: center`、`min-height: 22px`）：基线对齐加 12px 箭头会把行高顶到 30px，而状态点和命令文字只占 15px，点开时头部与正文之间会多出半行空转的高度。
- 展开详情与改动汇总共用卡片外观，外框与正文左对齐，内部分「命令」「输出」两区，复制命令／复制输出分别放在对应区标题旁，底部保留终端操作；输出默认换行，不添加行号，支持切换原始行宽并在输出区横向滚动。超过 6 行的命令默认预览前 6 行，通过「展开完整命令」查看全部；复制和终端入口始终使用完整原命令，搜索跳转展开完整命令及输出。
- 展开后的完整命令按行宽换行（`white-space: pre-wrap` + `overflow-wrap: anywhere`），不横向滚动、不裁切：这是用户点开这一行要读的东西，必须能一眼读全。输出正文直接左对齐；「收起」贴左、宽度随内容，与下方左对齐的「复制命令／复制输出／在终端中打开」同一起点。
- 输出默认收起；点行展开后在统一卡片的输出区显示，不再用 `--output-bg` 色块。输出最多显示 6 行，不带行号；运行中的行与工具组一同展开。
- 展开后**只保留一份命令**：正文的 `.bash-full-command` 显示完整原命令，头部那份去掉 `cd … &&`、`2>/dev/null` 并截断到 75% 的摘要（`.bash-inline-command`）隐藏。两者同时出现时，同一条命令会以「中间一个省略号」和「完整」两种形式上下各说一遍。收起时摘要是这一行的唯一信息，继续保留。
- 组内只显示最后 8 条，上面显示「展开全部」。
- 工具组行显示 ≥0.1s 的实测用时；其他位置不到 1 秒不显示用时；没有实测数据时显示「耗时未记录」。

### 4.3 文件改动（35a）
- 已完成 Edit/Write 的行内展开复用 `ChangeSummaryCard`：文件行、增删比例与统计和轮次汇总一致，默认展示代码差异；文件行可折叠，“全部查看”打开这次调用的历史改动。代码正文与 ChangesPanel 共用 `ChangeDiff`（词级高亮、上下文折叠与截断提示），收起的工具行仍无边框。展开卡片外框与 Edit/Write 行和正文左边缘对齐，桌面及窄屏均不额外缩进，内部留白保持不变。失败与执行中的调用继续展示原始状态与尝试内容。
- 对话与代码改动遵循 [35a 设计](chat-diff-design.md)。成功改动在每轮汇总卡与独立 ChangesPanel 中显示；失败和运行中的调用保留状态。历史命令组默认收为一行，当前运行组展开。
- 面板默认本轮，支持整个分支与未提交；600px 对话列，面板最小 560px；1200px 以下使用抽屉。
- 以下旧卡片规则只用于失败详情及兼容视图。对话里的编辑/写入卡片同样遵循 29a：成功或运行中的调用是一行无边框行（状态点 · Edit/Write · 文件路径 · `+N −M`），默认在行下展示 diff（运行中随参数流式更新，完成和历史记录保持展开，可手动收起），失败调用保留卡片（容器沿用代码块那套：`1px var(--border)` 边框、`--r-md` 圆角、32px 头部栏加一条 `--border-soft` 底线、栏内条目与栏同起点、计数右对齐，与对话里的代码块观感一致）。展开箭头只在已展开时显示（由▸ 转为 ▾），悬停不出现：行首位置必须保持不动，鼠标移上去不能把「状态点 · 编辑」向另一边推。
- 标题行：操作 · 文件路径 · `+N −M` · 状态。编辑/写入行的增删数量紧跟文件路径，不显示“打开”按钮，路径不伸展填满整行；长路径缩略，为统计与操作留出空间，“更多”留在行尾。
- diff 在浅色模式下：新增行用 `--green-soft` 底，删除行用 `--red-soft` 底，行号那一栏颜色再深一档。深色模式下用对应的深色变量。
- 相邻 3 次及以上的编辑合成一个文件列表，每个文件的 diff 默认收起。

### 通用工具卡片（#45）
- 自定义/MCP 工具使用紧凑标题行：工具图标、可点击折叠的名称、状态与耗时；放大和复制参数使用带可访问名称的图标按钮。
- 简短标量参数按键值展示，复杂参数保留可滚动原文；输入区明确标为「参数」，输出区保持既有截断与展开行为。
- 完整输出下载位于卡片底部的轻量操作区，不使用突兀的默认按钮。没有文本但有输出文件时说明可下载完整结果，不展示空输出框。
- Bash、文件读取、编辑和 Codemode 专用卡片保持各自布局。窄屏标题允许名称截断，参数自动换行，所有操作可键盘访问。
- `subagent action=run` 在同一通用工具卡内按来源列出任务、排队／运行／完成／失败／取消及当前目录、搜索、读取、提交报告或整理回答动作；标题只汇总真实完成数与报告数，不伪造百分比，也不增加子代理聊天窗口。
- 完成后各来源可展开摘要、finding 类型、引用原文、关联、待确认问题、用量及截断／未核验警告。首份报告和失败／取消项默认展开。来源标题的完成状态只表示任务结束；报告内单独显示引用核验，并直接可见「只核对引用原文与指纹，不证明结论正确」的说明，不能只靠悬停。跨仓关联仍需主模型综合。摘要与证据先于根目录、核验时间和用量等元数据；原始参数与输出保留在末尾折叠区，`sources`、`inspect` 和无法解析的数据继续使用普通 JSON 工具卡。
- 来源标题使用原生按钮，支持 Enter／Space 展开收起；长任务、路径和摘录可换行。600px 以下来源动作移到下一行，finding 类型独占一行，根目录标签与完整路径分行且路径续行对齐。次级文字使用可读性足够的现有 dim 色。减少动态效果偏好关闭入场与箭头过渡，沿用现有颜色与圆角变量。

### 4.4 等待指示器（31a）
- 三个 6×6px 方块（`#EE8C7C` `#3E8FC0` `#F2BC4E`），圆角 1.5px，间距 3px，依次呼吸，周期 1.2s。
- 文字 13px，字重 500，灰色加流光（1.8s）；用时 12px 灰字。
- 位置：最后一个内容下方 8px，左边留 2px。
- 聊天运行状态文案固定使用英文（包括中文界面），计时用 sec/min，等待指示器里的停止链接为 Stop：

| 阶段 | 文案 |
|---|---|
| 已输出正文、任务仍在进行 | Working |
| 刚发出消息 | Understanding your question |
| 工具调用刚结束 | Reading command results / Reading files |
| 有思考但还没有正文 | Thinking |
| 测试或构建命令超过 4 秒 | Waiting for test results / Waiting for build results |
| 插话已送达 | Processing your direction |

- 300ms 后才出现；4 秒后显示用时；60 秒以上显示「M min SS sec · Stop」。
- 正文已输出但服务端仍报告运行时，显示 Working（流式正文和正文间的执行间隙均保留），不把正文出现当作任务结束；完成／中断后随权威运行状态消失。纯思考与普通工具执行沿用各自的运行提示；断线、重试、压缩或静默告警时由对应的状态接管。计划步骤仅按成功 plan 更新推进，不由工作提示推断完成。
- 系统开启减少动态效果时，方块和文字都静止。
- **不再使用**：「正在分析请求」「仍在思考」「响应较慢」「等待模型」，以及显示在标题行的蓝色等待状态。

### 输出截断提示（#143）
- 模型以 `length` 结束时，消息显示「模型输出达到长度上限，回答未完成」及继续／调整额度建议，保留思考与部分正文；完全空的截断回复也不得隐藏；截断消息是过程列表的合并边界，不能被前面的成功工具组吞并。复用错误提示样式及现有按钮。
- 最新且已停止的截断回复提供「调整输出额度」，打开所属输入框的模型管理，保留草稿；显示本轮实际输出 token 用量。仅已有部分正文时提供「准备继续」，点击追加普通后续消息到草稿，由用户发送，并说明不保证断点续写。只有思考或完全空内容时不推荐盲目继续，提示先提高额度或降低思考强度后重试原问题。历史提示保留，操作入口随后续消息消失。
- 当前任务显示「输出达到上限 · 回答未完成」，已完成的工具步骤保持成功；不把调用结束当作回答完成。
- 扩展页 Pi CLI 卡片（issue #151）：`cli-status` 探测的是**服务进程自己的 PATH**，与工作区无关，因此不再受 `cwd` 校验门控——之前会话切换中或 `cwd` 过期时会直接 409，卡片就显示「检测失败，请重试」，用户会误以为没装 Node。现在只有 quiesce（退出/重启中）返回 409。
- 同一张卡片必须明说「谁没找到」：Node.js / npm 已在时显示「已找到 Node.js x.y.z 与 npm a.b.c，pi CLI 需要单独安装」，并激活「安装 Pi CLI」按钮；只有真的缺 Node 时才提示去装 Node，且点名缺的是哪一个。
- 顶栏任务位（issue #150）：只有**原生 plan** 才有「第 N / M 步」。工具调用是执行细节，`task.steps` 计的是本轮每个工具组，长工具循环里会变成「第 107 / 107 步」，而右栏把同样的步骤归并成 1 个阶段——两处数字互相矛盾。没有 plan 时顶栏只显示「任务进度」，不编造位置；分段进度条同样只跟 plan 走。

### 4.6 结构化回复（4a）
- 回复里的盒线字符树（`├──` / `└──`，每行都是分支，至少 3 行）渲染为浅色结构化树：顶部「根 · 根标题 · N 个分支」，节点编号用灰色等宽字，副说明灰字，子层用左侧细线缩进。多数节点共有的 `← 本轮` 类标注只在顶部说明一次，各节点只显示与之不同的部分（黄色标签）。用户粘贴的树保持原样。保留复制原文。
- 回复中的编号问题（如 `❓ **Q1** - **标题**：问题` 或 `❓ Q25 — 问题`）即使只有一道也渲染为卡片；未编号的普通问句保留 Markdown，两个及以上 `❓` 问题仍兼容成组卡片。卡片内容为：编号、标题、问题说明；`(a) …;(b) …` 选项逐行可点（单选，再点取消）；`➡️ 推荐 (c)。理由` 的推荐项带「推荐」标记并默认选中，理由显示在选项下。没有字母选项的开放问题，推荐答案作为一个可选项（默认选中）。每张卡片最后都有「其他」行：单选圆点 + 虚线卡片内联输入框（占位「不采纳以上选项？写下你的答案或原因…」），聚焦或输入即选中；写了内容才计为已答，空内容列入「Qx 待回答」。发送时「其他」按「Qx 标题：其他 · 内容」附上（多行合成一行）。「全部采纳推荐」覆盖所有题的选择，已写的「其他」文字保留，可重新选回。卡片之间的普通段落照常显示。内联选项按分号分隔，选项正文中的 `(b)` 等引用保留为正文，不生成空选项或重复编号。 整段无分号时按空格回退：需 ≥3 个标记、字母从 `a` 依次递增，且没有选项正文以括号字母或连接词开头，否则整段只作为问题说明、仅显示推荐与其他。 逐行选项兼容 `- **A.** 选项`、`**(a)** 选项`、`A) 选项` 和 `A：选项` / `A: 选项`（兼容冒号后无空格及编号加粗）；整行加粗的 `❓ **Q1 — 标题**` 也按题号和标题解析；编号加粗不应使选项退化为普通说明、只剩推荐与其他。
- 只有最新且已结束的回复可作答。此时输入框上方出现回答栏：「已选 N / M」「Qx 待回答」、「全部采纳推荐」、「发送回答」；占位文字为「补充说明，或直接输入其他回答…」。发送内容为每题一行「Q1 标题：(c) 选项」，输入框里的文字附在最后，走普通发送流程（附件、当前文件、排队规则不变）。「全部采纳推荐」在所有推荐已选中时也必须给出可见确认（按钮短暂变为绿色「已采纳推荐」），多轮提问中新旧卡片混排时不能无反馈；带字母后缀的题号（Q1a/Q1b）保持独立答案键，不截断碰撞。回归：`tests/question-accept-test.mjs`（#100）。
- 「回到底部」是 28px 圆形箭头按钮，放在阅读列右侧留白、输入框上方，不覆盖正文和用户气泡；只在离底部超过一屏且正在向上滚动时出现，不推动输入框。文字放在悬停说明与可访问名称。

- **任务页信息层级（2026-11 重设计）**：面板顶部先给一条概览——左端状态点 + 文字（执行中／准备中／本轮已结束／Failed／Interrupted，运行中状态点用 `--progress-text` 的呼吸动画），右端「N 步 · x 项失败 · 总耗时」灰字，下面一条 3px 时长条按阶段实际耗时分配宽度（完成浅绿、进行中 `--progress-text`、失败红色），让人一眼看出这轮花在哪些阶段。
- **概览自动开合**：运行中（含出错、中断、提醒）展开；本轮结束后自动收成一行（只剩状态、计数、耗时和向下箭头），把高度让给步骤列表。读者在本轮内手动开合过后以其选择为准，换一轮重置回默认。收起态箭头朝下（展开语义），展开后转为 `收起概览`。概览不重复计划信息，也没有标题栏。

- **时长格式**：一分钟内显示 `12.3s`，一小时内 `3m 32s`，一小时后 `1h 5m`；不足 0.1s 不显示，避免出现一串 `0.0s`。

- **本轮文件**（2026-11-07 移除）：右栏任务页不再列本轮写入／修改的文件与 `+N −M`。文件从步骤记录、聊天编辑卡片和左栏 Git 改动标记查看；`web/src/task-outputs.ts` 仅保留其他界面使用，右栏不渲染。

### Secondary dialogs and previews

Node source/credential/edit forms, session-tree navigation/bookmark/content dialogs, and provider authentication use the shared focus boundary. Conditional dialogs register only while visible; reopening captures the new trigger. Escape in provider authentication closes only that topmost dialog, leaving settings underneath open. Small-screen secondary dialog fields use 16px text; action rows wrap and touch targets have at least 44px height. SQLite tables retain their own horizontal scrolling.

### Wiki 编辑问题 #109–112

正文内的目录块（`<!-- toc -->`）是阅读辅助：标签「目录」12px/600、字距 .04em、弱前景色，不当作标题；每条目录项是整行可点的链接（`display: flex`、`min-height: 26px`，满足 WCAG 2.2 指针目标 ≥24px），缩进 16px/级且落在链接上，命中区随级别变宽；层级同时用字重（一级 500、更深一级 400）与缩进表达，不靠两级几乎同色的蓝区分；「移除目录」是 chrome：12px、常驻右侧、悬停才显著，只读态隐藏。标题末尾 Enter 新建正文段落，Shift+Enter 保留标题内换行。阅读目录位于右侧「目录」页签，编辑后更新，小屏复用覆盖面板，不写入文档。表格表头与内容默认居中，状态列保持紧凑（显式 Markdown 对齐优先），列间有分隔线；表头用 `--bg-elev2` 浅灰底 + 500 字重表达层级，字号与正文一致（富文本根节点带 `.msg-text`，须显式覆盖聊天气泡表格的 12px 表头字号，否则列名会比正文更小更淡）；新插入的列按 `/table` 模板约定自动命名为「列 N」（取现有列名最大编号 +1），不留空白表头；表格不常驻操作浮栏，点击外边框选择整表（行/列结构操作走单元格右键菜单）。

### 格式刷与清除格式

Wiki 主工具栏的格式组（粗体、斜体、删除线、下划线之后）并列「格式刷」和「清除格式」两个图标按钮，窄屏随该组一起收进「更多」；小记的紧凑工具栏把这两个按钮放在「更多」展开区内。选中文字的浮动浮层仍然只有「问 pi」，不加入这两个入口。回归：`tests/format-painter-test.mjs` 与 `tests/unit/format-painter.test.ts`，行为规则与取舍见 `docs/adr/0008-format-painter.md`。

-   **单次与连续**：单击格式刷采样并只应用一次，应用后自动退出；双击进入连续模式，按钮保持按下态，可连续刷多处，Esc 或再次点击退出。
-   **采样为空**：光标所在块没有文字时，按钮置灰，悬停说明「光标所在位置没有可复制的格式」，不进入模式——不做静默无反应。
-   **整块替换**：刷到段落时，源块的块级属性（对齐、行距）整体替换目标的块级属性，源块没有的属性会从目标上移除。不做合并。
-   **块类型双向复制**：正文、标题与不同标题级别之间双向应用；列表与表格单元格保留结构。普通正文可作为清除目标额外格式的来源。
-   **多块选区**：逐块应用样式，并将正文／标题统一为来源类型。
-   **只刷可持久化格式**：采样结果经过 `cleanStyle` 的白名单过滤，白名单外的样式（如 `letter-spacing`、`margin`）不会应用，避免刷完后存盘丢失。采样还会减去孤立普通段落的基线，不把 `getComputedStyle` 的解析默认值印到内容上。
-   **清除格式**：同时清行内格式与块级样式，并移除格式标记。
