## 最新视觉基准：2026-10-19 语雀桌面参考

本节替代下文旧的暖灰、MiSans 和浮起导航样式。Web 与 Electron 共用：默认纯白正文、浅灰侧栏、中性灰选中行、细分隔线。浅色令牌为正文 #FFFFFF、侧栏 #FAFAFA、选中行 #EFEFEF、边框 #ECECEC、正文文字 #333333、标题 #262626。主操作使用独立 action 绿色 #00875A，链接与计数保留蓝色。默认主题显示名改为「简白」，存储键仍为 warm；其他色调与深色选择保留。

- 字体沿用 2026-10-20 实测语雀页面的回退顺序，但内置字体已排到系统字体之前：`--sans`／`--document-font`／`--document-title-font` 依次是内置 UI SC、内置 UI Symbols、内置 PI Emoji（Noto Color Emoji），其后才是 -apple-system、system-ui、Segoe UI、Roboto、PingFang SC、Hiragino Sans GB、Microsoft YaHei、Helvetica Neue、Helvetica、Arial、sans-serif；文档正文不插入 -apple-system、system-ui 或 Roboto，文档标题在 Segoe UI 后保留 Roboto。原「Chinese Quote」@font-face（`local()` 取 PingFang SC／SimSun，仅覆盖四个中文弯引号）已移除：它按平台取不同字形，而 UI SC 现在自带这四个引号。代码字体独立，`--mono` 同样是内置 JetBrains Mono → UI SC → UI Symbols → PI Emoji 优先。
- 主界面保留贴边三栏、窗口按钮避让、拖动区及功能入口；导航改为小圆角平面按钮，文件、项目、会话选中项使用灰底，不使用浮起阴影。
- Wiki、小记和聊天 Markdown 正文采用 15px / 26.1px、0.12px 字间距、400 字重，强调文字 700。文档标题 36px / 50.004px、700；正文 H1 28px / 36px、H2 24px / 32px、H3 20px / 28px，均为 700。标题不使用负字间距；窄屏保持同一文字尺度，通过换行适配。Markdown 段落间距 12px，不移植语雀页面的目录预留空间。小记源码输入采用正文比例字体，代码块保持等宽。
- Wiki 正文和右侧大纲为白色，文件栏为浅灰色。大纲单行省略并保留完整标题提示；目录与问 pi 页签、键盘切换和草稿继续保留。
- 大纲以文档标题为根节点，H1–H6 按实际父子关系组成树（跳级标题归到最近的较浅标题）。每个分支可独立折叠；顶部提供隐藏／显示条目和全部折叠／展开，隐藏后保留工具栏以便恢复。正文滚动时高亮当前标题，若标题藏在折叠分支内则高亮最近的可见祖先，不强制展开。折叠操作不改变正文或光标，重名标题按 DOM 元素区分；切换文档重置折叠状态。
- 文档代码块为细边框、小圆角，长行横向滚动；元信息使用统一的弱化文字样式。表格保留内容列宽、显式对齐和状态列规则。
- Wiki 编辑细节按用户代码块与插入菜单截图：代码块显示不可复制的行号、整块折叠及纵向尺寸调整，宽版切换位于文档工具栏；控件不进入 Markdown。空段落提示「输入 / 唤起更多」。空查询插入菜单为六列图标网格，支持正文、H1–H6、无序／有序／待办、链接、代码、引用与高亮块等；输入查询后显示带说明的列表。最近使用最多三项，仅保存操作 ID，不保存文档内容。键盘支持网格方向键、Enter、Esc；代码长行保持横向滚动。
- 创建工作区和打开问 pi 使用绿色主操作。发送／停止保留此前用户指定的黑色圆形图标。保存、关闭保护和原生窗口行为不变。
- Workspace 使用 240px 单栏导航与顶部切换浮层，详见下文「Workspace 项目分组」。

- 触屏指针下，历史、项目栏、文件栏开关、抽屉关闭及新对话动作的实际点击区域至少 44×44px；顶栏空间不足时只让视图页签自身横向滚动，不产生整页横向溢出。发送／停止继续使用既定尺寸。
- 覆盖式文件抽屉只在握持区显示一个「文件」标题，面板内不再重复标题；新建、刷新、更多与关闭操作保留。常驻桌面文件栏标题不变。
- 无任务且无输出时隐藏右栏下方占位；运行进度、已有结果与输出保留。
- 正文 15px/1.74，界面 13px，辅助文字 12px；字体沿用上述语雀回退。段距 12px、列表缩进 24px、条目间距 4px；行内代码 .9em、内边距 1px 4px、小圆角轻灰底。
- 行内代码必须落在正文基线上，不撑高所在行：`.9em` 缩小后再用 `line-height: inherit` 让它的行盒与正文行高一致，配合 `vertical-align: baseline`（不用 `middle`，否则与中文基线错位）。上下各 1px 内边距保留，但不得因此让含行内代码的段落比纯文字段落高出哪怕一行——判断标准是同一段落里混排行内代码时行距保持不变。
- 普通文字与有效背景对比度至少 4.5:1，大号文字和关键非文本图形至少 3:1；禁用控件除外。链接使用独立前景令牌，小字号新增／删除统计可使用状态色与正文色的受控混合，不改变状态图标和 diff 背景语义。五种外观均按实际表面验收。
- 自动裸链接遇到成对 Markdown 强调定界符时，定界符不得进入显示文字或 href，并恢复对应强调样式；中文标点、中文路径和显式 Markdown 链接继续沿用现有边界规则。

- 本轮仅调整主聊天页，不重新设计 Wiki、小记或文件编辑器；不改变聊天、附件、保存和协议逻辑。

## 1. 设计令牌

所有颜色和圆角只能通过 CSS 变量使用，组件里不写十六进制颜色（终端 ANSI 调色板和第三方渲染器配置除外，见 1.4）。

### 增删差异配色

增删行在所有外观下采用深绿／深红实色底，配浅色文字：新增背景 `--diff-add-bg`（#14532D），删除背景 `--diff-del-bg`（#7F1D1D），文字分别为 `--diff-add-fg`（#F0FDF4）和 `--diff-del-fg`（#FFF1F2）。词级变化使用 #166534／#991B1B 的独立底色；保留行号和加减号。适用于工具编辑卡、Git 差异、文件差异、对话改动面板和 Wiki 改动记录。增删行内语法文字统一使用对应浅色前景，避免普通浅色主题的语法色落在深底上；未变行沿用原语法配色。成功／错误等通用状态色不变。

### 1.1 颜色

| 变量 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--accent` | `#008AC4` | `#52B5E5` | 选中状态、链接、开关 |
| `--accent-soft` | `#E0F3FC` | `#203A49` | 开关打开时的底色（如「π 对话」按钮） |
| `--green` / `--green-soft` | `#12A453` / `#E6F4EA` | `#79C68E` / `#243C2B` | 完成、成功 ✓、diff 新增行 |
| `--red` / `--red-soft` | `#DC4848` / `#FBE9E7` | `#EF9689` / `#452B29` | 失败、中断 ✗、diff 删除行、危险操作 |
| `--yellow` | `#F2BC4E` | `#EDC765` | 改动数、待发标签等黄色语义的底色来源 |
| `--progress-text` / `--progress-soft` | `#0E7C36` / `#E4F7E9` | `#79C68E` / `#243C2B` | 绿色「进行中」指示色：左栏会话运行点、任务面板、计划步骤与进度条；聊天过程组使用中性流光例外。浅色取比 `--green` 更深的绿（`--green` 在暖白侧栏上只有 3.1:1，6px 圆点看不清；`#0E7C36` 为 5.1:1，与旧黄色持平） |
| `--yellow-fg` / `--yellow-bg` | `#8A5A00` / `#FDF1D6` | `#EDC765` / `#463C22` | 改动数、待发标签、警告与「工作中」文字 |
| `--bg` | `#F6F5F2` | `#17191D` | 窗口背景 |
| `--bubble-bg` | `#F1EEEA` | `#2C3037` | 用户消息气泡 |
| `--output-bg` | `oklch(0.97 0.003 80)` | `#202329` | 命令输出、代码块 |

**规则**
- 一种颜色只有一个含义：蓝色表示选中或链接，绿色表示运行中与成功，红色表示失败，黄色表示有改动或待发。进行中的指示使用 `--progress-text`（任务面板、计划步骤与左栏运行点），聊天过程组按上文使用中性灰白流光；不得再用 `--accent` 或 `--yellow-fg` 表示运行中。
- 界面不使用紫色。珊瑚色 `#EE8C7C` 只出现在图标里。
- Git 标签使用绿色数量徽标（green-soft 背景、green 文字）；顶栏移除独立「改动」按钮。文件栏标题与目录行不展示改动数量，分支名在状态栏显示；对话内改动汇总及快捷键入口保留。
- 每个基础颜色变量只定义一次：浅色在 `:root`，深色在 `:root[data-appearance="dark"]`，不在后面重复覆盖。

### 1.1a 背景色调（设置 → 外观）

五种底色：1a 暖白（默认，即上表浅色）、1b 雾蓝、1c 鼠尾草、1d 燕麦、1e 石墨。只改变底色与中性色（`--bg`、`--bg-elev(2)`、`--border(-soft)`、`--text*`、`--heading`、`--bubble-bg`、`--output-bg`、`--input-border`、`--sidebar-bg`、`--row-active`），蓝色强调色和状态色不变。

- 1e 石墨就是深色外观：`data-appearance="dark"` 的唯一实现；1a–1d 为 `data-appearance="light"` 加 `data-theme`。`<html>` 上始终同时有两者。
- 浅色色调在 `:root[data-theme="…"]` 中各定义一次；设置页预览色块用同名 `.theme-swatch[data-theme="…"]` 重声明令牌（检查脚本只放行这两种选择器）。
- 「跟随系统深浅色」：系统深色时用石墨，浅色时用最近选择的浅色色调（从石墨切回时用暖白）；开启后石墨卡片置灰不可选。
- 存储：`pi-harness:theme`、`pi-harness:theme-follow`；旧 `pi-harness:appearance`（light/dark/system）只读一次迁移。
- 组件不写死中性灰：表面、边框、次要文字一律用上述令牌，否则换色调时会漏改。

### 1.2 圆角

| 变量 | 值 | 用于 |
|---|---|---|
| `--r-sm` | 6px | 按钮、图标按钮、列表项、标签 |
| `--r-md` | 8px | 输入框、卡片、代码块、命令组 |
| `--r-lg` | 12px | 弹窗、设置窗口 |

圆点状态指示使用 50%；开关轨道使用 `--r-switch`。词级 diff 高亮使用 `--r-diff-word`（2px，内容专用）。其余圆角使用上表三个令牌；`0` 用于直角，`inherit` 只用于继承父元素圆角。

### 1.3 字体
- 界面与正文使用「最新视觉基准」中的语雀字体回退。
- 命令、路径、版本号、代码用本地 JetBrains Mono，关闭连字；依次回落到 Cascadia Mono、SF Mono、Menlo、Consolas。
- 正文 15px，行高按文字体系分开：西文 1.74，中文（汉字／假名／谚文为主的段落）1.68。拉丁字母有升部降部，1.74 两行之间留出的白刚好当呼吸带；汉字占满字身框，同样的 1.74 在纯中文段落里读起来是行距松散、段落被撑开，长中文回复尤其明显。判断按文本**内容**而不是界面语言（中文界面照样会渲染英文回复），由 `web/src/text-script.ts` 的 `isCjkDominant()` 给出，阈值 0.6；代码围栏先被剔除，`agent_runtime.py` 这类标识符算一个词而不按字母数计入，否则一句中文夹文件名会被误判成西文。混排段落保持 1.74：一段里中英交替本来就会产生混合行距，收紧只会挤到英文词。界面 13px，辅助文字 12px；状态栏 11px。

### 1.4 允许写死颜色的地方
- 终端 ANSI 调色板（`--term-*`，光标使用 `--accent`）。
- Mermaid 等第三方渲染器配置读取 CSS 变量。独立代码配色（`--file-code-*`、`--wiki-code-*`、`.hljs-*`）可以定义内容色板，关键字使用蓝色系。
- 文字高亮色板（`remark-text-highlight` / `.fp-highlight-*`）。这是用户可选的内容颜色，不属于界面颜色。
- 窗口红绿灯使用 `--tl-close`／`--tl-minimize`／`--tl-maximize`／`--tl-glyph` 令牌（悬停与键盘焦点不再改变底色）。深色浮层及阴影统一读取根变量。
- 深色命令输出中的 Git 状态使用 `--out-green`、`--out-yellow`、`--out-red`，与界面状态色分开。

`npm run check:design` 扫描 `web/src` 下全部 `.css`、`.ts`、`.tsx`，禁止色板及上述例外之外的十六进制颜色、RGB/HSL、颜色名和紫色 OKLCH；非令牌圆角报错并给出行号。颜色名只检查样式值，避免误报文案、路径和标识符。透明色与 `currentColor` 可用。图片转码的白底和文档高亮序列化色板属于内容处理，检查只豁免对应文件中的指定声明。`npm test` 先运行此检查。根色板只允许根选择器中的变量声明，不能通过带 `data-appearance` 的组件规则绕过检查。

## 3. 布局

### Workspace 项目分组（#53）

单栏宽 240px，顶部 Workspace 浮层承载分组管理，项目树与对话、小记同栏，设置固定底部。支持 56px 图标栏与悬停展开；沿用既有图标。具体尺寸与交互以上文「单栏导航」为准。900px 以下导航用抽屉覆盖正文。

分组标题加号打开名称弹窗，创建后选中空分组；每行更多菜单提供重命名和确认删除。无分组时仅显示新建入口，不自动创建或导入项目。沿用既有 catalog、ID、成员和选中偏好。点击 Workspace 只改变目录展示；项目和会话仍走原有切换与草稿保护。添加项目只登记目录，删除分组只移除索引。保存失败保留表单，过期版本要求重试。

## 4. 对话流

版本不一致、项目切换和后台请求等页面提示在视口中央以浮卡叠放，默认 5 秒后收起，可用 × 提前关闭，鼠标悬停或键盘聚焦期间保留。

通知：同一对话、级别和正文完全相同的可见通知合并为一条，以「×N」显示出现次数；不同对话的通知独立。重复信息通知刷新自动关闭计时，警告与错误保留到手动关闭。

### 4.1 消息
- 用户消息：靠右，`--bubble-bg`，圆角统一 `--r-md`（8px，四角一致，只有助手侧才用不对称圆角），最宽 75%、最宽 90%（≤768px 窄屏），内边距 8px × 12px，行高沿用正文 1.74 而不是单独压低；首尾 Markdown 块不额外添加外边距；时间以 10px 弱化文字放在气泡下方右对齐，间隔 4px。
- 用户气泡的宽度、内边距与圆角**只允许有一处声明**（`.msg-user > .msg-body`），后续规则只能改变窄屏断点下的宽度；旧实现同一属性被声明四次（78%／75%／90%），看似改了却由后声明的值生效，排查时极易误判。内容完全相同、中间没有回复的连续用户消息只显示一次，时间旁标「已重发 N 次」（N 为多发的次数），其余保留定位锚点（3a）。
- 折叠与展开回复的头像、pi 名称左边缘保持一致：头像 18px，头像到名称间距 8px（只使用头像右边距，不叠加 gap），名称统一 13px/600。
- pi 回复：一轮只有一行头部（18px logo · pi · 时间，时间紧跟 pi），模型名以中性胶囊显示在名称与时间之间，同时保留时间的悬停说明；正文不加气泡，和过程列表左对齐在同一列。
- 模型错误：单条显示为随文字收缩的浅红提示行，不铺满正文列；同一轮中相邻、内容完全相同且没有正文或工具的错误合并为一条，右侧以「×N」显示总次数。不同错误、正文/工具、用户消息及时间分隔打断合并；原始消息与定位锚点保留。
- system 消息是系统提示词快照，不在聊天列表展示；原始会话数据保留。
- 消息节奏（29b / 29d）：消息盒**没有下内边距**，间距只有一条 `margin-top`，量的是盒子与盒子之间（旧实现 padding 14px 叠 margin，写着 14px 实际读出 28px）。轮与轮之间 36px、用户问题前 28px；上一条回复以正文收尾、下一条回复另起时同样是 36px（原实现只有 21px，比回复内部 10px 的头部间距都不成立，视觉上两段回复粘在一起）。继续上一条的回复（`msg-continuation`，无头部）14px；首条消息不加间距，列表 padding 已有留白。
- 一次连续执行（29d / 29e）：一轮里「句子 → 命令 → 句子 → 读取」是一条连续流，每一段距上一段 **10px**（两个过程块相邻时 4px），只有真正的轮与轮之间才是 36 / 28px。否则会出现「已运行 2 条命令」与「已读取 1 个文件」之间空出 36px 的断档，把一次连续工作切成几段。
  - 实现要点（踩过的坑）：① 消息外固定套两层 LazyMount 包装（`.messages > div > div > .msg`）；② `:is()` 取参数里**最高**的特异性，写 `:root … :is(.messages > *, …)` 实际只得 1 个类，与基础 `.msg` 打平而被后者赢；③ 不要在间距规则上使用 `!important`——之前 continuation 上的一条 `!important` 静默压掉了后面所有间距规则，导致 36px 断档反复出现。现在的写法是显式层级 + 额外 `.msg` 令牌，禁用 `!important`。
  - system 分隔线上下各 34px，负责把「已加载系统提示」两侧的两个轮次分开。
- 回复内部排版（29f）：`.msg-text` 用 `display: flow-root`，把末段图块的 12px 外边距收进盒子内——否则它会“穿透”盒子叠到下一个间距上，10px 实际读成 20px（标题、单行段落后面都能看到）。首/末图块的边距归零必须用 **8 个类**的写法才压得过段落规则 `.view-pane .main .msg-assistant .msg-text .md p`（6 个类），否则回复正文永远比头部低 12px。回复内相邻两个文本块之间 10px，和一轮里其余间距同一个刻度；`margin-top` 只有一条声明，不再用多条同选择器规则叠出最终值。
- 折叠摘要行沿用同一套行结构：无左边框、无圆角、无底色，头像/名称 · 预览 · 时间，与展开的消息同一列对齐；悬停只变文字颜色。
- 回复头部：头像、pi、时间与「折叠」按钮同一行，行高固定 22px。折叠按钮只在悬停、键盘聚焦或触屏（无 hover）时出现，出现与隐藏不改变高度，所以正文起始位置不会跳动。
- 过程说明：工具调用前后的短句（少于 40 字，说的是下一步要检查、读取或修改什么），用 12.5px 灰字。结论和要点保持正文样式。
- 长历史摘要每组保持单行，并沿用正常消息流的形状：用户摘要是靠右的单行气泡 + 时间；pi 摘要是 logo · pi · 时间 · 灰色预览；system 摘要同样是分隔线。用户摘要不显示附件原文（`<file …>` 包装）：技能显示为 `/名称` 蓝色等宽小标签，问题文字居中省略，附件显示为带回形针的文件名标签（多个时「+N」），重复发送在气泡下方与时间并列「已重发 N 次」；用户摘要气泡显示完整问题（最多 4 行）和全部附件名。被折叠的 pi 回复与随后展开的同一轮回复共用一个头像和名称。展开一轮里**其中一条**时，这一轮剩余的消息会重新合成一个摘要行（`buildCollapsedGroups` 把展开项 flush 出去，后面的同角色消息另起一组），那一行**不再重复角色名**——身份已由被展开消息的头部提供；否则同一轮会出现两条 `pi`，看起来像两轮。没有正文、思考、工具或错误的空回复（如中断的重试）在折叠区和完整视图都不显示，也不打断重复问题的合并。工具次数、思考和附件统计放在悬停说明，不再单独占一行；没有正文时用统计作为摘要。整行可点击或键盘展开，完整内容与搜索定位保留。
- 长历史的折叠摘要也参与惰性窗口化，首次加载先用等高占位；视口附近才挂载摘要。占位保留消息定位，搜索、展开与问题跳转仍可恢复完整内容。
- 整列只有一种纵向节奏：同一回复内 `.md p` 段间距 = 相邻 `.msg-text` 块间距 = 10px（文档 4.1）。此前段内是 12px、块间是 10px，长回复里两种节奏并存。
- 时间分隔行（`.time-gap`）上下留白 10 / 12px，共约 38px：它只是一条 1px 细线加时间，分段已由细线表达，不再用大留白配送（原 17 / 22px 叠上相邻消息边距后每处吃掉 55px，长对话被切成一段段）。分隔行前后的 `.msg` 上边距归零，避免叠加。
- 命令行末尾的展开箭头同样紧贴内容（耗时之后），不用 `margin-left: auto` 推到右端：用户读完命令和耗时视线就停了，几十个字符外的提示等于看不见。箭头仍只在展开或悬停时出现，收起态的行首行尾不因鼠标移动而跳动。
- 折叠行末尾的展开箭头（`>`）紧贴文字结尾，不推到容器最右边：预览不能撑满整行宽度，否则用户视线停在省略号上就看不到几十个字符外还有一个可点击的提示。预览仍受行宽约束并省略，箭头不会被挤出可视区。

- 对话里的 Markdown 标题末尾的括号说明（如「(不用你回答)」）显示为同行灰色小字副标题；紧贴在标题上方的分割线不显示，其余分割线为 1px 浅色。
- 顶栏会话标题去掉「skill:」前缀（显示「grill-with-docs · 问题」）；空间不足时分支标签和项目名先收缩，标题优先保留。

### 执行 Trace

顶栏「Trace」与 `/trace` 打开当前会话的执行 Trace 弹窗。概览展示耗时卡片和可筛选轨道的时间线，详情视图聚焦选中区间；模型请求显示关键里程碑与本次运行的宿主事件统计。离线 HTML 先列运行概览与静态时间线，再提供可展开的会话正文。左侧按时间列出本轮及持久化历史 run，支持按 run、模型、工具和状态筛选；右侧展示总运行、模型、工具、宿主及未归因时间的聚合卡片，模型／工具／宿主三条时间线，以及 provider 请求和工具调度明细。运行中每 2 秒刷新，手动刷新和关闭按钮均有可访问名称。截断、归属不明确或未采集的指标必须显示状态，不能用零值代替；服务重启前未闭合的 run 显示 `interrupted`。界面明确提示数据只含 metadata、不含消息正文，但并非匿名。弹窗使用主题表面、边框、状态色和圆角令牌，窄屏改为上下布局并保留独立滚动区。标题栏与 `/trace-export` 可下载包含 transcript 和 Trace 的无脚本静态 HTML，也可通过 `/trace-export json` 仅下载非匿名的 metadata JSON。

### 4.2 过程列表与命令组（3a / 27a / 29a）
- #167：历史正文取消折叠不应禁用过程分组；同一轮两段正文之间的连续思考和命令跨消息合并为一行统计，数量与思考用时按真实步骤累计。点击或 Enter／Space 展开全部步骤，再点收起；搜索与工具定位自动展开目标。用户消息、正文、编辑、错误及事件边界仍隔离，不吞正文、不合并不同请求。

  - 已结束且无失败、且收起时：没有边框，只在过程行位置留一行「[终端图标] 运行了命令」（GPT Desktop 式，bash-group-codex-style）：圆角方框终端图标与文案使用中灰实色，不显示右箭头，可点开查看步骤。收起态 icon 外框为 15×15px、内部符号为 10×10px，与文字高度协调；浅色基准按参考图像素校准：文字与 icon 字形使用 `--tool-text`（#999999），icon 边框使用 `--text-faint` 的 34.3% 混透明色（白底约 #CECECE）；其他主题沿用同一比例。**所有命令组都不带计数**（含与思考/读取/搜索混合的组）；收起时不附加 Thought 用时，混合组仅保留读取／搜索附加段。跨消息合并仍按 #167（合并为一个组，展开行数累计）。

  - 行：组头与命令摘要固定使用 `--command-font`（Mac 为 SF Pro Text／PingFang SC，备选 Inter／Microsoft YaHei）、14px／20px、400 字重、0 字距；标题与命令均使用 `--tool-text`（浅色 #999999）。命令行无独立卡片底色，行间无分隔线。成功的 bash 行以圆角方框终端小图标（`.bash-row-icon`）开头（替代绿 ✓，bash-group-codex-style），后接命令摘要，不显示「运行命令」标题、右侧耗时／行数；行尾箭头常驻占位、只在悬停／键盘聚焦／已展开时淡入；运行中 / 错误 ✗ / 未执行 − 及其必要状态反馈不变。
  - 只有思考、没有工具的列表同样不加外框；思考行不再用浅灰底，只用灰色常规正文缩进。
- 思考行：进行中不显示转圈或绿灯，第一行「用时 N 秒」（英文界面「Elapsed Ns」，跟随界面语言，每秒递增）使用灰白文字流光，计时从该行出现开始；第二行可选显示最新一条适合用户阅读的摘要。状态与摘要均为 13px／400／20px、非斜体，摘要单行省略，点击展开完整思考。纯命令、路径、JSON、代码或单个技术标识符不作为摘要，此时只显示用时；完成后移除整行，不再显示「› Thought for Ns」或已完成思考正文。

- 运行中的命令沿用灰色终端图标，不显示绿色转圈或呼吸灯；右侧「执行中… Ns」与组头 Running 使用灰白文字流光。减少动态效果时显示静态灰字。
- 运行中的命令行（#106）：右侧显示实时计时「执行中… Ns」（满 60 秒改写为「Nm Ss」，同思考行）；收起时标题旁用斜体灰字单行省略显示最新一行输出（同进行中的思考行），展开时输出区显示最后 6 行而不是前 6 行，不添加行号。
- 每条命令一行（29a）：成功行的行头只有 [终端小图标] + 清洗后的命令摘要（去掉 `cd … &&`、`export … &&` 等 setup 前缀，`commandPreview`），**按行宽尾部省略**（`text-overflow: ellipsis`，不在中间拼「前 28 … 后 48」，也不把路径压成 `…/leaf`）；完整命令在悬停 title 与 Shell 卡里。成功行不显示可读名称、「运行命令 |」或右侧结果计数；运行中、失败与未执行行保留必要的状态和计数。
  - 行尾展开箭头（`›`／展开后 `⌄`）对**所有**行都常驻占位、用 `opacity` 淡入，成功行也一样；触屏（无 hover）不常显。出现与隐藏不改变文字位置。点击或键盘 Enter／Space 仍可展开详情。

- 完整命令相同的连续调用合成一行，标「试了 N 次」，显示最后一次的命令和结果。
- 命令行的头部按内容高度收缩（`align-items: center`、`min-height: 22px`）：基线对齐加 12px 箭头会把行高顶到 30px，而状态点和命令文字只占 15px，点开时头部与正文之间会多出半行空转的高度。

- Shell 命令按行宽换行（`white-space: pre-wrap` + `overflow-wrap: anywhere`）；**长命令（原命令 >6 行）默认截断为 6 行预览**（`.bash-request-code.clamped` 的 `-webkit-line-clamp`），下方「展开其余 N 行／收起」切换（`requestOpen`，N 为隐藏行数），搜索 reveal 自动展开；复制始终取完整原命令。输出正文左对齐，「展开/收起」贴左。

- 行头命令是清洗后的单行摘要（扫读用），Shell 卡以真实 Bash 代码完整呈现原命令——两者形式不同，不构成重复。收起时该行只显示这份命令摘要。
- 组内只显示最后 8 条，上面显示「展开全部」。
- 非成功的工具组行保留 ≥0.1s 的实测用时或必要状态；成功 bash 行不显示用时和行数。其他位置不到 1 秒不显示用时；需要展示耗时但没有实测数据时显示「耗时未记录」。

### 通用工具卡片（#45）

### 4.4 等待指示器（31a）
- 纯文字指示，不再显示彩色方块（2026-11-24 用户决定移除）。
- 文字 13px，字重 500，灰色加流光（1.8s）；用时 12px 灰字。
- 位置：最后一个内容下方 8px，左边留 2px。
- **Codex 式运行反馈（remove-wait-status-live-running）**：运行中的工具由其**流式行**自身表达（转圈 + 最新输出行 + 实时计时，运行组自动展开），等待指示器**不再叙述工具阶段**（去掉「Reading command results / Reading files / Waiting for test results / Waiting for build results」）。指示器只填补**非工具静默空档**——刚发出消息、空思考、已输出正文但任务仍在进行——统一为一个极简 **Thinking** 阶段（不再区分 Understanding/Working/Steer 文案）。
- 聊天运行状态文案固定使用英文（包括中文界面），计时用 sec/min，等待指示器里的停止链接为 Stop。可见思考沿用思考行自身的「用时 N 秒 / Elapsed Ns」，不另起等待指示器。

- 300ms 后才出现；4 秒后显示用时；60 秒以上显示「M min SS sec · Stop」。
- 正文已输出但服务端仍报告运行时，显示极简 Thinking（流式正文和正文间的执行间隙均保留），不把正文出现当作任务结束；完成／中断后随权威运行状态消失。工具执行由流式行表达，工具结果后的空档不再显示等待文案；断线、重试、压缩或静默告警时由对应的状态接管。计划步骤仅按成功 plan 更新推进，不由工作提示推断完成。
- 系统开启减少动态效果时，文字流光静止。
- **不再使用**：「正在分析请求」「仍在思考」「响应较慢」「等待模型」，以及显示在标题行的蓝色等待状态。

- 复用恢复状态行显示「正在中止重复输出」「检测到重复，正在恢复 1/1」「输出截断，正在续接 1/2」；活动恢复期间停止按钮持续可用，断线时禁用，不同时显示静默或普通等待提示。
- 自动恢复消息使用轻量事件行，跳过问题导航、编辑重问和用户轮次统计；保留先前工具结果，不伪装为用户重新发送原问题。
- 最终停止显示次数耗尽、空响应、无法确认工具状态、取消或恢复失败的具体原因；刷新恢复状态但不自动重启任务。

### 输出截断提示（#143）
- 模型以 `length` 结束时，消息显示「模型输出达到长度上限，回答未完成」及继续／调整额度建议，保留思考与部分正文；完全空的截断回复也不得隐藏；截断消息是过程列表的合并边界，不能被前面的成功工具组吞并。复用错误提示样式及现有按钮。
- 正常正文或只有思考的截断最多自动续接两次，连续续接仍耗尽后停止。最终最新且已停止的截断回复只显示自动恢复结果与本轮实际输出 token 用量，不提供调整额度入口。仅已有部分正文时提供「准备继续」，点击追加普通后续消息到草稿，由用户发送，并说明不保证断点续写。完全空内容或没有正文及思考时不盲目自动续接，提示重试。历史提示保留，操作入口随后续消息消失。
- 当前任务显示「输出达到上限 · 回答未完成」，已完成的工具步骤保持成功；不把调用结束当作回答完成。
- 扩展页 Pi CLI 卡片（issue #151）：`cli-status` 探测的是**服务进程自己的 PATH**，与工作区无关，因此不再受 `cwd` 校验门控——之前会话切换中或 `cwd` 过期时会直接 409，卡片就显示「检测失败，请重试」，用户会误以为没装 Node。现在只有 quiesce（退出/重启中）返回 409。
- 同一张卡片必须明说「谁没找到」：Node.js / npm 已在时显示「已找到 Node.js x.y.z 与 npm a.b.c，pi CLI 需要单独安装」，并激活「安装 Pi CLI」按钮；只有真的缺 Node 时才提示去装 Node，且点名缺的是哪一个。
- 顶栏任务位（issue #150）：只有**原生 plan** 才有「第 N / M 步」。工具调用是执行细节，`task.steps` 计的是本轮每个工具组，长工具循环里会变成「第 107 / 107 步」，而右栏把同样的步骤归并成 1 个阶段——两处数字互相矛盾。没有 plan 时顶栏只显示「任务进度」，不编造位置；分段进度条同样只跟 plan 走。

### 4.6 结构化回复（4a）
- 回复里的盒线字符树（`├──` / `└──`，每行都是分支，至少 3 行）渲染为浅色结构化树：顶部「根 · 根标题 · N 个分支」，节点编号用灰色等宽字，副说明灰字，子层用左侧细线缩进。多数节点共有的 `← 本轮` 类标注只在顶部说明一次，各节点只显示与之不同的部分（黄色标签）。用户粘贴的树保持原样。保留复制原文。
- 回复中的编号问题（如 `❓ **Q1** - **标题**：问题` 或 `❓ Q25 — 问题`）即使只有一道也渲染为卡片；未编号的普通问句保留 Markdown，两个及以上 `❓` 问题仍兼容成组卡片。卡片内容为：编号、标题、问题说明；`(a) …;(b) …` 选项逐行可点（单选，再点取消）；`➡️ 推荐 (c)。理由` 的推荐项带「推荐」标记并默认选中，理由显示在选项下。没有字母选项的开放问题，推荐答案作为一个可选项（默认选中）。每张卡片最后都有「其他」行：单选圆点 + 虚线卡片内联输入框（占位「不采纳以上选项？写下你的答案或原因…」），聚焦或输入即选中；写了内容才计为已答，空内容列入「Qx 待回答」。发送时「其他」按「Qx 标题：其他 · 内容」附上（多行合成一行）。「全部采纳推荐」覆盖所有题的选择，已写的「其他」文字保留，可重新选回。卡片之间的普通段落照常显示。内联选项按分号分隔，选项正文中的 `(b)` 等引用保留为正文，不生成空选项或重复编号。 整段无分号时按空格回退：需 ≥3 个标记、字母从 `a` 依次递增，且没有选项正文以括号字母或连接词开头，否则整段只作为问题说明、仅显示推荐与其他。 逐行选项兼容 `- **A.** 选项`、`**(a)** 选项`、`A) 选项` 和 `A：选项` / `A: 选项`（兼容冒号后无空格及编号加粗）；整行加粗的 `❓ **Q1 — 标题**` 也按题号和标题解析；编号加粗不应使选项退化为普通说明、只剩推荐与其他。
- 只有最新且已结束的回复可作答。此时输入框上方出现回答栏：「已选 N / M」「Qx 待回答」、「全部采纳推荐」、「发送回答」；占位文字为「补充说明，或直接输入其他回答…」。发送内容为每题一行「Q1 标题：(c) 选项」，输入框里的文字附在最后，走普通发送流程（附件、当前文件、排队规则不变）。「全部采纳推荐」在所有推荐已选中时也必须给出可见确认（按钮短暂变为绿色「已采纳推荐」），多轮提问中新旧卡片混排时不能无反馈；带字母后缀的题号（Q1a/Q1b）保持独立答案键，不截断碰撞。回归：`tests/question-accept-test.mjs`（#100）。
- 「回到底部」是 28px 圆形箭头按钮，放在阅读列右侧留白、输入框上方，不覆盖正文和用户气泡；只在离底部超过一屏且正在向上滚动时出现，不推动输入框。文字放在悬停说明与可访问名称。
- **贴底跟随**：视口停在最新内容（距离底部 24px 以内）时，流式正文、思考、工具输出以及异步渲染（代码高亮、图片解码、卡片展开）都把视口带到最新；用户自己向上翻（滚轮、拖滚动条、拖选文本、跳转旧消息、打开会话内搜索）后立即停止跟随，新内容只在下方增长，不再把人拽回去；重新滚回底部即恢复跟随。判断「离开底部」只认手势与显式跳转，不认被动布局变化（惰性窗口化换高、finalize 塌缩），否则会出现「自己滚上去又被吸回底部」。回归：`tests/chat-autoscroll-browser-test.mjs`。

## 6. 右栏
- 普通文件栏与 Wiki 目录统一使用顶部「搜索文件」入口（Cmd/Ctrl+P）、32px 树行、18px 层级缩进及中性线框文件／文件夹图标。同级预留相同的展开箭头位置，名称用界面字体。悬停／键盘聚焦使用暖灰背景，右侧引用按钮为浅黄色底；引用文件或目录只附加路径、不自动发送。触屏持续显示引用入口。
- 目录已删除、无权限或不可读取时，在对应树节点下显示原因和刷新按钮，不弹出重复通知；根目录失效提示重新选择项目。刷新成功清除错误。
- 文件标题栏提供新建文件与刷新按钮；新建在标题下输入工作区相对路径，父目录需已存在，创建空文件后打开，重名报错并保留输入。刷新保留展开状态并更新已展开目录。Wiki 文件栏共用新建入口，默认填入当前文档所在目录。
- 上半部分是文件树，下半部分是「进度 / 输出」两个平铺分区，用细分隔线隔开，不再套卡片（3a）；分区标题 11px 灰色，两区可以分别折叠。空状态只有一行说明文字，紧贴标题，不显示占位图形。
- **进度**：优先显示原生 plan 的步骤；无计划的任务显示按工具步骤归并的阶段行（同一行样式，标题下一行 10px 单行摘要，不虚构计划）；此时分区标题改为「步骤」，右侧灰字「N 步」。每步一行：绿色 ✓（进行中转圈；只有之后再无成功步骤的失败才是红 ×，探索中失败后继续推进的算成功）· 标题（模型的叙述标题原样保留；「读取 2 项」这类通用标题按实际内容改写为「读取 N 个文件 · 运行 M 条命令」）· 右侧用时（≥0.1s）；下方逐行列出涉及的文件或命令（等宽 12px，工作区内用相对路径，短的家目录路径保留 `~/`，其余只显示文件名，同名文件补上一级目录；最多 4 行，其余「还有 N 项」）。点击文件打开预览，点击命令跳到对话中的对应行。本轮已采用计划的当前步骤用 `--accent`；尚未用于本轮的历史计划中，未完成步骤统一显示待办，不高亮或自动滚动到历史当前项。完成用 `--green` ✓，失败或中断用 `--red`。历史计划仅显示「此前未完成计划」，不提示用户确认；计划工具不引入单独的审批步骤。本轮结束但计划未收尾时显示「本轮已结束 · 计划待继续」（issue #63）。
- **步骤轻量精简**：无计划步骤的文件／命令明细默认折叠，点击步骤标题展开；展开后列出该阶段**全部**命令与编辑（2026-11-07 改，不再限制 4 行、不再去重、不再有展开其余入口），命令单行省略（悬停看全文），文件行省略路径，节点均保留跳转。通用标题简化为「读取文件／修改文件／运行命令」，混合活动保留各类别，原数量摘要放在标题悬停提示中；自动生成的「运行 + 原始命令」（含截断标题）同样使用简短类别标题，避免重复展示命令；模型具体叙述标题不改写。仅当阶段全部命令为明确的 typecheck 与 build 且两者都有时显示「验证类型与构建」，其他命令不推测用途。原生计划清单与生命周期不变。
- **任务页信息层级（2026-11 重设计）**：面板顶部先给一条概览——左端状态点 + 文字（执行中／准备中／本轮已结束／Failed／Interrupted，运行中状态点用 `--progress-text` 的呼吸动画），右端「N 步 · x 项失败 · 总耗时」灰字，下面一条 3px 时长条按阶段实际耗时分配宽度（完成浅绿、进行中 `--progress-text`、失败红色），让人一眼看出这轮花在哪些阶段。
- **概览自动开合**：运行中（含出错、中断、提醒）展开；本轮结束后自动收成一行（只剩状态、计数、耗时和向下箭头），把高度让给步骤列表。读者在本轮内手动开合过后以其选择为准，换一轮重置回默认。收起态箭头朝下（展开语义），展开后转为 `收起概览`。概览不重复计划信息，也没有标题栏。
- **步骤行密度**：每步一行，左列固定 16px 状态图标（绿色 ✓、进行中旋转圆环、只有之后再无成功步骤的失败才是红 ×，均为 SVG 描边图标而非文字符号），右列标题 12.5px、`--text-dim`、悬停转正文色；行右端依次是条目数胶囊（仅 >1 时）、耗时（tabular-nums）与展开箭头。类型徽标（读取／修改／命令，均为中性灰小胶囊，修改与命令不再用强调色）挂在标题列下方第二行，不再挤在耗时旁边。步骤行内边距 7px／6px，不再有 14px 的行间距——15 步的回合现在一屏可读。
- **运行中的步骤**：不做成卡片描边加阴影，而是整个面板里**唯一**的强调块：`--progress-soft` 底色、标题 500 字重加深，右端「进行中」胶囊用 `--progress-text`，并默认展开它正在执行的条目（点击标题可折叠）。条目列表左侧一条 1px 细线对齐标题起始位置，命令 11px 等宽、单行省略。减少动态效果时圆环静止，状态文字仍显示。
- **时长格式**：一分钟内显示 `12.3s`，一小时内 `3m 32s`，一小时后 `1h 5m`；不足 0.1s 不显示，避免出现一串 `0.0s`。
- **Codemode 执行记录**：独立放在步骤之后，每次外层调用一组，仅呈现实际内部工具及模型调用。运行中默认展开，显示最后 8 条已收到记录，可展开全部已收到记录；手动折叠不被更新覆盖，结束保留展开状态，恢复历史时初始折叠。每行显示工具名、缩略参数、状态标记与已有耗时，点击跳到外层聊天卡片并展开调用页签。执行状态用英文，内部失败不改变计划状态。256 条传输上限与界面折叠分别说明；取消及缺少终态分别显示 Cancelled / Unfinished。只展示当前用户请求，完成后保留至下次请求；压缩后从持久分支恢复，顶栏入口仍保留。目标卡片已被压缩时按需打开只读历史弹窗，支持键盘关闭、焦点恢复和失败重试，不导航分支。断线不改变调用终态。详见 [设计说明](codemode-task-records-design.md)。
- **本轮文件**（2026-11-07 移除）：右栏任务页不再列本轮写入／修改的文件与 `+N −M`。文件从步骤记录、聊天编辑卡片和左栏 Git 改动标记查看；`web/src/task-outputs.ts` 仅保留其他界面使用，右栏不渲染。
- 计划完成标准为可选项；为空时，聊天计划卡片与右侧进度均不显示「完成标准」行。
- 不显示命令记录、读取记录、「计划有变」提示或总耗时。

-   **单次与连续**：单击格式刷采样并只应用一次，应用后自动退出；双击进入连续模式，按钮保持按下态，可连续刷多处，Esc 或再次点击退出。

-   **清除格式**：同时清行内格式与块级样式，并移除格式标记。

### 长命令反馈与终端入口（2026-11-21）

命令卡运行时保留实际输出末行；收到过输出且连续 30 秒没有新输出时显示 `No new output for …`，输出恢复即清除。计时来自会话级工具输出接收记录，不受卡片折叠或重挂载影响；首次加载及重连缺少时间记录时显示 `Waiting for output`，不虚构历史静默时长。已连接的命令行连续显示 30 秒仍未收到首次输出时，提示部分命令在结束时才输出；收到输出后提示消失。断线显示 `Disconnected · waiting to reconnect`，不继续计算无输出时间。工具结束事件先到、结果未落盘时显示 `Command finished`；真实结果到达后使用成功／失败及退出码。静默不等于卡死，也不自动中断命令。

命令卡移除“在终端中打开”：旧行为会重新执行命令，容易被误解为查看正在运行的进程。保留复制命令及运行中的停止按钮；需要重新执行时由用户复制到终端。状态遵循英文执行标签规范，操作文案保持中英双语；静默秒数不通过 aria-live 每秒播报。

### 内置浏览器快照卡

聊天中的成功读取默认展开摘要，依次展示页面标题、采集时的网址（省略查询参数和片段）、提取统计、正文摘录与关键元素。摘要／元素／原始 JSON 分段支持键盘切换，正文默认预览最多十行。元素可按类型、名称和编号过滤，「让 pi 点击」把含快照 ID 与元素编号的请求追加至当前对话草稿。旧记录缺少的网址和表单状态不补猜。失败、运行中及其他浏览器操作沿用工具状态行；但普通失败的浏览器步骤行不展示行内「Error · 时长」标签（2026-11 用户决定，与失败 bash 同理——模型会自行重试，失败状态是噪音），点开该行仍可查看完整错误输出；响应超时保留专门提示，运行中指示与成功状态不变。回归：`tests/native-features-browser-test.mjs`。

Trace 瀑布图按单调时钟排列请求、工具与分组宿主区间。点击行或从详情选择器选择区间，可定位工具、缩放或恢复全程。占比按各类区间并集除以 agent 活跃时间，跨类可能重叠。请求匹配覆盖率仅统计本次 run 已识别的请求。首次助手输出是 SDK 的非空增量或工具调用开始事件，历史记录可能没有类型。

地址栏或 Agent 导航遇到网络错误时，当前标签页在地址栏下方显示错误码和「重试」；被策略禁止的地址显示拦截提示。错误文案中的地址省略查询参数和片段。

视觉操作或提交需要确认时，内置浏览器工具栏原位显示网站、动作目标、用途和取消／确认按钮。确认期间网页保持可见且尺寸稳定，坐标以截图尺寸为准。
